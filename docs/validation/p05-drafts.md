# 搭建草稿验证

2026-09-09：P05 Task4 与准备页 API 已实现；冻结预览和广告执行继续实施。

- 草稿保留所有原始剧名/账户行、空行和重复反馈。账户按完整 ID/全名分批解析，每页 100 行，跨页按实际 advertiser ID 去重；此阶段不展开账户与剧目的笛卡尔积。
- 版权方准备为独立持久任务。草稿消费者只读其结果，`result_unknown` 原样保留。已结束准备再次刷新时观察同一个版权方任务，不为未知结果换请求重建渠道。
- 素材按完整剧名逐页读取，文件名/ID 稳定分组，保留尾组。同素材可被多部剧使用；分页 API 用 SQL 标注多剧命中。
- 所有准备和编辑锁序为草稿→准备记录。输入或策略变更增加 revision 并重置自动准备；手动素材编辑只修改当前剧目分组。编辑冲突返回 409，不覆盖当前数据库版本。未来预览必须核对该 revision。
- 请求幂等绑定租户、草稿及准备任务。重复准备请求的别名也持久化；查询保存/准备请求支持网络未知结果回查。
- 本地准备每次处理一页，进度和下一条 outbox 原子提交。定时修复保留同一任务 ID/generation，未发布积压保留原退避；撤权明确记录阻断，恢复权限可重新准备。
- 工程输入上限为 1000 行剧名、100000 行账户、每行 1000 字符及合计 16 MiB；不是 TikTok 平台限额。页面查询默认 50、最多 100 条，游标绑定租户/草稿/revision/筛选。

验证：17 项草稿测试通过，包括 PostgreSQL 真实并发创建/准备/编辑、205 份匹配素材跨页完整性、跨页账户去重、HTTP 游标与越权、未知链接、手动分组、只读目录无新任务、撤权恢复和 outbox 延迟恢复。与材料、SDK 及运行配置合计 191 项通过；Ruff、strict mypy、ty（只忽略 SQLModel 对底层 SQLAlchemy execute 的弃用提示）通过。Alembic 新库和 `check` 通过，新增迁移 `0005b_build_drafts` 追加于已交付策略迁移。
