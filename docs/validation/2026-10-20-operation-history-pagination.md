# 操作记录分页与读取性能修复

## 问题与修改

操作记录页使用 useInfiniteQuery 累加页面，与其它页面的 Pager 不一致。后端虽然每批 SQL 带 LIMIT，但为了求总数仍遍历全部历史任务，每笔任务又逐项读取冻结路由、账户与授权；第二页总数还错误地仅计游标之后的剩余记录。

现在复用 Pager/useCursorPage，默认50条、可选100条，显示总数、页码和上一页/下一页。每次只请求并展示当前页；刷新只重读当前页。租户、BC或动作/来源筛选变化时重置分页，包括浏览器前进/后退；加载中展示骨架，错误不伪装为空结果。

后端复用 usable_grants 的账户权限条件，在 SQL 内核对原冻结连接、租户/BC、授权版本、绑定版本和契约版本，以及明确读取授权。任何任务项失权即隐藏整笔任务；不会借另一个连接的权限读取旧记录。COUNT 在完整可见筛选范围计算，游标只作用于当前页，数据库最多物化 limit+1 条任务；摘要仅按当前页批量读取。无数据库迁移、数据写入、队列、功能开关或平台配额变化。

## 验证

- 修复前真实 PostgreSQL 回归复现：60笔历史请求2条产生969次SQL；第二页 total 从4错误变为2。修复后同用例通过，查询数上限固定为12。
- 后端广告管理完整测试：142 passed（10.54秒），包含22种授权/冻结路由失效、任务混合可见/不可见账户、相同时间稳定分页、跨BC、动作/来源筛选和固定总数。
- 前端广告管理完整浏览器测试：20 passed（17.8秒），包括页间替换、上一页、刷新当前页、50/100条切换、来源筛选及浏览器回退重置。
- Ruff、全应用 ty、前端 TypeScript/Vite build、git diff --check通过。
- 测试使用专用本地 PostgreSQL 数据库 `tkada_history_20261020_test`，Redis DB14；浏览器平台边界使用测试响应，没有真实广告写入。
