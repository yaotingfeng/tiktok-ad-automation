# 创意级基础报表验证方案

**日期**: 2026-11-10  
**目的**: 验证基础报表的 `ad_id` 维度（创意级）能否替代现有的素材报表补链流程  
**状态**: 两轮已执行（junbo、xuyin）；结论：创意级报表不能单独替代素材报表

## 背景

当前架构：
- 广告报表使用 `ad_id_v2` 维度，拿到的是整条 Smart+ 广告的汇总数据
- 无法获取每个创意的拆分数据
- 通过素材报表（按帖子 `main_material_id`）反推，触发"帖子 → 广告 → 视频"的补链
- 补链任务积压严重

官方文档显示：
- 基础报表同时支持 `ad_id_v2`（广告层级）和 `ad_id`（创意层级）维度
- `ad_id` 维度下，每个创意是单独一行，`campaign_automation_type` 为 `UPGRADED_SMART_PLUS_CREATIVE`
- 官方明确说明：Smart+ 广告的 `smart_plus_creative_id` = `/ad/get/` 的 `ad_id` = 基础报表 `AUCTION_AD` 层级 `ad_id` 维度的 `ad_id`

如果创意级报表包含收入指标且数据完整，就可以用"创意级报表 + 广告目录"直接获取素材维度数据，完全绕开帖子和补链流程。

## 验证目标

三个关键问题：

### 1. 创意级报表是否包含收入指标？

**假设**: `ad_id` 维度能返回 `native_growth_*` 系列收入指标。

**验证方法**:
```http
GET /report/integrated/get/
  ?advertiser_id=7691249267022446613
  &report_type=BASIC
  &data_level=AUCTION_AD
  &dimensions=["ad_id","stat_time_day"]
  &metrics=["spend","native_growth_total_ad_impression_value","native_growth_ad_revenue_d0"]
  &start_date=2026-11-08
  &end_date=2026-11-08
  &page=1
  &page_size=10
```

**预期结果**:
- 请求成功，返回 `code: 0`
- 每行的 `metrics` 包含 `native_growth_total_ad_impression_value` 等收入字段
- 至少部分行的收入值不为 `null`、`"-"` 或 `"0"`

**如果失败**: 收入只在 `ad_id_v2` 层级，创意级报表不可用，必须保留现有素材报表。

### 2. 创意合计是否等于整条广告的合计？

**假设**: 同一条广告的所有创意数据求和，应等于 `ad_id_v2` 的汇总数据。

**验证方法**:
1. 拉取 `ad_id_v2` + 天的数据，记录某条广告 A 的消耗和收入
2. 拉取 `ad_id` + 天的数据，筛选属于广告 A 的所有创意
3. 对创意的消耗和收入求和
4. 对比两者是否一致（允许浮点误差 < 0.01）

**映射关系获取**:
- 调用 `/ad/get/` 或 `/smart_plus/ad/get/`，用 `ad_id_v2`（或 `smart_plus_ad_id`）筛选
- 返回的 `creative_list` 里，每个创意的 `smart_plus_creative_id` 就是报表里的 `ad_id`

**预期结果**:
- 消耗合计误差 < 0.01
- 收入合计误差 < 0.01

**如果失败**: 数据口径不一致，无法用创意级报表做核心指标。

### 3. 已删除的创意能否通过 STATUS_ALL 查回？

**假设**: 素材重建或删除后，旧创意在 `ad_status=STATUS_ALL` 的报表里仍能查到。

**验证方法**:
1. 查询 `ad_id` 维度 + `STATUS_NOT_DELETE` 筛选，记录创意总数 N1
2. 查询 `ad_id` 维度 + `STATUS_ALL` 筛选，记录创意总数 N2
3. N2 应 >= N1

**进一步验证**:
- 从广告目录找一条经历过素材重建的广告，记录其当前的创意 ID 列表
- 在 `STATUS_ALL` 的报表里搜索这条广告的历史数据
- 确认是否能找到已不在目录里的旧创意 ID

**预期结果**:
- N2 > N1，说明包含已删除创意
- 能查到历史旧创意的数据

**如果失败**: 无法回溯历史素材表现，适合新数据但需要另外处理历史积压。

## 第一轮结果（2026-11-10，生产只读）

范围：租户 junbo（新骏伯 BC `7683817908149272592`，OFFICIAL_API），近 7 天（2026-11-02 至 11-08）Smart+ 消耗最高的 5 个账户。在生产 API Pod 内复用报表读取器与冻结路由，凭据未离开 Pod；共 15 次 SDK 报表读请求，无写入。脚本与原始输出：`.runtime/backlog-rootcause-20261110/probe_creative2.py`、`probe_creative2.txt`。

| 检查 | 结果 |
| --- | --- |
| 创意级行类型 | 全部为 `UPGRADED_SMART_PLUS_CREATIVE`，358 行 / 175 个创意 |
| 收入指标 | 全部 7 个 `native_growth_*` 字段都有值，无缺失 |

## 第二轮结果（2026-11-10，xuyin，生产只读）

范围：租户 xuyin（BC `7673415075352576016`，OFFICIAL_API），2026-10-27 至 11-02，按当前补链缺口金额选前 3 个账户；另对账户 `7689011066160021525` 逐天拉取。共约 50 次 SDK 读请求，无写入。原始输出：`.runtime/backlog-rootcause-20261110/probe_creative3.txt` 至 `probe_creative8.txt`、`probe11.txt`、`probe12.txt`。

### 1. 两个大账户基本一致

| 账户 | 整条广告消耗 | 创意级消耗 | 差额 |
| --- | --- | --- | --- |
| 7691535328313786369 | 4571.66 | 4570.84 | 0.78（18 个广告组 × 天，单处 ≤ 0.52） |
| 7690871453612343316 | 1082.91 | 1081.91 | 0.89（16 个广告组 × 天） |

创意全部能在本地目录找到；但其中轮播（目录类型 IMAGE）占消耗 64% 和 79%，视频只占 36% 和 21%。素材维度改造必须同时处理轮播身份，不能只按 VID。

### 2. 第三个账户：历史日期创意级与素材报表都缺数

账户 `7689011066160021525` 逐天对比（单位：USD）：

| 日期 | 整条广告（ad_id_v2） | 创意级（ad_id） | Smart+ 素材报表（实时重拉） |
| --- | --- | --- | --- |
| 10-27 | 66.99 | 1.70 | 6.54 |
| 10-28 | 126.26 | 7.36 | 29.60 |
| 10-29 | 65.28 | 2.29 | 28.98 |
| 10-30 | 21.83 | 3.21 | 11.87 |
| 10-31 | 32.28 | 29.97 | 30.26 |
| 11-01 | 266.99 | 259.89 | 260.14 |
| 11-02 | 1419.19 | 1364.52 | 1365.36 |
| 合计 | 1998.82 | 1668.94 | 1732.75 |

- 不是分页或截断：7 天查询 total_number 2667，逐天之和 2667，全部取回；单广告组单日按 adgroup 过滤可完整取回 900 个创意。
- 平台本身在这些日期没有给出创意或素材粒度的数据：实时重拉的素材报表与本地已存数据完全相同。
- 素材报表比创意级多 63.81（3.8%），集中在 10-27 至 10-30。符合“素材重建后旧创意从创意级报表消失，但旧帖子仍留在素材报表里”的现象。`STATUS_ALL` 与 `STATUS_NOT_DELETE` 行数相同，旧创意不会作为“已删除”出现，无法用状态筛选查回。

### 结论

1. 创意级报表在当前创意上口径准确（与整条广告逐广告组一致），能直接接到目录里的视频或轮播，可作为素材维度的主数据源，请求量远低于帖子补链。
2. 它不能单独替代素材报表：被重建的旧创意历史会从创意级报表消失，本例约占 3.8% 消耗，只能靠素材报表（帖子）补回。
3. 某些账户日两种素材粒度都远小于整条广告消耗（本例 10-27 至 10-30），这部分平台没有素材粒度数据，任何方案都只能显示“无法归属到素材”，不能用补链解决。
4. 下一步若改造，建议：创意级报表为主；素材报表只用于找回“创意级报表里已经没有的旧帖子”，并只对这部分做补链；整条广告与素材合计的差额按“无法归属”显式展示。改造前需在更多账户上量化第 2、3 类的占比。
