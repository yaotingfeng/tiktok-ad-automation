# 批量素材准备与明确失败恢复修复

## 范围与根因

仅新加坡测试环境，基线 `11a4c5b`；服务器原运行 `c0a318f2b61634cb6b1df5b4fe877077ef2f3be3`。无数据库迁移、前端、功能开关或上游调用额度变更。

- 同 BC 共享候选先 LIMIT 10000 后按冻结身份筛选，前置不合格记录可挤掉锚点及同伴，造成不能合批。将同租户/BC/操作者/路由/来源/transport/未发送/可领取条件下推到分页前，优先锚点及同素材目标，锁内仍复核，数量上限不增。
- 跨 BC 就绪转存的20素材×10账户恢复逐关系锁取/刷新/重复鉴权。本地原13623条SQL，改为整片统一锁序、每账户短事务权限复用及最终新鲜复核，降至3566条（约74%）。授权中途变化只回滚该账户，实际共享仍复用唯一原生共享器；不是第二套跨 BC 共享实现。
- 就绪依赖绑定和批量领取原来等待数据库锁无短期限。复用既有有界事务，最多5秒共享资源预算；超时整体回滚，原 outbox/依赖身份保留，不能降级单条发送或记成业务失败。审查补出两次候选读取间另一消费者完成的空集合窗口，补幂等退出。
- 显式 RETRY 原来排除所有已有 distribution_id 的素材，即使确有未生效证据也不能恢复。新分支只接纳已终止、无活动消费者/发送/正回执冲突、冻结来源和MD5不变的明确失败，调用原准备入口产生新操作，保留旧操作和审计新旧ID。UNKNOWN、源上传所属操作、缺历史内容快照、共享降级上传均不开放。
- SDK 视频、图片、创建的非零整数平台错误码需完整保留；图片POST原来在通用读取解析中先抛异常，丢失请求ID/错误码，已改为写响应解析。保留错误证据不等于把平台错误一律分类为无效果。
