## 修复与合同

1. 目录任务只在业务提交之后直接补位并有界发送 outbox。终态、失效和发布退避释放槽后才扫积压；普通分页/准入等待仅发送已有续步。全量和实时两池同时考虑，支持主目录发布产生实时素材子运行及父目录补读。沿用窗口锁、租户轮转、保底、代数、冻结授权和原消息身份。
2. 移除完成后的五秒桶 Control 唤醒。初次请求的 Control 通知和 Beat 恢复仍有效，已存在的旧 `dispatch_only` 消息仍可正常执行；不清队列。发送或补位失败不会撤销已发布数据，失败领取回滚，后续正常调度恢复。
3. 素材关联归并先按现有活动部分索引的复合顺序取 50 条，再读这些条目的 progress。Redis 保存跨轮游标、尾部回绕，非阻塞锁保护并发；PG 成功提交后才保存游标，Redis 丢失只会重扫。单个慢候选使用 SAVEPOINT，不跳过未审查尾部，不修改在途冻结任务。
4. 唤醒依赖与归并保持独立事务及各一秒预算。维护失败不回滚已完成派发。

无 DDL、模型/消息格式/任务名/队列拓扑/Worker 并发/配额/功能开关变化。Redis 新增两个短期维护键，不是业务事实。现有大量任务仍需自然消费，修复不代表积压立即清零。
