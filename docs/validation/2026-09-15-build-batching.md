### 真实只读验证：共享后的目标 MID 查询

从该租户、BC 和目标账户已成功原生共享记录选取三个源 MID，使用任务的原冻结 MCP 连接执行一次 `search_videos(material_ids=...)`。返回三条、完整一页，返回 MID 集合等于源 MID，目标 VID 集合和三条 MD5 均与原已核实目标映射一致；没有任何平台写请求。

这揭示并消除了仅做“批量已知 VID 详情”仍会漏掉的主链路热点：原生共享刚返回时目标 VID 未知，旧流程依然逐素材按名称搜索。新实现须将这一阶段也按同账户/MID 合并，不能把源 VID 直接冒充目标 VID。只读私有脚本为 `.runtime/singapore-staging/probe-shared-mid-read.py`，实际范围和身份不写入公开产物。
