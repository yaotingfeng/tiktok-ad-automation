# 广告报表查询续办与素材覆盖索引

## 范围与依据

承接会话01a1bfe3-082b-7dc0-9348-d34be4ddc63e，用户已要求优化六个报表维度，并明确授权提交、推送和发布生产。续办时生产为be6c7cdc、数据库0104；前轮发布状态complete，但项目Jenkins仍暂停。本轮仅提交报表修复、索引迁移与对应验证，保留并行会话的前端修改及临时生成物。

同一范围4859账户、近7日的只读执行计划显示：素材默认汇总的账户成员头读取179876行，视频点查15245次，累计56863个磁盘块读取，单此部分约44秒；事实阶段另约14秒。原默认查询超出30秒SQL期限。剧目分页将账户集合与系列ID集合分别查询，制造了大量无效组合探测。

## 修改

- 分页目录和事实按实际账户/对象二元组读取；父级沿实际账户传递，数组参数保留超过65535绑定参数的支持。
- 素材候选只读取有事实的视频，未归属帖子及广告位置保持按完整身份点查；账户条件在受限视频来源外过滤，避免每个视频重复展开数千账户。
- 无文本/层级筛选的素材汇总不读取广告ID数组；非名称排序也不读取目录名称。页展示、选择和导出仍按冻结的版本读取完整依据。
- 1000账户以上的紧凑指标查询先按租户、类型和日期读取，避免优化器采用账户主键的数千次分散探测；小账户范围沿用原计划。只读事实阶段样本约14.7秒降至5.0秒，不能当作完整接口提速倍数。
- 0107将现有素材账户成员视频索引替换为相同键、包含version_id/use_count的覆盖索引；紧凑指标日期索引保留原键，包含汇总所需的身份、币种、时区及金额/空值标记，覆盖现有及后续月份分区。不改变业务行、冻结合同、Worker资源或配置。索引更宽，需计入存储和写放大；不另保留冗余旧索引。
