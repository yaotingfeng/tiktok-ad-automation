# 分页列表数据总数验收

日期：2026-09-15

## 交付范围

- 通用游标分页响应新增必填、非负的 `total`，口径为当前租户、BC、权限和筛选条件下、应用游标之前的精确记录数。
- 租户、成员、用户候选、账户、连接、BC、素材、上传批次、版权方、策略、草稿、预览和搭建任务的分页查询均返回该口径。
- 公共分页器统一展示“共 N 条 · 第 X 页”；MCP BC、小程序、素材编辑、待上传文件和平台用户等自定义分页同步显示总数。
- 后续统一抽取全局 `PaginationSummary`，公共游标分页器、通用表格及原自定义分页全部复用“共 N 条 · 第 X / Y 页”；总页数由精确总数和当前每页条数计算，0 条稳定显示 1 / 1 页。
- 请求刷新期间保留上一份已确认总数，筛选或分页结果到达后使用新响应更新；未把当前页条数冒充全量总数。
- 无迁移、无新功能开关，不调用 TikTok、版权方或素材存储接口。

## 实现边界

- ORM 查询在加入 seek 游标和 `limit` 前统计完整筛选范围。
- 原生 SQL 目录使用与页面查询相同的租户、BC、状态、日期、版权方和搜索条件单独计数。
- 两万行素材导入目录将计数标量子查询合入正常页面读取；游标越过末行的空页再执行有界计数，仍返回原筛选总数。
- 平台用户沿用既有 `UsersPublic.count`；本轮只补充真实总数展示，不改变其既有客户端分页模型。
