# 大账户池报表查询优化（本地完成，未上线）

## 问题与改动

普通报表读取已发布的数据库事实，但首次查询仍需计算跨日聚合、筛选排序、完整管理成员快照及页补全。此次完整服务诊断确认：账户页补余额使用DISTINCT ON，扫描所选账户全部余额历史后才取最新；50账户样本在该语句超过40秒诊断上限。不能将此前仅测成员SELECT的17秒当作完整接口延迟。

新增唯一`latest_balance_observations`入口，按已授权账户集合进行单条SQL的LATERAL短探测，复用于页补全、同步状态版本及余额排序依赖。保留最新时间与ID并列决胜，最新不可用余额不回退旧可用值，明确租户/账户条件，空范围不查询、输入去重。

账户快照仅在余额排序时读取全候选余额，仅在文字/命名筛选需要时读取版权方投影及事实名称。页内仍显示最新余额；完整系列引用、快照名称版本、金额与覆盖、跨页排序及冻结选择不变。没有迁移、开关、额度或后台任务合同变化。

- Ruff检查/格式、修改脚本语法、差异检查通过。余额入口、row_set、dimension_query和query_reuse四模块严格mypy通过。API严格mypy仍有原有5项问题（内部execute_query未注解/Any返回及health可空/无类型调用）；用HEAD原文件独立复查为同样5项，不记为API类型检查通过，不夹带修复。
- 生产4859个有效账户，同一REPEATABLE READ窗口：今日与7日的旧/新成员、顺序、冻结引用摘要相同。热缓存成员SQL今日840→526ms、7日1515→1141ms；缓冲访问分别120204→66847、169326→115424。缓存未清空，仅说明本样本SQL，不外推浏览器倍率。

## 剩余瓶颈与发布边界

生产只读全快照等价SELECT仍17.13秒，其中目录成员索引读取76,685个系列、约11.25秒，状态按4859账户探测约3.80秒；必须冻结的成员不能直接删掉或改为点击选择时再读取，否则会纳入新同步系列。新完整服务首屏仍25–32秒，不能宣称全部性能问题已解决。

素材使用位置改数组批读、账户引用改JOIN、名称版本改集合查询三个候选均未得到足够稳定收益，未修改这些路径。后续需针对目录成员、状态日期访问的索引布局或日聚合/成员预存制定独立方案，单独验证写放大、回填、授权及冻结语义。

本轮未推送、未发布、未执行生产DDL、备份或恢复演练。当前main另含尚未生产迁移的0102经营比例合同及其他同步修复；不能把整批main当作无迁移报表小修直接上线。发布需明确选择范围、精确版本与对应程序/数据库合同。
