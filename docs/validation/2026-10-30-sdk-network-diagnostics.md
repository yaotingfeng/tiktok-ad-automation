# 2026-10-30 SDK分阶段日志及创建失败证据

## 问题与变更

用户指出反复故障只有总耗时和异常堆栈，无法快速排查。这次I89F建连超时需要反查生产urllib3行号才能判断HTTP尚未发送，暴露了诊断颗粒度不足；旧Pod删除也会使stdout证据不完整。

本轮复用现有官方SDK及原日志边界，记录DNS/TCP、TLS连接准备、请求写入和响应阶段的摘要，保留任务/租户/BC/账户/步骤及本地HTTP尝试号关联。每SDK客户端使用独立连接类/pool副本；全部网络动作仍调用原SDK和父类，不新增请求或底层重试。前次明确未发送的nonce证明保持，不使用日志数据放行重建。

关键创建失败的安全摘要写入已有StepEvidence的原结论summary，与原attempt/nonce同事务提交。白名单只保留故障阶段、计时、错误类型/位置、连接参数及运行版本等诊断数据；无请求头/正文、令牌或签名URL。移除创建拒绝日志中的平台原始message。Docker构建把既有VCS_REF同步为只读构建元数据。

阶段精度、查询方式、留存边界见[运行手册](../runbooks/sdk-network-diagnostics.md)。DNS/TCP是合计耗时，TLS为连接准备残差，响应阶段包括等待和读取；不宣称独立DNS、纯握手或TTFB，也不据此断言具体网络跳故障。
