## 修复

- 网眼返回的 `id` 是取链接口使用的技术身份，`int_id` 是用户核对的数字剧目编号。新增 `ProviderDrama.display_drama_id`，搜索和候选保留数字编号，已核实链接的 `drama_int_id` 也可补齐缺失值。原 `external_drama_id`、取链请求、归因及冻结广告身份不替换。
- 准备页表格、输入详情和候选展示使用数字编号，表头改为「版权方剧目 ID」。缺少可靠编号显示未提供，不把本地编号或网眼长字符串当作数字编号。嘉书沿其正式 `video_id` 展示。
- 准备进度接口按当前草稿关联的链接返回原 URL 和归因名称，保留原文。已有自动或手动链接均显示「修改推广链接」，缺链接才显示「补充推广链接」；复用原有手动编辑表单与 PUT 接口，标题和预填随实际链接状态变化。
- 手动表单的数字编号在同租户/版权方/应用内解析到原剧目，保存新的链接记录，不覆盖原链接或把数字编号写到原技术 ID 上。准备中的写入限制、权限、草稿版本、未知回执恢复及保存后继续准备沿用现有流程。

## 迁移和并发

新增迁移 `provider_display_drama_id`，父版本 `manual_promotion_links`。旧网眼记录仅依据同租户/连接/应用/剧目的历史归因数字编号补齐；有冲突或非法值时不推测。新字段为空不影响取链，原长 ID 与链接保留。没有新增依赖或开关；实际发布必须先备份并执行 Alembic 迁移。

新增展示 ID 匹配后，自动发现与手动插入可能使用不同技术 ID 指向相同数字编号。回归先复现 `MultipleResultsFound`；修复为插入后再核对，出现竞争时撤销保存点内的临时插入，复用另一事务已提交的唯一记录。真实歧义仍返回明确业务错误。两个真实 PostgreSQL 事务验证最终只有一条剧目、自动标题保留、手动链接绑定正确。
