# 目录额度等待与重复素材扫描修复

## 生产证据与根因

目标为新加坡 ACK / `test`（生产用途），线上采样版本 `3b498c70`。本批只读检查覆盖用户指定的原骏伯和大账户池；未执行 TikTok 广告写入或修改生产配置。

- “待补齐或刷新”按当天有消耗广告的三层父链统计，包含不存在和过期。采样大池 5,407 条有消耗广告中，广告/组/系列实际缺失 66/3/4；原骏伯 781 条中实际缺失 10/3/3。多数为状态过期，不能把全量任务数下降当作目录新鲜。
- 此前“对象目录仅剩几个”遗漏定向通道；采样定向待办约 3,200 条，大池最早排队超过两小时。实测 `targeted_capacity=0`，outbox 只有秒级等待。
- `worker-ads-live-directory` 日志反复出现 `AccountAdmissionDeferred` 未捕获异常。Worker 已写入 90 秒领取租约，随后本地调用额度不准入，任务直接报错；直到租约过期才能被扫描器再次派发。全量与定向使用同一执行方法，均受影响。原样抛出错误的四个参数化回归先红，修复后绿。
- 素材未完成大池 2,635 条、782 个独立账户/冻结查询分区；原骏伯 78 条、76 分区，历史重复扫描占用读取名额。只读试算“优先最新同范围扫描”后大池代表扫描 782 条、原骏伯当时 67 条（独立采样，期间自然完成继续发生），生产相同选择谓词 `EXPLAIN ANALYZE` 约 21 ms。
- 规则 19:00（北京时间）自然运行已零命中且 `NOT_REQUIRED`；仍保留真实 `STALE_REPORT` 提醒，不以屏蔽提醒代替修复。

## 实现

1. 目录读取本地准入延后时，仅在原代数、原领取 token 仍归本执行者时释放租约。保留已暂存页、游标、冻结授权和观测时间；增加代数隔离旧消息，原 outbox 按本地共享调用准入返回的等待时间（至少 1 秒）安排同页续步。成功读取后清除等待错误。不扩大并发、窗口、平台速率或业务开关。
2. 全量素材候选遇到同租户、BC、执行人、冻结路由、账户、完整查询分区且序号更新的未完成扫描时，先推进新扫描。旧任务和页保留，待新扫描真实发布后由原 superseded 机制处理；不合并不同时刻的分页，不伪报完成。其它授权范围不受阻挡，定向回读仍优先。

无需数据库迁移、前端变更或新配置。保留原开关、配额、队列、窗口与 Worker 数量。没有通过数据库操作改写历史成功时间或清空队列。
