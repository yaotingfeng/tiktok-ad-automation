# MCP 一次授权接入多个 BC

## 交付范围

- 一次候选确认发布一份共享凭据和授权事实，可接入多个 BC；现有连接支持刷新可见目录、追加 BC，无需再次 OAuth。完整目录最多 5000 个，单次选择最多 1000 个。
- 每 BC 独立同步、重试、错误和解绑，保留独立默认 API/MCP 连接。共享令牌刷新不使兄弟 BC 的目录变新，也不会清理其账户权限。
- 冻结任务保存绑定代数。解绑后重新接入不恢复旧任务；普通同步、令牌轮换、默认切换不改变代数。旧六字段不可变 JSON 按原代数 0 解释，原场景摘要及历史核查证据不改写。
- 旧 ACTIVE 授权缺少新观察时，仅用当前凭据读取实际工具，再核对主体和 BC；没有复制候选、延长授权窗口或采用预期 schema 冒充真实观察。
- 迁移依次为 `mcp_multi_bc`、`mcp_multibc_runtime`。旧 runtime 任务只从自身冻结路由回填版本；无法证明的任务保留证据并终止。

## 本地验证

所有数据库/锁与并发测试使用独立 PostgreSQL 测试库及 Redis 测试 DB，外部请求仅在 HTTP 传输层替换；没有真实广告或素材写入。

- 授权管理作者组 28 项通过；目录与 runtime 两组各 34 项通过，含 API 旧路径及两 BC 独立发布、真实本地 HTTP 令牌刷新。
- 管理员撤权恢复 7 项通过；每 BC 目录新鲜度与 runtime 联合 28 项通过。
- 绑定版本与迁移 14 项通过；已有授权工具重观察和 HTTP 合同联合 23 项通过；场景历史摘要增量 3 项通过。
- 前端账户/租户原 90 项均获得通过结果（客户端生成空窗影响的两项已复验），最终五项增量通过；TypeScript/Vite 构建、移动端和桌面截图检查通过。测试组存在重叠，不累加为独立用例总数。
- 根级联合回归分组执行：首组 351 项通过，暴露的旧 schema 播种与并行落盘前旧模块导入问题分别修复/复验；后续组 268 项通过，发现历史迁移 fixture 及 S3 测试环境未固定；最终广告恢复组 111 项通过，剩余旧迁移测试的跨版本降级假设单独修订。旧恢复迁移参数组已改为单迁移事务内验证且 2 项通过。各失败均保留原因与对应复验，不将失败的整组写成全绿。
- 历史迁移 fixture 改为当时实际字段，并保留原升级/降级与审计不可丢失断言；两组相关测试 5 项与 17 项通过。
- 最终代码的旧恢复迁移、素材父路由、共享管理 HTTP、升级工具重观察及场景版本联合 **40 项通过（7.89 秒）**。
- 全应用 ty、相关 strict mypy、Ruff、前端 Biome、Git diff 检查通过。独立代理审查已关闭共享权限污染、过期目录串用、升级观察缺失、旧场景摘要变化及撤权挂起问题。

## 测试环境验收

待固定提交发布后填写。发布前已保存 1 条授权、1 个绑定、42 个账户的只读基线。必须按部署手册执行完整备份与恢复验证，再迁移、切换同版本服务及 Sun Browser 实际验收。

现有测试授权只有一个已明确接入的真实 BC；多 BC 并发行为由隔离测试验证。素材上传与广告创建仍需各自的实际权限/服务证据，本功能不自动开放写能力。
