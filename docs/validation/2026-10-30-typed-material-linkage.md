# 轮播补链循环修复验收

## 范围与官方依据

用户授权：先核验官方文档，在新 worktree 实现，验证后合并本地主线。初始基准 `faf35831`，复用已有分支 `feat/campaign-rename`，工作树 `.worktrees/sync-material-linkage`；合并前已整合主线 `e0ce4c09`。本轮未调用真实 TikTok 接口，未推送或部署生产，不能据此宣称线上积压已清空。

实际阅读 TikTok 官方门户的 [Creative Breakdown](https://business-api.tiktok.com/portal/docs/run-an-upgraded-smart-creative-breakdown-report/v1.3)、[Creative Overview](https://business-api.tiktok.com/portal/docs/run-an-upgraded-smart-creative-overview-report/v1.3) 和 [Breakdown dimensions](https://business-api.tiktok.com/portal/docs?id=1843337879988226)。官方区分 Spark 帖子、非 Spark 主素材、轮播和目录 ID；Spark 轮播的主素材是帖子 ID，非 Spark 轮播的主素材是轮播 ID。概览可提供广告与主素材的对应关系，不能据此把轮播要求为视频 VID。

## 最终行为

- 共用类型感知的完成条件：同租户、同账户、同类型、非空广告归属。两种明确轮播类型完成广告归属即可退出报表补链；两种视频类型还须有效 VID；未知类型不自动放行。
- 任务生成、旧任务恢复、依赖等待、健康覆盖和概览范围使用同一规则。混合任务只为未完成的视频请求身份目录；原有普通目录刷新保留。
- 历史归属定位从目标、二分查询、共享单广告回执到缓存、已检查列表均保留 ID+类型。缺少类型的响应报错；旧无类型定位续点重新读取，保留已保存的业务映射及概览分页。每步最多一次远端读取与完整查询复用仍通过测试。
- 只在官方返回的类型与原映射类型不同的纠正场景清除旧桥接/VID；同类型已证实 VID 不变。新旧帖子不会仅凭名称或广告当前图片组共用身份。
- 当前图片序列、音乐、远端创意 ID 继续通过现有目录合同表达。`carousel_linkage_complete` 仍如实反映内容不足；报表关联完成不代表历史图片组已重建。不把图片 ID 写入 VID，不改事实金额、不按图片分摊金额。
- 无表结构迁移、并发/额度调整或新部署开关。复用既有 10 分钟至 6 小时依赖退避和负缓存期限。

## 审查边界与后续发布

- 已有非空但失效的视频 bridge 阻止备用解析，是先前根因报告注明的独立问题；本次不更改该分支。代价是这部分真实视频缺口仍可能等待，不能宣称所有积压均已解决。
- 旧混合任务的冻结概览范围继续完成原分页，不中途缩小。代价是可能读完少量旧范围页；这是避免跳页漏关联的取舍。纯轮播且已有归属的任务在入口直接完成，不再读取这些页。
- 本轮只合并本地。后续发布需固定精确版本并统一 API、Control、报表及补数等相关角色，旧消费者正常退出后使用新版本处理；不能混用新旧定位缓存合同。无需清队列或手改业务映射；新版本会重判旧等待任务。回退也必须停止相关消费者并审查任务续点合同，不能盲目恢复旧二进制。
- 线上验收应分别观测轮播无 VID 等待数、真实视频缺口、未知广告归属、图片内容缺口、请求量和队列净增速；本地用例不能替代部署后的这些观测。
