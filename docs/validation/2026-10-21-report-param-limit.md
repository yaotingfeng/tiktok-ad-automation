# 报表大租户查询超出数据库参数上限

## 问题

生产 xingyu 租户（BC 7666010978596749328，约 6.9 万个系列）打开广告报表时看不到数据。创建报表快照时，名称版本查询按「账户 IN (...) AND 系列 IN (...)」逐项绑定参数，788 个账户加 69,228 个系列共 70,016 个参数，超过 PostgreSQL 65535 上限，接口直接失败。与此前同步修复无关，不需要重新拉取报表数据。

## 改动（d195f70e）

- 快照名称版本：账户与系列各以一个数组参数 `unnest` 按精确 (账户, 系列) 对关联，库内 `DISTINCT ON` 取最新修订，排序规则同 `latest_projections`。
- 分页读取中来自结果集的系列/广告/素材身份列表统一改为 `= ANY(:ids)` 单个数组参数。
- 无数据库结构、队列、任务合同或运行配置变化。

## 验证

- 本地临时 PostgreSQL 18 / Redis 8：新增两个 7 万规模回归用例，原逻辑精确复现 `number of parameters must be between 0 and 65535`，修复后通过；报表与广告管理 802 项通过。
- 产品提交推送 GitHub 与公司 main，自动触发 Jenkins #104 正常发布（检查线 backend/frontend 通过，批次 20261021T080429-3214c9），北京时间 16:14 完成；11 个角色均为 d195f70e 且 Ready。
- 生产实测：以 xingyu 租户管理员身份在 API 容器内执行与报表页相同的首屏查询，整个事务回滚，不留快照。
