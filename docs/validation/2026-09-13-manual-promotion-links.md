# 其他版权方与手动推广链接：本地验收

## 用户确认的交互

保留「批量输入 → 准备与调整 → 搭建预览」。第一步仍是剧名文本框，版权方选择增加「其他版权方」和名称输入；用户不必先建连接，也没有自动/手动模式选择。

「已有推广链接？批量添加」弹窗同时粘贴 Excel 的剧名、推广链接两列（不含表头），可附第3列外部剧目ID、第4列归因名称。同名补链、新剧追加；保存后只展示数量摘要。第二步复用原剧目表，以「补充/修改推广链接」侧栏逐行保存并继续准备，不增加重复表格。

## 数据和边界

- 其他版权方采用租户内 other/local 资料范围；无凭据、无远端登录。本地 application 只作关系命名空间，自动取链管理列表不展示这类资料。
- 已提供的链接保留原 URL 与来源；未提供链接的网眼/嘉书行沿原任务取链，其他版权方的缺链行留在原表待补充。未提供外部ID时生成明确标记的本地编号。
- 当前搭建仅接收 HTTPS TikTok Minis 链接。网眼手动链接同时要求真实归因名称。链接格式和目标 Mini 检查不等于版权方后台业务核验。
- 新增 PUT 单行补链接口复用草稿版本和请求回执。响应未知时只查原回执；旧版权方任务不能覆盖手动行，也不会为其余未知行重复取链。
- 只删除被修改剧目的旧绑定；其余素材分组保留。修改剧名顺序必须显式携带新行号对应关系，前端按剧名重建映射；冲突明确提示。
- 同版权方/应用的本地准备使用单一事务锁，避免逆序多剧死锁；与自动发现同时写入同外部ID时依靠唯一约束收敛，不覆盖已发现标题。锁内没有远端调用。
- 租户、BC、执行授权、素材、Mini、冻结预览及提交校验保持原合同。没有修改真实广告。

## 迁移

新增 `manual_promotion_links`，父版本 `automatic_mini_targets`。加入输入补充信息、链接来源和本地版权方类型，扩展预览版权方名称长度。旧链接默认来源为 provider。

独立 PostgreSQL 历史库验证：旧记录和冻结证据保留；无手动资料时可降级；已有手动资料时明确拒绝丢弃数据。历史迁移夹具按反射所得旧列播种，避免今日 ORM 新字段污染旧 schema。
