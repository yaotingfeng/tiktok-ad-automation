# 经营比例按时间段配置（本地验收）

用户确认按时间段管理版权方抽成和BC其他返点，并明确要求开始实现。规格见[时间段配置设计](../superpowers/specs/2026-11-09-business-rate-periods-design.md)，实施见[计划](../superpowers/plans/2026-11-09-business-rate-periods.md)。本轮不推送、不发布、不修改线上比例或广告。

## 用户可见行为

- 当前列表直接显示开始日期、结束日期或持续有效、比例及状态；按所选参考日期查看适用比例和下一次变化。版本移至修改记录，显示操作人、说明及调整前后日程。
- 支持新增/从某天调整、修改时间段、结束当前段并选填接续比例。结束与接续的默认安排保留下一条已有配置；显式选择持续有效时，预览会展示后续配置被替代的结果。
- 填写范围内替换，范围外已有比例保留；移动、缩短和截止后产生的空档明确待配置，不复活旧记录、不当成0%。从未设置的作用域及首次触及日期之前仍为默认0%。明确填写0%是有效配置。
- 预览不落库，最终确认提交原预览对应的操作和修订。409冲突保留输入、刷新日程并要求重新预览；取消不写数据。预览滚动回顶部，桌面与390px窄屏均已检查。
- 待配置只影响相应经营金额，平台收入/消耗与独立补贴/赔付继续保留。汇总、情景及CSV不以0补缺；历史冻结导出保留原结果。

## 实现与数据边界

新增不可变 `BusinessRateSchedule` 完整日程修订。预览与保存使用唯一 `transform_periods`，辅助取值和投影使用唯一 `period_rate`；待配置使用显式null段，日程从最早触及日起覆盖到无限期。各租户、版权方连接、BC及费率种类独立；使用原管理权限和父对象锁，保存检查预览修订并原子推进重算围栏。

新迁移 `0102_business_rate_periods` 从旧 `BusinessRate` 按生效日期、同日最高修订生成日程，保留所有旧记录供历史查询，维持原日费率。`business_day.rebate_rate` 父表及分区允许null。计算合同提升为3，旧候选退役，日程冻结进任务签名、发布签名和前缀兼容判断。配置变化仍按原后台调度与完整清单原子发布。

独立审阅发现并修复两项明细证据问题：新字典键未同步到冻结provider_rate；ORM批量写入忽略None会令待配置返点使用默认0。现复用同一解析值生成金额与明细，并使用 `render_nulls=True`；真实PG断言非零、待配置费率及所有分区列约束，修复前两项测试失败、修复后通过。没有未处理的审阅问题。

## 验证记录

最终经营后端 **117 passed / 151.88秒**，页面 **13 passed / 20.0秒**；正式及体验版构建通过。Ruff、20个业务模块源码mypy、迁移语法及5个前端手写文件Biome、差异空白检查均通过。测试不调用真实TikTok或版权方接口。

另补已有7%比例只修改日期的页面用例：修复前输入出现7.000000000000001、无法通过表单步长校验；统一按接口比例精度转换百分数并将输入步长对齐至0.000001%，修复后页面与保存参数均保持7%/0.07。

测试命令使用独立本机PG18和Redis7，实际连接参数不进入此文档：

- 后端：在backend下 `uv run --frozen pytest tests/modules/business -q --tb=short`，显式设置专用 `DATABASE_URL`、`REDIS_URL`、非零库号 `TEST_REDIS_URL`。
- 前端：`bun run test tests/business-dashboard.spec.ts --project=workspace --workers=2 --reporter=line`，独立Playwright端口。
- 构建：`bun run build`，正式与体验版两份构建。
- 静态检查：`ruff check app/modules/business tests/modules/business`、`mypy app/modules/business`、新迁移 `py_compile`、5个前端手写文件Biome及 `git diff --check`。
- 迁移：真实PG的旧乱序日期/同日修订等价、迁移往返、所有分区返点列允许空值；新日程编辑后拒绝破坏性降级。

环境问题如实记录：早期缺测试Redis的两项未运行，补独立Redis后通过；两次后端测试共用测试库引发DDL锁竞争，最终改为单后端进程串行；随后Docker磁盘耗尽导致临时PG退出，未将这次失败报告为业务通过。仅移除本轮创建的临时PG及其卷，重新创建2GiB tmpfs测试PG后重跑，未清理其他项目镜像/容器/数据。tmpfs实例关闭fsync/full_page_writes并限制WAL，只用于本轮锁、查询与业务测试，不代表耐久性或生产性能验收。
