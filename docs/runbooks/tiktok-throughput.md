# TikTok统一额度与批量管理运行说明

## 程序合同（2026-10-31，待发布）

创建、目录/素材/报表读取与管理写入使用统一官方SDK应用额度解析。`TIKTOK_CALL_POLICIES.sdk_level`显式选择实际已核实的`BASIC`/`ADVANCED`/`PREMIUM`/`ULTIMATE`。没有该字段的现有部署仍保留其配置，不能仅发布代码后宣称已经提高线上额度；本轮尚未修改生产配置。`MCP_SERVICE_QUOTA_SCOPE`及服务额度独立核实，不从Marketing API应用档位推断，不叠加SDK与MCP绕开同一上游额度。

官方档位与默认物理接口额度（QPS/QPM/QPD）：Basic 10/600/864000，Advanced 20/1200/1728000，Premium 30/1800/2592000，Ultimate 50/3000/4320000。特殊接口覆盖通用档位，例如普通`POST /ad/create/`为Basic 5/150/86400；当前搭建使用`POST /smart_plus/ad/create/`，不能误套普通广告例外。来源：[TikTok官方Rate limits](https://business-api.tiktok.com/portal/docs?id=1740029171730433)，核对日期2026-10-31。

同一应用的物理端点跨租户、BC、token、业务入口共用原子计数；不同端点不再共用虚构的所有接口合计10QPS桶。`management.rename`与系列预算同属系列update端点，普通/Smart+、系列/组/广告的status端点各自独立。对应注册表在`backend/app/integrations/tiktok/platform_quotas.py`。未登记SDK物理端点在新档位配置下闭合拒绝，不能借其他端点额度发送。

Redis使用QPS窗口、滚动分钟和UTC日计数，额度不足不扣其它计数。已实际发送消耗的次数不因释放并发租约返还。平台40100的QPM至少暂停5分钟，QPD到UTC次日；有效Retry-After取更长等待，未知类别保持有界冷却。冷却按应用/物理端点共享，以Redis时钟原子延长，不能被另一个较短退避缩短。SDK业务拒绝、结果未知及本地未发送证据分开存储。

## 请求并发与资源参数

`AD_MANAGEMENT_REQUEST_CONCURRENCY=50`为每个管理进程共享的请求窗口上限（1–50），不是业务开关，不是50QPS，不增加Celery prefork进程。所有任务共享同一线程池；每个实际请求新建独立SDK/MCP客户端，禁止共享last_response。数据库会话只在短事务内借用原连接池，网络和配额等待不持SQL事务。实际吞吐仍受平台QPS/QPM/QPD和部署的app/tenant/advertiser/endpoint资源在途限制约束。

生成待审阅配置，不读取密钥、不修改环境或线上Secret：

```bash
.venv/bin/python scripts/tiktok-quota-config.py --level BASIC --max-inflight 50
```

`BASIC`仅在本地验证时作为官方默认假设，生产档位尚待核实。`base`是未单独核实服务（含MCP）的显式配置，新SDK档位会覆盖旧的业务名3QPS；SDK物理接口特殊覆盖键为`OFFICIAL_API:POST /open_api/v1.3/.../`。不得整份覆盖生产现有配置而丢失已验证的资源/服务设置。发布前审阅实际应用档位、SDK与MCP额度域、50窗口的内存/client/连接池等待、全库连接预算及限流率；需要改变资源上限时单独选值。

## 管理流程与平台合批

手动启停点击即提交；预算、ROAS、改名只输入参数后提交。HTTP冻结完整选择证据和路由，返回PREPARING；后台200成员一块准备，结果和游标原子落盘，原选择过期/删除不影响已受理任务。加减与百分比只计算一次；准备失败提供安全中文原因，重试不重算已准备值。自动规则和旧预览来源仍保留原始不可变证据，创建流程本身的既有具体预览不在本轮取消范围。

平台合批：同任务/租户/BC/连接代数/账户/动作/接口才合并。普通及Smart+系列/组/广告启停最多20 ID；Smart+素材同广告最多20且轮播/非轮播分开，缺可靠类型证据保守单项。Smart+组预算与普通总预算使用专用20条预算接口。普通日预算保持单对象立即更新，不偷改为次日生效的预约预算。系列预算及改名仍单系列接口。Smart+ ROAS按已核实父系列及最终值去重，只发一个广告组更新，保留全部受影响成员审计；20限制不约束单组接口的联动审计数量。

请求前校验当前授权、冻结路由代数、原值、取消状态与对象/祖先锁。批次与每成员attempt先持久化，部分成功按实际成员证据处理；缺失/重复/矛盾回执为UNKNOWN，不整批标成功。取消后仍可落已发回执及做已受理的只读刷新，不复活任务或继续发送；过期失联claim转UNKNOWN核查，活跃claim保留未来恢复消息。

## 恢复与验收

准备检查点同事务保留未来watchdog；SQL暂时故障（Operational/Interface）和Redis临时故障进行Celery退避重投。请求领取同事务登记租约到期恢复，提前重投发现未来retry_at/claimed_until仍补持久唤醒。锁竞争/本地额度等待不消耗传输失败预算，不永久终止有效对象；任务级时间桶合并重排消息，避免每个成员重复派发。

UNKNOWN保持不可自动重发。真实只读核查使用原冻结路由、指定ID和新鲜观察，当前状态符合目标也不等于证明本次请求受理。受理证据与状态观察分别保存；失败有界退避后保留待核验状态。

本轮迁移head为`0069_management_batches`（0068直接任务来源合同；0069物理请求/成员审计），迁移与程序必须统一审阅发布。普通发布默认不备份/不恢复演练不等于允许跳过任务合同审查。保留精确版本、正常退出、原队列/冻结任务、配置摘要和四个已有业务开关；不擅自推送/发布，也不把用户浏览器原选择自动执行。
