# TK-ADA 生产环境筹备与发布规则

## 当前状态

截至 2026-09-19，**TK-ADA 尚未配置或确认任何生产服务器，生产环境未建立**。

- 当前唯一已部署的远程环境是[新加坡测试服务器](staging-singapore.md)。它始终属于 `staging`，不能改称生产，也不能承载生产发布。
- 仓库旧记录中的服务器、域名、端口、目录和 Compose 项目标识不再代表当前生产资源，不得据此连接、发布、迁移或操作数据。
- `.env.production`、`compose.production.yml`、`deploy/production-compose.sh` 和生产 Nginx 示例只是待建环境的模板，不证明服务器、域名、证书、数据库、Redis、备份或外部授权已经存在。
- 任何“部署生产”“上线正式环境”请求都必须先取得用户明确提供并确认的新生产服务器、网络入口和授权范围；不能从旧文档、测试服或历史记录推断。

旧的“生产发布验收”已由[口径更正记录](../validation/2026-09-10-production-release.md)标记为失效，不能作为现网或恢复依据。

## 建立生产环境前必须确认

用户明确决定新建生产环境后，先形成并确认一份环境清单：

1. 服务器地址、SSH 端口、登录方式、操作系统、CPU、内存和磁盘。
2. 正式域名、HTTPS 端口、DNS、证书来源、反向代理及防火墙边界。
3. 服务目录、运行用户、Docker 或原生 systemd 方案；不得默认复用测试服方案。
4. 独立 PostgreSQL、Redis、对象存储、备份位置和异地备份策略。
5. 独立的签名/加密密钥、管理员账号及配置文件路径；不得复制测试环境密钥、会话或数据库。
6. 生产 TikTok API/MCP、BC、账户、版权方和对象存储授权；测试环境的连接与能力证据不能继承。
7. `TIKTOK_CALL_POLICIES`、素材导入/清理等功能开关的生产取值及用户确认。
8. 首发 Git SHA、唯一 Alembic head、维护窗口、恢复目标和验收负责人。

清单未完成前，只能准备和审查部署资产，不得执行远程连接、创建生产资源或发布。

## 首发执行原则

生产服务器确认后，应先根据实际基础设施补充一份具体环境手册，再按[通用部署手册](deployment.md)执行。至少满足：

- 使用已推送、验证通过的 `main` 完整 40 位 Git SHA，发布目录不可原地编辑。
- 生产数据库、Redis、对象存储、密钥、授权和队列与本地及新加坡测试环境完全隔离。
- 首发无旧业务数据时明确记录备份不适用项；已有任何状态时，切换前必须完成完整备份、校验和独立恢复演练。
- 数据库只通过审查后的 Alembic 迁移；API、所有 Worker 与唯一 Beat 使用同一版本和同一生产私有配置。
- 先验证 HTTPS、登录与租户隔离、数据库、Redis、队列、备份和恢复，再分别验收外部只读与写能力。
- TikTok 健康、MCP READY、页面可访问都不能替代真实授权、BC 绑定、账户发现、素材或广告操作验收。
- 未经具体广告操作授权，不创建、启用、暂停或修改真实广告。

## 后续更新与回退

生产环境建立后，每次更新都要在该环境专用手册中记录当前版本、服务拓扑、配置来源、备份命令、排空顺序和恢复步骤。通用边界如下：

1. 比较代码、迁移、依赖、服务定义和功能开关；新增或改变语义的开关先获确认。
2. 冻结新写入，停止调度，正常排空消费者；保留队列、Outbox、UNKNOWN 和审计记录。
3. 备份 PostgreSQL、Redis、当前项目与构建产物、私有配置、证书和服务配置，并在隔离目标验证恢复。
4. 演练迁移通过后才迁移正式数据库，随后统一切换 API、Worker 与 Beat。
5. 验证固定 SHA、单一迁移 head、运行配置、HTTPS、登录、队列、日志和备份定时任务。
6. 数据库不兼容时优先前向修复；不得自动 downgrade、清空队列或用重建远端对象掩盖未知结果。

具体生产主机、域名、端口、目录和命令必须在未来获批后写入本文件。在此之前，本文件不构成任何服务器操作授权。
