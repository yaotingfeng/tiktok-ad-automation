# 引导式体验版（Demo 模式）设计

## 背景与目的

TK-ADA 直连真实 TikTok 与生产数据，任何操作都会落到真实账户上，因此不能直接拿来做演示。用户需要一个体验版，给两类人看：

- 领导：看清工具的整体能力，知道从拿到工具开始每一步能做什么。
- 投放使用者：学会怎么操作，能自己一步步点下来。

体验版要做到：界面与生产版一致；每个页面都预置好数据；体验者不需要自己找剧、找素材、找链接，点按钮就能走完整个流程；所有功能都要覆盖到；全程碰不到任何真实数据。

## 目标

1. **全功能覆盖**：前端所有页面、所有功能在体验版里都能操作并看到合理结果，包括主流程以外的页面（自动化规则、广告管理任务、通知、成员、平台租户管理、用户设置等）。实现时仓库里已有的页面都要覆盖，包括同日正在开发的“素材制作内嵌工作区”（`2026-10-21-material-production-workspace.md`）。
2. **每页都有预置数据**：打开就有内容。数据包括已授权的 BC 和广告账户、版权方连接、剧单与推广链接、素材库、几套投放策略、历史搭建任务（成功、部分失败、进行中都有）、带趋势的广告报表、广告管理任务、自动化规则、通知、成员。
3. **操作能跑通**：写操作会真实改变页面上的数据，并在同一会话内前后一致。例如提交搭建后任务列表多一条，状态从“准备中”推进到“完成”，广告列表出现对应的新广告；改预算后广告详情显示新预算。
4. **点按钮即可**：搭建流程中需要选择或输入的地方（选剧、选账户、选素材、粘贴账户 ID 等）都有预置候选或一键填入，体验者不需要准备任何数据。
5. **步骤引导**：
   - 一条贯穿全流程的“主线引导”，从进入体验版一直带到看报表、调广告、配自动化规则。每一步高亮要点的元素，并说明这一步在业务上做什么、为什么。
   - 每个页面有“本页怎么用”入口，可单独打开这一页的分步讲解，覆盖主线没讲到的功能。
   - 引导可以随时退出、重新开始，也可以从任意一步继续。
6. **可重置**：刷新页面或点击“重置体验”后回到初始数据和引导起点。

## 非目标

- 不连接任何后端，不调用 TikTok、R2/对象存储、版权方或飞书。
- 不保存体验者的操作，不做多人共享状态，不做账号体系。
- 不用于验收或联调，体验版的任何结果都不能当作真实业务验证证据。
- 不模拟真实的失败率、限流、配额等运行细节（预置的“部分失败”任务只是为了展示失败如何呈现、如何恢复）。

## 反目标（技术上能跑，也算失败）

- 任何一个请求打到了生产 API，或体验版读到了生产登录凭证。
- 体验者分不清自己是在体验版还是生产版。
- 体验版界面和生产版明显不同，演示出来的东西与真实工具对不上。
- 生产版改了页面或接口后，体验版悄悄坏掉也没人发现，或者每次生产改动都要花大量精力同步体验版。
- 预置数据里出现真实账户 ID、真实剧名对应的真实收入、真实人名或任何凭据。

## 已确定的方案

### 形态与入口

- 体验版是同一套前端代码的一个**独立打包模式**，复用生产的全部页面和组件，只在接口层替换为浏览器内的假后端。不复制页面代码。
- 打包产物放在生产网站的 `/demo/` 子路径下，随生产版一起打包、一起发布，不单独申请域名。
- `/demo/` **公开访问，无需登录生产账号**，链接可以直接发给没有账号的人。
- 生产版的平台租户管理页（`/platform/tenants`）上加一个“打开体验版”按钮，在新标签页打开 `/demo/`。
- 进入体验版后，登录页提供“一键进入体验”，使用内置的演示账号。演示账号拥有能看到所有页面的权限（平台管理员 + 租户管理员）。
- 页面顶部常驻“体验版 · 演示数据”横幅，并带“重置体验”和“开始引导”按钮。

### 安全隔离（同域下的三层防护）

体验版与生产版同域，浏览器存储和 Cookie 会共享，因此必须同时满足：

1. **请求打不到生产**：体验版的接口基础地址指向一个生产后端不存在的路径。即使假后端漏拦某个请求，它也只会得到 404，不会命中真实 `/api/v1`。体验版不得发出任何指向 `/api/` 的请求。
2. **不读生产凭证**：体验版不读取生产的 `localStorage.access_token`，也不读其他生产存储键。它自己的状态使用独立的命名空间，并且不写入生产会用到的键，避免影响同一浏览器里的生产会话。
3. **假后端未就绪就不渲染**：假后端启动成功之前不渲染应用。启动失败时只显示“体验版加载失败”，不发出任何请求。
4. **未覆盖的接口要醒目报错**：假后端遇到没有处理的请求时，必须明确报错（页面提示 + 控制台），不能放行到网络。

### 外部交互的模拟

- TikTok/MCP 授权跳转：点授权后直接回到页面并显示授权成功，账户、BC 列表随之出现。
- 素材上传（含直传对象存储的 `fetch` 和分片流程）：选择文件或点“使用示例素材”后，模拟上传进度并入库，不实际传输文件。
- 飞书告警、版权方取链：直接返回成功结果。
- 各类异步任务（搭建准备、提交、素材处理、报表同步、广告管理任务等）：前端靠轮询看状态，假后端按时间或轮询次数推进状态，让体验者看到“等几秒就好”的过程。整个流程的等待都控制在几秒内。

### 数据

- 剧名、账户名、ID、金额全部虚构，但看起来像真实业务：短剧风格的剧名，量级合理的消耗、ROI、回收和趋势。
- 数据之间相互一致：报表里的广告能追溯到对应的搭建任务、剧、素材和策略；同一个 BC、同一组账户贯穿各页面。
- 体验者的写操作只保存在当前页面的内存中，刷新或重置即恢复初始数据。

## 留给实施者的决定

以下由实施者决定，下面的建议是设计者的倾向，不是用户的要求：

- **假后端技术**：建议用 MSW（Mock Service Worker）在浏览器内拦截生成的 axios 客户端；也可以在生成的客户端层直接替换。需要选一种能同时覆盖素材上传里直接调用 `fetch` 的方式。
- **引导组件**：建议用 driver.js 这类轻量库，样式适配现有 shadcn 中性视觉规范。
- **路由**：设计者的倾向是体验版使用 hash 路由，所有深链接都只请求 `/demo/`，这样后端和 nginx 不需要为 `/demo/*` 增加专门的 SPA 回退规则。若改用子路径路由，就必须保证 `/demo/xxx` 刷新时返回体验版的 `index.html`，而不是生产版的。
- **数据组织**：可以复用 `frontend/tests/utils/*Boundary.ts` 和 `frontend/tests/fixtures/` 里的现有假后端与样例数据，也可以与它们共享同一份数据源，避免两处维护。不要求必须复用。
- **防止体验版悄悄坏掉**：设计者的倾向是加一个自动检查，比对前端实际使用的接口（`src/client/sdk.gen.ts`/`openapi.json`）与假后端已处理的接口，生产新增接口而体验版未处理时检查失败；再加一条端到端测试，跑通主线引导，并断言全程没有请求发往 `/api/`。
- **打包与发布接入**：怎样让 `/demo/` 产物随现有 Dockerfile / Jenkins 流程一起产出并由 FastAPI 提供，由实施者决定。不得影响生产版的构建产物和行为。
- **引导步骤的具体文案和顺序**：主线按“登录 → 选租户/BC → 账户授权 → 版权方与剧单 → 素材 → 投放策略 → 新建搭建 → 草稿 → 预览 → 提交（直接开投，无单独激活步骤）→ 搭建任务 → 广告报表 → 广告管理 → 自动化规则”的业务顺序组织，文案由实施者撰写。

## 设计者已定的细节（设计者的决定，非用户要求，实施者可在计划中说明理由后调整）

- **构建隔离**：体验版用独立的 Vite 构建模式和独立入口产出 `/demo/`（`base: "/demo/"`，独立 `outDir`，再并入生产产物目录）。假后端、预置数据和引导代码只能从体验版入口引用，生产入口不得 import。验收时检查生产产物中不含体验版的标识字符串。开发时可以用本地命令直接启动体验版。
- **绕过生成客户端的请求**：目前只有 `frontend/src/features/materials/upload-scheduler.ts:170` 直接调用 `fetch`，用于往对象存储直传分片，目标 URL 来自上传授权接口的响应。体验版里这个 URL 由假后端返回一个固定的假地址，并由同一套拦截处理。新增的直接网络调用也必须走拦截，否则会触发“未覆盖”报错。
- **路由**：体验版使用 hash 路由，后端和 nginx 不需要新增 `/demo/*` 的回退规则，只需提供 `/demo/` 下的静态文件。
- **覆盖范围**：以实施时 `main` 上已有的路由和接口为准，`features/material-production` 在内。之后新增的页面或接口，在它们各自的开发任务里补体验版数据，并由接口覆盖检查强制执行。
- **接口覆盖检查**：静态比对 `openapi.json` 中的操作与假后端已注册的处理，作为前端测试的一部分在 CI 中运行。如确有不需要演示的接口，必须显式列入豁免清单并注明原因，不能默认放过。运行时遇到未处理的请求仍然直接报错。
- **预置数据**：建立一套独立的演示数据集，比测试数据更丰富，包含多种状态和 30 天趋势。可以复用测试里的数据结构和工厂函数，但不改动现有测试数据的语义。
- **异步推进**：按时间推进，每个阶段 1–3 秒。状态只保存在内存中，刷新即重置，与“刷新回到初始状态”一致。
- **引导文案**：由实施者按业务顺序撰写。合入前用户在体验版里走一遍并提修改意见。

## 约束

- 遵守仓库 `AGENTS.md`：shadcn/ui、TanStack Router、Bun；业务逻辑加中文注释；体验版的演示结果与真实联调证据严格分开记录。
- 生产构建不能包含假后端代码和预置数据，生产行为不能有任何变化。唯一的例外是平台租户管理页上新增的入口按钮。
- 预置数据不得包含真实凭据、真实账户 ID 或真实报表数据。
- 范围较大，按 AGENTS.md 拆成可独立验证的阶段。建议的顺序（由实施者细化）：
  1. 体验版打包模式、安全隔离、主流程（搭建到报表）的假后端和数据；
  2. 其余全部页面的假后端和数据；
  3. 主线引导与每页讲解；
  4. `/demo/` 发布接入与平台管理入口按钮。

## 验收标准

- 在体验版中从登录走完主线引导，每一步都有数据和可见结果，全程没有请求发往 `/api/`，也没有读取生产存储键。
- 逐页检查：每个页面都有预置数据，每个按钮或功能点下去都有合理反馈，不出现报错或空白。
- 刷新或点“重置体验”后回到初始状态。
- 生产构建产物中不包含体验版代码；生产版除新增按钮外行为不变。
- 接口覆盖检查通过。
