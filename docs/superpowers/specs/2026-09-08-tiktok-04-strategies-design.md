# TikTok 自动化投放工具：投放策略设计

日期：2026-09-08  
状态：已于 2026-09-08 经用户确认；首版默认规则纳入实施计划。  
范围：策略配置、版本、创意文案、素材分组、命名与预览参数冻结。

关联文档：[总体设计](2026-09-08-tiktok-00-overall-design.md)、[租户与账户](2026-09-08-tiktok-01-tenants-accounts-design.md)、[版权方与链接](2026-09-08-tiktok-02-provider-links-design.md)、[素材](2026-09-08-tiktok-03-materials-design.md)、[搭建与执行](2026-09-08-tiktok-05-build-execution-design.md)。

## 1. 产品目标与边界

运营选择一份策略，即可获得本次批量广告搭建所需的预算、目标 ROAS、素材分组、创意数量与命名规则。
策略是可复用的业务配置，不直接调用 TikTok，也不持有广告账户或版权方凭据。
租户可维护自己的策略；平台可以提供策略初始模板，租户使用时生成租户内版本。
本期策略用于创建广告，不包含投放后的自动调预算、自动调 ROAS、盯盘或数据分析规则。
策略不决定每剧分配哪些账户：本批次所有有效剧目覆盖本批次全部有效目标账户。
账户来自搭建页批量粘贴的输入，不在策略里保存固定账户池、滑动轮转或每剧 K 户规则。

## 2. 已确认的广告结构

每个“剧目 × 目标账户”创建一个 Campaign。
同一剧目的素材按文件名顺序排列，再按策略中的“每组素材数量”拆成多个素材组。
每个素材组对应该 Campaign 下的一个 Ad Group，尾组不足整组数量时保留。
每个 Ad Group 创建 N 条普通 Smart+ Ad，界面统一把 N 称为“创意数量”。
这 N 条广告以 SP1、SP2……SPN 区分，使用同一个素材组，英文文案各不相同。
SP1/SP2 是本系统对广告变体的编号，不是 TikTok 的两种 API 模式，也不是 Test Ad。
本期不创建 Test Ad，也不把“一条素材”直接等同于“一条广告”。
Campaign、Ad Group、Ad 的创建请求均直接使用 `operation_status=ENABLE`。

例如：一部剧有 23 份素材，每组 10 份，创意数量为 3，则每个目标账户创建：

- 1 个 Campaign。
- 3 个 Ad Group，素材数量分别为 10、10、3。
- 每组 3 条普通 Smart+ Ad，共 9 条广告。

## 3. 策略配置字段

| 字段 | 产品含义 | 校验与作用范围 |
|---|---|---|
| 策略名称 | 租户内可辨认的业务名称 | 必填；版本不依靠名称唯一识别 |
| Campaign 日预算 | 一个 Campaign 每日预算 | 正数；按目标账户币种展示和验证 |
| 预算币种 | 日预算金额所使用的币种 | 本稿建议显式保存；与目标账户币种匹配 |
| 目标 ROAS | 各 Ad Group 使用的投放目标值 | 必填正数；不得隐式套用旧批次值 |
| 每组素材数量 | 顺序拆分素材的组大小 | 正整数；尾组保留 |
| 创意数量 | 每个 Ad Group 的普通 Ad 数量 N | 正整数；不超过可用的不重复文案数 |
| 文案池版本 | 本次可抽样的英文通用文案集合 | 必须引用明确版本 |
| CTA 配置 | 场景支持的官方 CTA 选项或动态组合 | 基于实际可用选项校验 |
| 命名模板 | Campaign、Ad Group、Ad 名称规则 | 保护版权方归因基础名，校验重名与长度 |
| 投放参数 | Smart+ Minis 场景的其他适用参数 | 以已支持字段形成可解释配置 |

Campaign 开启预算共享，旗下多个 Ad Group 共同使用该 Campaign 日预算。
界面不把日预算复制展示成每个 Ad Group 的独立预算，也不按组数或 SP 数倍增。
策略只保存目标 ROAS 的业务值，搭建服务通过官方 SDK 的对应字段提交。
地域、语言、版位和 Minis 的约束来自当前租户授权资产与版权方应用，不能使用旧项目全局默认。
Minis 具体请求字段、可支持组合和平台数值边界以后续 SDK 联调为准，文档不预设未验证硬上限。
本稿建议策略明确预算币种；目标账户币种不匹配时，该搭建单元显示异常，其余匹配单元可提交，不做隐式换算。

## 4. 素材排序与分组

素材库上传时不强制绑定剧目，策略也不维护永久的素材归剧关系。
搭建时按“文件名包含完整剧名”获取候选，仅忽略大小写与剧名首尾空白，不使用别名、翻译或模糊匹配。
匹配和人工调整结果仅属于当前搭建草稿。
文件名命中多部输入剧目时，在各剧预览中展示该素材及多剧命中提示；允许同一素材参与多部剧，不因此阻断预览或要求额外确认。
策略分组消费自动匹配及人工调整后的内部素材 ID 列表，不要求对自动匹配结果再次逐条勾选。
本稿建议按文件名升序排列，同名文件以内部素材 ID 作稳定次序补充。
排序规则版本与结果一起写入预览，不随运行环境的默认排序行为改变。
素材在预览中被移除、增补或调整组别后，重新计算分组、名称和广告数量。
已经确认提交的分组不受素材库后来增加文件影响。
目标账户 VID 的变化只是远端资产映射变化，不改变已冻结的内部素材集合。
某素材无法分发或不可用时，执行器不得自动换文件，也不得自动缩减已确认的组内素材集合。
运营可以在新的预览中移除问题素材，形成新的明确提交范围。

## 5. 英文通用文案与 SP 变体

平台预置 100 条英文通用文案，作为可版本化的内容池，而不是临时请求 AI 生成的执行依赖。
文案表达观看短剧、继续了解故事等通用意图，不虚构具体剧情、人物关系或效果承诺。
文案池以条目 ID、英文正文、启用状态、版本和维护时间管理。
同一组 SP1……SPN 从有效且正文不重复的候选文案中无放回抽样。
抽样在预览生成时完成；不在每次执行请求或失败重试时重新随机。
如果 N 大于该版本有效且不重复的文案数，策略校验直接阻断并提示调整创意数量。
不同素材组之间可以复用文案，不要求整个批次全局无重复。
本稿建议同一剧目素材组在本批次全部账户复用同组 SP 文案，便于统一核对；此范围规则已随本组设计确认。
预览保存每个 SP 对应的文案条目 ID 和实际英文正文，不仅保存随机种子。
文案池后续编辑、条目停用或租户切换策略都不会回写已提交任务。
重新抽样属于草稿编辑操作，生成新的预览版本，不能改变运行中批次。

## 6. CTA 配置

CTA 候选来自该投放场景、账户权限和当前接口支持的官方选项。
如果场景支持动态 CTA 组合，可以使用官方支持的组合方式，并在预览中显示实际选项。
100 条英文文案与 CTA 是两个独立配置，不生成或宣传“100 种自定义 CTA”。
策略保存 CTA 的选择意图，预览将其解析为当前目标账户可用的具体配置。
不同账户支持的 CTA 不一致时，对受影响的搭建单元显示原因，不静默替换成其他 CTA。
需要创建远端 CTA 资源时，由执行模块保存其 ID 和阶段状态，策略模块不发起远端创建。
重试优先复用本批次已经成功创建并回查可用的 CTA 资源。

## 7. 命名模板：本版采用的补充规则

以下是随本组设计确认的首版命名默认值，后缀仍可在策略中编辑，不引用旧批次的固定命名规则。
版权方返回的归因基础名必须原样保留，策略仅允许编辑后缀模板，不开放基础名编辑。
归因基础名不由剧名或整数剧 ID 临时拼凑，不将网眼前缀改写为统一版权方名称。
网眼原始 `{b…/s…/c…}` 归因片段的语义由版权方适配器解释，策略不推导或修改。
批次号由系统生成，在预览时确定，重复提交或失败续建仍使用同一个批次号。
本稿建议命名日期使用租户配置时区的日期，并把时区与日期值冻结到预览。

| 对象 | 建议默认模板 |
|---|---|
| Campaign | `{protected_base}-{YYYYMMDD}-{batch_short_id}` |
| Ad Group | `{campaign_name}-g{group_no}` |
| Ad | `{adgroup_name}-sp{creative_no}` |

例如基础名为 `{b30008/s328302/c3}-The Bond`，批次号为 `B7K2M9Q4`：

- Campaign：`{b30008/s328302/c3}-The Bond-20260908-B7K2M9Q4`。
- Ad Group：`{b30008/s328302/c3}-The Bond-20260908-B7K2M9Q4-g01`。
- Ad：`{b30008/s328302/c3}-The Bond-20260908-B7K2M9Q4-g01-sp1`。

同一批次不同广告账户可以使用相同业务名称，唯一性检查必须包含目标账户 ID。
系统对批次号设本地唯一约束；若同一账户出现计划内名称碰撞，预览阻断，不自动覆盖旧广告。
名称超过接口允许长度时，提示调整可编辑后缀；禁止静默截断受保护的版权方归因部分。
名称用于人工识别和远端核查，本地幂等仍以提交 ID、执行单元 ID 和步骤键为准。

## 8. 版本、引用与预览冻结

策略主记录保存租户、名称、当前版本和可用状态；每次有效编辑产生新的不可变策略版本。
草稿引用明确的策略版本，不能只保存“当前默认策略”这一可变引用。
生成预览时冻结预算、ROAS、分组、N、文案正文、CTA 解析结果、命名与实际账户范围。
预览还保存版权方链接版本、归因基础名、Minis/Identity 引用和素材源账户记录。
用户修改任一影响结果的字段后，旧预览显示已过期，必须生成新的可提交预览。
已提交任务始终消费原版本，策略的更新或停用不反向修改正在执行的任务。
停用策略阻止新的选择，不直接暂停已在 TikTok 创建并启用的广告。
策略版本不能携带凭据；引用的资产必须在提交时和执行时重新验证租户权限。

## 9. 必要接口与职责

以下接口路径与版本实体是本稿工程建议，供文档审阅，不是已经部署的接口。

| 接口 | 职责 |
|---|---|
| `GET /api/tenants/{tenant_id}/strategies` | 返回当前租户可用策略及当前版本 |
| `POST /api/tenants/{tenant_id}/strategies` | 创建租户策略和初始版本 |
| `POST /api/tenants/{tenant_id}/strategies/{id}/versions` | 校验配置并保存新版本 |
| `POST /api/tenants/{tenant_id}/strategies/{id}/validate` | 返回配置错误与场景限制，不创建广告 |
| `GET /api/tenants/{tenant_id}/copy-pools/{id}/versions/{version}` | 获取可见的文案池版本与有效条目 |
| `POST /api/tenants/{tenant_id}/build-drafts/{id}/preview` | 由搭建模块生成含策略解析结果的预览 |

租户身份从服务端鉴权上下文取得，不能信任请求体传入的租户 ID。
平台管理者需要明确进入被管理租户的业务上下文，策略读写记录操作者与实际租户。
策略校验错误区分字段错误、版本不可用、文案不足、场景不兼容和命名碰撞。

## 10. 验收示例

- 23 份素材、每组 10 份、创意数量 3：分组为 10/10/3，每账户 1 Campaign、3 Ad Group、9 Ad。
- 2 部剧都各有 23 份素材、粘贴 4 个有效账户：创建 8 Campaign、24 Ad Group、72 Ad。
- Campaign 日预算为 100：每个 Campaign 共用 100 的日预算，不显示成每组 100。
- 同一素材组的 SP1/SP2/SP3 文案正文不同；刷新执行进度、网络重试和断点续建后保持原文。
- 有效不重复文案仅 98 条而创意数量为 99：预览前阻断，不降为 98，不进行有放回抽样。
- 删除素材或重新抽样后产生新预览，旧预览不能再次作为当前草稿的提交依据。
- 版权方归因基础名在三级名称中保持完整；旧的固定 `xy` 后缀和账户窗口不进入默认模板。
- 策略发布新版本后，已提交批次预算、ROAS、素材、文案与名称仍与原预览一致。
- 三层创建参数均为 ENABLE，策略中不存在创建后等待独立激活的隐藏状态。

## 11. 前端交互补充草案，待本轮评审

本节细化 UI-06 策略列表与 UI-07 策略编辑，沿用既有策略字段及版本规则，不增加自动投后调价或报表。页面使用桌面紧凑浅色 shadcn，复用全局左侧导航与顶栏租户、BC 上下文。
UI-06 路由为 `/tenants/:tenantId/strategies`；UI-07 使用 `/tenants/:tenantId/strategies/new` 与 `/tenants/:tenantId/strategies/:strategyId`。视觉尺寸与全局状态遵循[前端体验设计](2026-09-08-tiktok-06-frontend-experience-design.md)。
策略归属于租户；顶栏 BC 为接下来搭建提供上下文，不意味着切换 BC 会复制或清空租户策略。页面顶部显示“当前租户策略”，避免把策略误认为某个固定账户池配置。

### 11.1 UI-06 策略列表

页面采用“标题及操作 → 筛选工具栏 → 分页表格”。有 `strategy_write` 权限者在标题右侧看到唯一主按钮“新建策略”。工具栏提供策略名称搜索与全部/可用/已停用筛选；默认显示可用策略，不增加 KPI 卡片。

| 表格列 | 内容与行为 |
| --- | --- |
| 策略名称 | 主名称，可进入 UI-07；复制策略必须生成新的租户内策略记录 |
| 当前版本 | v1、v2 等版本号，点击查看只读版本历史 |
| Campaign 日预算 | 币种和金额，明确单位“每个 Campaign/天” |
| 目标 ROAS | 目标数值，使用倍率表达，不显示为百分比 |
| 每组素材 | K 条/组；鼠标或键盘提示说明保留尾组 |
| 创意数量 | N 条/组，辅助显示“SP1～SPN”，与素材数量分开 |
| 状态 | 可用或已停用 Badge，不使用广告投放状态替代策略状态 |
| 更新信息 | 当前版本保存时间与操作人，可折行压缩宽度 |
| 操作 | 编辑、复制为新策略、查看版本、停用或恢复可用 |

表格不需要逐行勾选才能使用策略。编辑进入 UI-07 并保存新版本；复制进入已填充的新建表单，用户保存前不创建新记录。停用是策略可用性修改，页面明确提示“已提交任务不受影响”，不调用任何广告暂停接口。
版本历史以右侧 Sheet 展示版本号、保存时间、操作人、预算/ROAS/K/N 摘要；打开旧版本为只读查看，有 `strategy_write` 权限者可“复制为新策略”，不能覆盖旧版本。
列表使用服务端游标分页和已访问游标回退，默认每页 50 条、可切换 100 条，筛选变化回第一页；不在浏览器一次加载全部租户策略。

### 11.2 UI-07 策略编辑布局

采用独立页面，主区是分区表单，右侧是即时示例。窄桌面下示例移到表单下方，仍可查看完整内容。顶部显示策略名称、编辑来源版本及可用状态；底部固定操作区只保留“取消”和一个主操作。
新策略主操作为“创建策略”，已有策略为“保存为新版本”；旧版本详情为只读，不显示可提交表单。没有改动时不生成重复版本，保存成功进入实际返回版本，并更新列表。
必填项、错误位置与后台字段保持对应，预算和 ROAS 以十进制字符串传输，不让 UI 浮点运算改写金额。

| 表单分区 | 字段与控件 | 边界和帮助信息 |
| --- | --- | --- |
| 基本信息 | 策略名称 Input；来源版本只读 Badge | 名称必填，版本由保存生成，不让用户手工输入版本号 |
| 预算与出价 | Campaign 日预算 Input、币种 Select、目标 ROAS Input | 预算和 ROAS 为正数；显著说明“多个广告组共享这个 Campaign 的日预算” |
| 素材与创意 | 每组素材数量 K、创意数量 N，均为整数输入 | 显示“每个素材组对应一个 Ad Group；组内 SP1～SPN 使用同样素材、不同文案” |
| 文案与 CTA | 英文文案池版本 Select；有效条数只读；官方 CTA 候选控件 | 文案池预置 100 条；同组抽取 N 条不同正文；CTA 不能输入自造名称 |
| 广告命名 | 归因基础名示例只读、Campaign 后缀模板 Input、白名单变量按钮 | 只编辑后缀；`{YYYYMMDD}` 和 `{batch_short_id}` 可插入，基础名由版权方提供 |
| 生成规则 | 每剧每户 1 Campaign、每组 1 Ad Group、每组 N 条 Ad | 只读说明，不加入每剧户数、固定账户池、滑动轮转或 SP 模式选择 |

广告组与广告名称展示继承规则 `Campaign名称-g{group_no}`、`Ad Group名称-sp{creative_no}`，本轮不为它们新增未纳入 StrategyConfig 的自由编辑字段。其他投放参数只有在已有后端配置与场景校验明确支持时才显示，不增加空的“高级 JSON”输入。
表单使用 `FieldGroup/Field/FieldLabel/FieldDescription`，错误使用 `FieldError` 与 `aria-invalid`；两个互相关联的数字字段并排，中文标签完整显示，不能仅用 K/N 作为标签。

### 11.3 即时结构、预算与命名示例

右侧固定说明“示例：1 部剧 × 1 个账户，23 条素材”，示例数量不写入策略，不代表账户或剧目已被选择。改变 K 或 N 后即时更新结构：K=10、N=3 时为 1 个 Campaign、3 个 Ad Group、9 条 Ad，素材组分别为 10/10/3。
展开一个 Ad Group 可看到 SP1、SP2、SP3 共用该组素材的结构标签；若展示示例英文文案，只使用当前文案池中的样例并注明“实际文案在搭建预览抽取”。编辑 N 不在策略页执行真实抽样或写入批次。
预算区域始终显示“本例 1 个 Campaign 的日预算：币种 金额”，N 从 2 改为 3 或素材组从 2 组改为 3 组时该金额不变。整批实际预算只在搭建预览根据实际 Campaign 数汇总，策略页不猜测整批支出。
命名示例显示 Campaign、Ad Group、Ad 三行，前缀以“版权方归因基础名（示例）”标识并锁定；可编辑后缀变化后即时更新三行。变量缺失、非法字段、长度错误在对应输入下显示，不截断归因部分凑长度。
示例依据与 Task 3 后端相同的白名单规则生成；保存前以后端校验为准，不能把静态演示文案误记为真实版权方返回的名称。

### 11.4 文案池与 CTA 的交互

文案池旁提供“查看文案”只读 Sheet，显示版本、英文、条目正文及当前有效数量；租户策略页不承担生成或维护 100 条文案的功能。有效去重文案少于 N 时在“创意数量”字段下明确提示，并禁用保存。
CTA 只展示平台已核实的 Smart+ Minis 官方候选，选择结果保存为既有 `cta_option_ids`；可以根据已支持的场景呈现单项或多项选择，不提供自定义 CTA 文本输入。
官方场景目录不代表所有目标账户均可用，字段下说明“具体账户的可用 CTA 将在搭建预览中校验”。候选尚未取得时显示“CTA 候选尚未就绪”，保留已有配置，不伪造官方选项或把空候选当作全部可用；是否可保存遵循当前策略校验结果。
页面中“100 条”始终修饰英文文案池，不出现“100 种 CTA”“生成 100 个按钮”等表述。真实 CTA 资源创建与回读仍由执行模块负责。

### 11.5 加载、保存异常与权限状态

| 状态 | UI-06 / UI-07 行为 |
| --- | --- |
| 列表或版本加载 | 使用 Skeleton，保持表头与分区高度稳定；版本载入前不可提交 |
| 租户还没有策略 | Empty 显示“还没有投放策略”，有权限时提供“新建策略” |
| 筛选无结果 | 显示清空筛选动作，不把策略加载错误当作空列表 |
| 加载失败 | Alert 提供重试；已有表单输入和筛选条件保留 |
| 字段校验失败 | 行内定位具体字段，顶部短摘要链接到首个错误；按钮不提交不合法配置 |
| 正在保存 | 主按钮显示 Spinner 和“正在保存”，防止重复点击；输入保持可见 |
| 明确保存失败 | 保留输入并显示错误，修正或重试；不关闭编辑页 |
| 保存结果未知 | 显示“保存结果待确认”，先回查策略/版本记录；没有明确结果前不重复发送同一保存动作 |
| 版本已变化 | 保留本地编辑，显示当前服务器版本与差异入口；不静默覆盖其他人保存的配置 |
| 文案池或 CTA 失效 | 显示具体来源和校验错误；不自动减少 N 或替换为另一 CTA |
| 只读成员 | 列表、历史和示例可查看；隐藏新建、编辑、复制、停用等写操作，详情字段只读 |
| 权限或租户变化 | 停止旧范围请求，表单不得提交到新租户；有未保存编辑时可留在原页继续处理 |

明确已保存后才显示成功提示和新版本号。保存未知时可以查看当前服务器版本，但不能把“列表里出现相似配置”当作已证明本次写入成功。
按钮、字段、表格、版本 Sheet 都有可访问名称；错误和状态有文字说明，不以颜色作为唯一信息。Sheet 必须有标题，关闭后焦点回到触发按钮。

### 11.6 映射实施任务与验收

本节映射 [策略与预览实施计划](../plans/2026-09-08-tiktok-05-strategies-preview-plan.md)Task 6 的策略 UI 部分，数据与校验依赖 Task 1～3；不改变搭建输入和核心预览流程。

- UI-S01：列表准确显示租户策略、当前版本、Campaign 日预算、ROAS、每组素材数与创意数量，支持服务端分页。
- UI-S02：K=10、N=3、23 条示例素材时显示 1/3/9 结构；增加 N 后 Campaign 预算保持原金额。
- UI-S03：归因基础名不可编辑，后缀改变后三级命名示例同步更新，非法变量明确定位。
- UI-S04：文案池显示 100 条英文来源；同组不同文案规则清晰，CTA 只能使用官方候选，N 超容量时阻止保存。
- UI-S05：保存生成新版本，复制生成新策略；旧版本和已提交批次不被编辑动作改写。
- UI-S06：未知保存结果不盲目重试；字段错误、空列表、加载失败、版本冲突和只读权限均有明确界面。
