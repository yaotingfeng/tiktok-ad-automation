# TikTok 官方 API 与官方 MCP 双通道设计

日期：2026-09-11。状态：用户已以“没问题”确认书面设计；[分阶段实施计划](../plans/2026-09-11-tiktok-mcp-implementation.md)已形成，尚未实施。

用户已确认使用目前 Codex 中骏伯、星屿所连接的 TikTok 官方 MCP，并接受各租户管理员在 TK-ADA 中自行授权、绑定自己的 BC。交付目标是在没有本产品 TikTok 开发者 App 配置时，通过 MCP 完成账户发现、素材入库和广告搭建；官方 API 路径继续作为正式支持的另一种通道。

## 1. 范围与设计裁定

- 一套业务流程、两种适配器：`OFFICIAL_API` 使用现有固定版本 TikTok Python SDK，`OFFICIAL_MCP` 使用固定版本官方 MCP Python 客户端。
- MCP 由 Python 后端直接调用，工具、参数和顺序均由代码确定。没有 Agent、提示词执行或模型决策依赖。
- 租户管理员发起自己的 MCP 授权；凭据、连接、BC、账户及任务始终带租户归属。沿用平台管理员在明确进入租户后拥有的管理权限，普通操作员不管理连接。
- 一个租户可以管理多个 BC；每个 MCP 连接明确绑定一个 BC。相同 BC 可配置两种通道及多条独立连接，但只能有一个当前默认执行连接。
- 第一版使用 TikTok 官方 MCP 的固定服务配置，不建设通用 MCP 市场、任意 URL 连接器、独立转接服务或自建 TikTok MCP server。
- 本次不新增消耗报表、预算优化或投放规则引擎。当前项目中的自动化指素材、场景准备、广告搭建和恢复队列。
- TK-ADA 的产品规则继续生效：用户提交具体预览后，三级广告直接以 `ENABLE` 创建；所有剧目投向全部输入账户；上传不绑定剧目；保存实际来源账户及目标素材 ID。运营 skill 中的轮转账户、固定预算和停用后启用流程不成为本产品规则。

本设计在 TikTok 通信、授权、配额与连接选路范围内取代此前总体、租户账户、素材、广告执行设计中的“仅 SDK、禁止 MCP”限制。此前租户隔离、冻结意图、持久化任务和远端结果核实要求继续适用。旧设计与阶段验收记录作为历史保留。

## 2. 已核实事实与接入验证边界

2026-09-11 只读核对本地配置，`tiktok-ads-junbo` 与 `tiktok-ads-xingyu` 的 URL 都是 `https://business-api.tiktok.com/open_mcp/tt-ads-mcp-flat`。名称是本地连接别名，不能作为远端身份或 BC 授权证据。未读取缓存令牌，也未执行任何已登录 MCP 调用。

TikTok 官方介绍提供 flat、layer 两种端点，支持自建客户端，并说明 MCP 接入无需开发者凭据。官方文档目录包含独立 MCP Authorization：授权服务器发现、客户端注册、用户授权、授权码换令牌、刷新和撤销。由此选择独立 MCP 授权路径，不再要求本产品的 Marketing API App ID/secret。

上述证据不代表已验证 TK-ADA 后端的真实授权闭环。阶段 P0 必须输出可复核的协议记录，确认客户端注册条件、实际传输、授权参数、回调要求、授权范围、令牌更新与撤销语义。不得借用普通 `tt_user` OAuth 文档的参数或有效期，也不得用假 App 配置跳过现有检查。

官方 MCP 是否允许所需参数、返回足够的权限/回读证据，以及服务端是否自动重试写操作，均以 P0 协议记录和后续授权联调为准。缺失能力将阻止对应功能开放，不以模拟响应或文本成功替代。

## 4. 组件与数据流

请求流为：页面命令 → 现有应用服务/持久化任务 → 解析固定连接及授权 → TikTok 业务操作接口 → SDK 或 MCP → 标准化结果 → 业务回执与后续任务。

| 组件 | 职责与边界 |
| --- | --- |
| 业务操作契约 | 定义账户、场景、素材、广告的强类型输入输出；不泄漏 SDK model 或 MCP content block |
| 连接解析器 | 校验租户、BC、账户和固定连接；构造包含授权版本、配额域、契约版本的调用上下文 |
| 官方 API 适配器 | 封装现有官方 SDK、API OAuth、响应及异常转换 |
| 官方 MCP 适配器 | 连接官方服务，执行工具契约校验、参数转换、调用与结果解析 |
| 授权管理 | 管理授权候选、令牌刷新、授权语义版本、失效与停用 |
| 业务执行与回读 | 保留现有冻结参数、去重、outbox、步骤状态、实际 ID、未知结果核查 |

契约分成 `AccountOperations`、`SceneOperations`、`MaterialOperations`、`BuildOperations`；统一入口解析出相应实现。业务层调用明确操作，如查询 BC 账户、读取视频、通过 URL 入库、创建 Smart+ Campaign。只有 MCP 适配器内部可以调用通用 `call_tool`。

FastAPI 和 Celery 都必须经过同一解析器。客户端在确定数据库连接归属后创建，不能仅在 HTTP dependency 中注入而遗漏 worker。MCP 使用任务作用域的异步会话，通过适合现有 prefork worker 的受控调用边界运行；不跨进程继承会话、不为多个租户复用同一个已认证会话，也不让网络等待占用长数据库事务。

第一版固定官方 flat 端点，以官方 MCP SDK 管理协议握手和会话。实际传输与 SDK 版本在 P0 核实并锁定；不手写 JSON-RPC 协议。工具发现支持完整分页；应用维护经过验证的工具映射和输入/输出契约版本，未知新增工具不会自动成为产品能力。服务升级使必要字段不兼容时停止对应操作并显示连接能力异常。

## 5. 租户授权与连接生命周期

### 5.1 用户流程

1. 租户管理员在“TikTok 连接”选择“官方 MCP”，发起授权。普通操作员可使用已授权连接，不能查看或修改凭据。
2. TK-ADA 使用官方 MCP 授权流程跳转 TikTok；回调一次性关联当前操作人、租户、连接、授权服务器和固定回调地址。
3. 后台取得候选凭据，读取当前授权主体与 BC 候选。管理员明确选一个 BC，后台完整发现该 BC 的账户并核实归属、角色及能力。
4. 完整校验后原子发布新连接/新授权。失败的候选不覆盖仍有效的旧连接；部分分页结果不替换已发布目录。
5. 该 BC 没有默认连接时，首次有效绑定设置为默认；已有默认时新增连接不改变默认。管理员可单独设置新的默认连接。
6. 页面展示连接方式、绑定 BC、账户数、读取/上传/搭建能力及最近检查时间。过期或失效时显示“重新连接”；其他租户不显示该记录。

官方 API 继续自己的授权入口。缺少 App 配置只影响官方 API，不能禁用 MCP。协议配置由部署方管理，租户无需输入服务端 URL、注册密钥或 TikTok App 信息；UI 使用现有 shadcn/ui 与中性黑色主按钮规范。

### 5.2 授权安全与状态

MCP 使用自己的授权尝试记录，复用一次性 state、过期、候选验证和原子发布原则，不伪装为 TikTok API 的 `AuthorizationAttempt`。回调必须验证一次性 state、固定 issuer/resource/redirect URI，并在发布前再次检查管理员权限。采用官方核实的授权码与 PKCE 流程；若服务要求客户端注册，该注册由部署方维护，在用户授权前明确检查是否完成。

认证材料保存在带租户绑定的加密封套中。授权码、access/refresh token、完整回调 URL、签名素材 URL 不进入日志、审计事件、页面返回或 Git。OAuth 浏览器重定向是用户授权流程，后台业务请求不能将凭据转发到任意跳转目的地。

连接沿用 `PENDING_AUTH`、`DISCOVERING`、`ACTIVE`、`REAUTH_REQUIRED`、`ERROR`、`DISABLED` 的业务含义；候选授权和刷新操作单独记录进行中/失败/结果未知。临时刷新故障不会直接抹掉仍有效的旧授权。

停用连接先立即禁止本系统发送新的业务写入，并停止派发；已在途响应仍归原 attempt 保存证据。重新授权或撤销远端授权是独立、可追踪操作，不能在一个租户停用时影响另一个租户的 grant。停用记录及历史结果保留；需要使用失效连接核查未知结果时明确提示先恢复可核实的授权，不能自动借用其他连接。

### 5.3 令牌刷新与授权语义

区分三种版本：

- `credential_revision`：加密凭据材料更新，包括正常 access/refresh token 轮换，用于并发 CAS。
- `authorization_revision`：授权 grant/主体、issuer/resource、scope、绑定 BC 或权限边界发生实质变化时递增。
- `adapter_contract_revision`：业务参数/返回语义发生变化时递增。

同一 grant、主体、范围的正常刷新只改变凭据材料版本，冻结任务可使用新令牌继续执行；不能仅因 token 字节变化令全部预览失效。授权尝试及后续刷新在本地保存连续关系；只有官方实际提供的标识才记为远端 grant ID，不能编造。目录及账户权限刷新另有证据版本/时效，并在每次发送前核实。单纯发现批次 ID、检查时间或目录证据版本更新不构成授权语义变化；重复核实相同权限应允许原任务继续。

一次刷新由连接级互斥和持久化 attempt 保护，多个 worker 不同时消费同一 refresh token。发请求前记录刷新版本，落库用 CAS；数据库事务不跨网络等待。拿到新令牌后先持久化完整加密候选，再原子替换，不能先删除旧凭据。若服务器可能已轮换令牌但响应丢失，记录刷新结果未知，不并发或盲目重复使用旧令牌。只有官方协议明确保证的恢复方式可自动使用；无法恢复时要求重新连接。旧 access token 在可证明的有效期内且无撤销证据时仍可使用，无法证明有效或已经到期则暂停新远端操作。新的候选、停用和撤权优先于迟到的刷新响应，迟到结果不得恢复失效连接。

授权主体、grant 或范围改变时使旧场景/未提交预览失效，已提交任务暂停受影响的后续写入。权限扩大、换主体或换 BC 必须经过管理员明确选择与候选验证后发布；权限缩减/撤销立即限制对应操作，不等待确认。重新授权若不能证明仍是同一 grant，按新授权处理；历史未知结果保留，恢复策略不能静默放宽原授权边界。新授权下的历史核查只允许显式发起、仅限重新验证为同主体同 BC 同账户的只读权限，并保存新旧授权关联；不改变原创建请求，不据此自动续建。

## 6. 数据模型、选路与能力

具体物理表名由实施计划对齐当前模型；以下逻辑字段与不变量必须实现。

| 对象 | 必须持久化的信息 |
| --- | --- |
| TikTok 连接 | tenant、kind、显示名称、受控服务配置引用、状态、加密凭据、凭据版本、授权版本 |
| 授权事实 | 连接、上游 grant/主体、issuer/resource、授予范围、来源与核实时间；服务未提供的字段保持未知，不能编造 |
| BC 连接绑定/默认路由 | tenant、BC、connection；默认路由为该绑定的受约束外键，每个 tenant+BC 只有一个默认 |
| 账户能力证据 | tenant、BC、advertiser、connection、授权版本、账户角色、支持能力、授予权限、检查时间、目录版本 |
| 冻结调用上下文 | connection、通道、BC、授权语义版本、业务契约版本；不保存 token 副本 |
| 远端操作回执 | 原 attempt、请求摘要、实际远端对象 ID、业务 request ID、MCP 调用/任务关联 ID（如提供）、状态和核查证据 |

`BCAccountAccess` 的 tenant+BC+advertiser+connection 归属及外部资产所有权约束继续保留。MCP 新连接限一个显式绑定 BC；既有 API 连接可以保留已存在的多个 BC 关系，由 tenant+BC 的路由选择使用，不改写历史归属。

新草稿/预览使用明确选定连接；未显式选择时在预览准备开始时解析一次 BC 默认连接并保存。预览、提交、素材入库/分发、封面、场景和恢复任务全部固定自己实际使用的连接。修改默认只影响以后开始的准备操作，不使已有冻结预览或任务改道。每次发送仍检查当前授权和对应账户权限。

由同一预览/提交派生的场景、目标素材、封面和恢复任务继承父级冻结的目标执行连接，延迟生成子任务时也不重新读取默认。确需另一条来源账户连接时，将它作为明确的来源依赖保存并独立校验 tenant、BC、账户和授权；来源连接不能替换目标执行连接。

不能将“工具存在”“账户可见”“一次只读成功”当作写权限。有效能力要求应用角色、明确 BC/账户归属、官方授予范围/授权证据、账户操作角色、工具参数与完整回读能力同时成立。能力区分支持、授权和实际联调证据；写入权限通过授权与角色证据建立，不通过偷偷创建测试广告探测。缺少官方授权证据时显示待核实并阻止对应写入，P0 必须找出可用的权限来源。

## 7. 必须覆盖的操作集合

下表列出业务闭环；名称来自现有代码/可见工具定义，仅作映射输入。最终调用名、参数、默认值、分页和结果结构必须通过实际官方 `tools/list` 与协议验证确认，不能将客户端命名空间前缀直接当远端工具名。

| 业务闭环 | 必需能力 |
| --- | --- |
| 连接与目录 | 授权事实、BC 列表、BC 广告资产、账户详情、角色与完整分页 |
| 场景准备 | Identity、Minis、CTA 推荐、地区、VBO 及当前策略所需事实 |
| 视频 | URL 入库、视频信息/搜索、目标账户可用性、结果未知后的关联查询 |
| 跨账户素材 | 已核实目标优先、来源素材读取、授权 URL 转存；共享只有在映射与权限验证通过后可选 |
| 封面 | 视频封面/建议封面、图片 URL 入库、图片信息/搜索及目标映射 |
| 创建 | CTA portfolio、Smart+ Campaign、Ad Group、Ad |
| 回读 | 上述对象的详情/分页/父子关系；必要时普通 `adgroup_get` 补充实际状态 |

返回结果使用业务 DTO，至少保留精确字符串 ID、分页完整性、金额/状态、调用证据与必要素材身份。MCP `isError=false`、自然语言“成功”或 HTTP 200 都不能独立证明业务成功；需要验证业务 envelope 与实际字段。对结构化结果优先校验，文本中的 JSON 只有满足固定版本完整契约时才接受；任意说明文本不参与业务判定。

代码使用 skill 中已验证的接口经验，例如读取 `smart_plus_ad_id`、目标账户回查、建议封面和 Smart+ 状态补查。现有 skill 的规模、预算、状态与失败清理策略不是本产品的默认输入，不自动删除本次空结构。

## 8. 素材上传与原件生命周期

首选现有 R2 流程：浏览器分片上传 → 后端校验完整原件 → 发送前生成受限时效 URL → MCP URL 入库 → 原账户视频回读 → 封面准备 → 目标账户验证。远程 MCP 不接收本机文件路径，也不把完整视频编码进 JSON。

当前应用允许单文件 1 GiB，这是应用容量设置，不是已经验证的官方 MCP 上传上限。对 MCP 路径增加按服务实测能力的检查；大文件吞吐、超时和可用容量单独验收，不因现有 R2 允许 1 GiB 就宣称 TikTok 已支持。

MCP 上传 schema 与 SDK 不完全一致，尤其 `video_signature`、`auto_bind_enabled` 等字段不能假定存在。P0/P2 必须确认在实际工具字段和响应下，原件摘要、内容身份、不自动修复、实际来源 advertiser 和目标 VID 的证据能满足当前契约。无法证明时阻止该路径，不伪造摘要、不悄悄 Smart Fix 或降低校验。

入库请求持久化稳定名称、原件代次、请求摘要、来源账户与连接。已取得 VID 先保存，再进行会话清理和视频回读。结果未知时保留原操作、来源及用途引用，不换名字/账户重新上传。无歧义读回后才能恢复后续步骤。

R2 原件由持久化用途引用保护，覆盖已发出请求、远端可能拉取、未知结果和恢复窗口。收到 MCP 返回、URL 过期、本地 worker 退出或租约到期均不等于远端已完成。只有满足已定义终态、保留策略且无活跃用途时才可删除；未解决用途持续占用容量预算并显示原因，不被自动过期清理绕过。

已有素材复用、共享或 URL 转存都必须保存真实来源 advertiser 与目标账户 VID/图片映射。共享尚未通过当前生产契约验证，不能据运营历史直接打开；优先完成当前可验证的 URL 路径。若目标跨账户分发缺乏权限或证据，该批次保持不可提交，不能只完成源入库就标记素材闭环成功。

## 9. 广告执行、未知结果与配额

### 9.1 执行与核查

使用现有冻结预览、提交回执、步骤展开和 outbox。在副作用前重新检查租户权限、固定连接、授权版本、账户能力和素材；取得准入后将精确请求及 attempt 持久化，再发送远端请求。

每个创建工具对应一个可追踪的业务操作，返回实际 ID 后立即保存，再清理客户端。三级对象直接以冻结请求中的 `ENABLE` 创建，后续分别回读实际参数和状态；`ENABLE` 不代表审核通过、已投放或有消耗。

| 情况 | 处理 |
| --- | --- |
| 请求确定未发送、额度不足或本地预检失败 | 保持未发送语义，按对应规则修正/重新调度 |
| 明确取得远端 ID | 先保存创建事实，再核对参数；清理失败不能把它变为可重建失败 |
| 发送后超时、断线、worker 终止、无法解析回执 | 结果未知，保留原 attempt；通过原连接只读核查 |
| 平台明确拒绝 | 按已验证错误类别记录；只有证明未产生副作用时才允许按规则重试 |
| 回读为空、分页不全、多候选或字段缺失 | 保持未知；不根据等待时长或“没查到”自动重建 |
| 权限撤销、连接停用或契约改变 | 阻止后续写入，保留已产生的对象证据和待核查状态 |

MCP 断开不证明远端取消。本地硬超时仅限制 worker 占用；若服务提供任务 ID、deadline 或取消机制，只有核实其保证后才能使用。协议未证明服务端结束时，同一步/同一素材不得发起竞争写入，不自动切另一通道补建。客户端关闭自动写重试；服务端重试语义必须记录，不能把 MCP JSON-RPC request ID 当作上游幂等键。

若已知服务端会自动重发非幂等写且没有已验证的端到端幂等保证，对应写能力不得开放。没有服务端保证时，不能承诺端到端“恰好执行一次”；本系统的验收承诺是结果未知后不再次发送同一副作用请求，保留证据并核查。P0 必须明确服务端可证明的保证及局限，真实联调记录已观察到的远端对象数量。

### 9.2 限流与并发

复用 Redis 调用准入和租户公平机制，同时区分服务共享额度、操作类别及广告账户。API 通道按真实 App 配额域；MCP 按可信服务/上游配额域，并叠加 MCP 自身限制。多个连接共用一套上游额度时必须共用桶，不能使用随机 connection ID 规避共享限制。配额域未知时将官方 MCP 归入保守共享桶，收到限流后退避。

每次实际工具调用及必要会话请求受限流和整体期限控制。握手、网络读超时、业务任务硬期限和租约使用明确预算；准入拒绝通过持久化重新调度，不在 worker 内长时间 sleep。远端结果未知的操作保留业务围栏；本地租约到期不释放同一操作的重发权，也不能被表述为远端并发已归零。

## 10. 迁移与发布

通过新增 Alembic 迁移扩展连接类型、授权/凭据版本、MCP 授权尝试、BC 默认路由和冻结调用上下文，不改写已交付迁移。

- 现有连接显式归为 `OFFICIAL_API`，保留 tenant、BC、账户、凭据和历史来源。
- 一个 BC 只有一条有效旧连接时建立相应默认；有多条时要求管理员明确选择，不延续 UUID 排序行为作为新规则。
- 历史已提交请求、名称、摘要及远端 ID 不变。通过可核实的历史连接建立伴随执行上下文，不修改不可变请求；缺少证据则阻止恢复并说明原因。
- 旧版尚未提交、缺少完整通道上下文的预览显式过期，重建后才可提交。新规则下修改默认连接不会使已冻结的新预览失效。
- 未知或在执行的任务不自动迁到 MCP；原通道的权限及回读仍必须可用。两条正式适配器均维护对应业务契约，不保留通用旧逻辑 fallback。
- 发布使用目标环境手册，先冻结新写、排空、备份、迁移和验收；MCP 功能按完成的能力开放，离线通过不自动开启真实写入。

本轮设计不授权部署、真实 OAuth 注册/授权/撤销或任何真实广告写入。后续真实联调必须记录目标环境、明确 BC、连接、账户、素材、预算和具体用户授权。直接使用运营 MCP 工具验收时，骏伯只能用 `tiktok-ads-junbo`，星屿只能用 `tiktok-ads-xingyu`；不得无说明混用两者。TK-ADA 后端使用自身租户连接 ID 并记录所选 BC。

## 11. 阶段交付与验收

本设计是一个双通道子系统，实施计划分为下列职责明确的阶段，按依赖推进；不把所有改动压进一份无边界的大任务。

| 阶段 | 交付物 | 完成标准 |
| --- | --- | --- |
| P0 协议与契约核实 | 官方客户端接入/授权记录、SDK 版本、能力矩阵、schema 和回读证据规范 | 证明独立授权路径无本产品 App 前置；明确必需权限、参数、返回、期限和重试语义；缺失项阻止对应写能力进入后续开放 |
| P1 连接与只读 | 连接模型/迁移、租户授权/刷新、默认路由、统一业务契约、账户/场景/素材/广告读取 | 没有任何 TikTok App 配置时 MCP 仍可授权与发现；目录完整发布、权限隔离、正确选路；API 既有行为回归 |
| P2 素材闭环 | R2 URL 入库、结果核实、封面、目标分发、未知恢复及清理保护 | 实际来源与目标映射完整；超时不重传、不提前删原件；完整素材身份契约通过 |
| P3 广告闭环与集成 | CTA/三级创建、回读、异常归类、恢复、页面状态、运行手册 | 同一业务测试分别通过两通道；响应丢失不由系统再次发送创建；目标环境独立验证、授权小批量试投另记证据 |

P0 对客户端注册/认证的验证若发现需要尚未具备的官方条件，应先报告具体条件和可用路径，不用 Codex 缓存 token 或手工假 scope 顶替。文档里已公开的官方能力与真实后端联调证据分开记录。

必须验证的行为：

1. App ID、secret、redirect 配置全部缺失时，MCP 通道仍运行；API 只阻止自身调用。
2. tenant/BC/advertiser/grant 任一不符、普通操作员管理连接、回调重放和跨租户回调均被拒绝。
3. BC 默认切换、新增连接和 UUID 大小不改变已冻结的调用路由。
4. 同一 grant 正常 token 刷新不使任务失效；主体/范围变化、撤权和停用会阻止后续写入。
5. 刷新并发、令牌轮换后响应丢失、迟到响应、候选授权失败不污染其他连接和有效旧凭据。
6. MCP 与 SDK 返回相同业务数据，包括分页、ID、金额、素材映射和错误类别；工具 schema 漂移不会静默丢字段。
7. 真实 PostgreSQL/Redis 下验证共享额度、任务去重、claim/nonce、outbox 恢复和真实 worker 中断；外部替身仅位于传输边界。
8. 模拟远端创建成功丢响应、上传继续拉取、回读为空、多候选及迟到回执，均不产生第二次写入或提前清理。
9. 两通道覆盖账户、场景、素材、封面、CTA、三级创建与完整回读，未完成必要依赖时预览不能提交。
10. 前端覆盖管理员授权、BC 绑定、连接选择、权限提示、过期重连、任务进度及租户切换；运行相关构建与迁移检查。
