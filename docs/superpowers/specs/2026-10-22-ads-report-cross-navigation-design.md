# 广告报表：剧→系列跳转、详情关联对象可操作、素材成片预览

日期：2026-10-22
状态：已实施（2026-10-23，用户授权实施者自定细节并直接实施）

## 背景与目的

用户在广告报表里按剧看数据时，经常要转去看、去管这部剧挂着的系列。现在有三处断点：

1. 剧维度的名称格子没有"›"跳转，其他维度（账户→系列→广告组→广告）都有。
2. 详情抽屉里点关联对象（剧详情的"关联系列"、各详情的"层级路径"）后，抽屉换成该对象的详情，但它是前端拼出来的只有 ID 的行（`detailRowFor`），不在报表快照里，所以被强制只读：没有启用/暂停/改预算等按钮，没有指标；而且换过去后回不到原来的详情。
3. 素材维度详情看不到视频本身，只能看使用位置。

目标：让用户在剧、系列、素材之间顺手跳转，且从任何入口打开的同一类对象详情都长得一样、能做一样的操作。

## 目标

### 1. 剧维度跳转到关联系列（用户确认）

- 剧维度名称格子右侧显示与其他维度相同的"›"按钮（`AdsNameCell` 目前只在 `childDimension()` 有值时显示）。
- 点击后切到系列维度，**只列出这部剧关联的系列**（来自剧行 `refs` 中 `kind === "campaign"` 的条目，可能跨多个账户）。
- 筛选标签（`AdsScopeChips`）显示"剧：<剧名>"，点叉号清除该筛选、回到全部系列。
- 剧没有任何关联系列时，不跳转，给出提示（复用 `setActionError` 的现有提示方式）。

### 2. 详情抽屉里的关联对象与在本维度报表中打开的详情一致（用户确认）

- 从剧详情点关联系列、从任何详情点层级路径里的账户/系列/广告组，打开的详情必须与在该维度报表里点开同一对象的详情**完全一致**：
  - 顶部同样的操作按钮（`actionsFor(dimension)`，按当前角色是否只读决定）；
  - 同样的页签（概览、趋势、设置、素材、操作记录，按维度规则显示）；
  - 概览里的核心指标为当前报表日期范围内该对象的真实数值。
- 抽屉左上角增加"返回"按钮，维护一个访问栈：例如 剧 → 系列 → 账户，可逐层退回；栈只有一层时不显示返回。关闭抽屉清空栈。
- 剧详情的"关联系列"列表改为显示**系列名**，第二行小字显示系列 ID 和所属账户（现在只显示 ID）。

### 3. 素材详情里预览成片（用户确认）

- 素材维度详情里放一个视频播放器，体验对齐素材库 `AssetDetails` 的"预览账户素材"。
- **必须覆盖不是通过本工具上传的外部素材**（用户明确确认），因此不能依赖素材库的 `MaterialFile` 记录，而是按"广告账户 + 平台视频 ID"直接向 TikTok 读预览地址。
- 视频 ID 与账户取自素材行的 `material_uses`（`platform_material_id` + `ad_ref.advertiser_id`）。

## 非目标

- 不改报表查询、指标口径、同步频率。
- 不新增批量操作；详情里仍是单对象操作。
- 不在素材详情里提供下载、替换或启停素材（启停仍在广告详情的素材页签）。
- 不做浏览器地址栏可分享的详情链接。

## 反目标（技术上能跑也算失败）

- 从关联入口打开的详情和本维度打开的详情样式或可用操作不一致。
- 详情里的操作作用到了别的对象，或越过租户/BC 范围（关联对象必须在当前 BC、当前租户、当前用户有权的账户内）。
- 为了让关联对象可操作而绕过现有"冻结选择 → 预览 → 提交"的管理流程。
- 素材预览接口变成可以按任意账户/视频 ID 读取的后门：必须校验当前租户在该 BC 下对该账户有读权限。

## 约束

- 遵守本仓库 `AGENTS.md`：shadcn/ui、TanStack、中文业务注释、复用现有方法、不保留旧逻辑兜底分支、调用 TikTok 走官方 SDK / 已批准的 MCP 通道。
- 所有新读写都要带 tenant + BC 范围，查询键包含 BC（沿用 `AdsDetailSheet` 现有做法）。
- 管理操作只能基于冻结选择（`FrozenSelection`）发起。
- 素材预览地址必须经过现有的预览域名白名单校验（`sdk_assets.source_preview` 中的 `allowed_hosts`）。
- 演示模式（`frontend/src/demo/`）有报表与素材的样例处理器；新接口需要在演示模式下有对应样例或明确禁用，不能报错。

## 已有实现可复用（供实现者参考）

- 下钻与筛选：`AdsWorkspace.tsx` 的 `navigateToChild`、`filterTo`、`applyScope`、`setScopeLabels`；`search.ts` 的 `CHILD`、`childDimension`。
- 报表查询按 `ids` 过滤：`query_ads_route` 的 `ids` 参数（CSV）。TikTok 系列 ID 全局唯一，跨账户时可以只按 `ids`、不传 `advertiser_id`。
- 详情抽屉状态：`AdsWorkspace.tsx` 的 `detail` state（`row / dimension / fromSnapshot`），`readonly={roleReadonly || !detail?.fromSnapshot}` 就是关联对象只读的来源。
- 冻结选择：`selectionMutation` 调 `freezeAdSelection`，用 `snapshot_id + row_keys`；单对象冻结的另一个先例是 `freezeAdMaterialSelection`（`backend/app/modules/reporting/ad_materials.py`）。
- 远端素材预览：`backend/app/modules/materials/remote_sources.py`（`read_remote_source`、`freeze_route`）、`sdk_assets.source_preview`（`expected_md5` 可为 `None`）、`accounts.access.usable_grants`。前端播放器样式见 `materials/AssetDetails.tsx`。

## 推荐做法（实现者可调整，但需满足上面的目标与约束）

**关联对象详情**：打开关联对象时，不再拼假行，而是用"该维度 + `ids=[对象ID]` + 当前日期范围"发一次报表查询，拿到带快照的真实行。详情抽屉记住这一行所属的快照 ID 和维度，操作按钮用这个快照冻结选择、并以该维度打开 `ManagementPreviewSheet`。这样指标、可操作性与本维度一致，且完全复用现有冻结/预览/提交流程，不需要新的后端冻结接口。查询失败或查不到该对象时，详情显示错误与重试，不降级为只读假行。`detailRowFor` 随之删除。

**关联系列名称**：剧详情打开时，用同样的方式按关联系列 ID 查一次系列维度，取名称展示；该结果也可直接作为点进系列时的行。

**素材预览**：后端新增一个只读接口（建议放在 reporting 或 materials 模块，由实现者决定），入参为 `advertiser_id + video_id + bc_id`，校验租户读权限与该账户的可用授权后，通过已冻结的通道路由读取 TikTok 视频信息，用 `source_preview` 校验（不传 `expected_md5`）并返回预览地址、宽高、时长、格式。前端在素材详情加"预览成片"按钮（与素材库一致，点击才读取，避免每次打开详情都调用 TikTok），从 `material_uses` 里依次尝试有权限的账户，第一个成功即播放。

## 留给实现者决定

- 访问栈存放位置（`AdsWorkspace` state 还是抽屉内部）。
- 剧筛选标签的数据结构（扩展 `ScopeKind` 还是单独字段）。
- 素材预览接口的具体路径、所属模块、限流策略键（需在 `TIKTOK_CALL_POLICIES` 中有对应准入策略，若复用 `materials.get_videos` 则无需新增）。
- 前后端测试的具体用例划分；至少覆盖：剧跳转筛选、关联详情可操作且操作冻结的是正确对象、返回栈、预览接口的权限拒绝路径。

## 审阅后补充的决定（实现者自定，用户已授权）

1. 关联对象按 `ids=[ID]` 查询返回多行时，只取账户与入口记录的 `advertiser_id` 一致的那一行；没有一致的行视为"该对象不在当前报表范围"，显示错误与重试，不做选择器。查询带 `include_empty=true`，零消耗对象也能打开。
2. 素材预览接口一次接收一个 `video_id` 和多个候选 `advertiser_id`（取自 `material_uses`，去重、上限 20），后端在 SQL 中筛出当前租户在该 BC 下有读授权的账户，按入参顺序只读取第一个有授权的账户；没有任何有授权账户时返回明确错误。前端只发一次请求。
3. 剧行 `refs` 中的系列条目带 `advertiser_id`（`EntityRef` 必填）。剧跳转系列只按去重后的系列 `ids` 查询，不传 `advertiser_id`；“显示无数据对象”沿用用户当前设置，与账户→系列等下钻一致（实施时调整，原写法是强制 `include_empty=true`，会悄悄改掉用户的筛选）。详情里的关联对象查询仍带 `include_empty=true`。
4. 演示模式：新预览接口沿用现有 `materials-read_remote_preview` 演示处理器的做法，返回封面地址与固定宽高时长，不准备真实视频。
5. 返回栈每层只存"维度 + 行 + 来源"（来源是工作台表格或关联查询）。返回时，表格来源的行从当前表格数据重新取（沿用现有 `items.find`），关联来源的行由 react-query 缓存提供；关联查询键纳入现有 `refreshCurrentPage` 的失效范围，操作提交后的回读会刷新它们。

## 验收标准

1. 剧维度点"›"后进入系列维度，列表只含该剧关联系列，筛选标签显示剧名，清除后恢复。
2. 剧详情 → 点关联系列 → 抽屉显示的内容和按钮与在系列维度点开同一系列一致；点"改预算"等操作走完预览后作用于该系列。
3. 剧 → 系列 → 账户 后可连按两次"返回"回到剧详情。
4. 素材维度详情点"预览成片"能播放视频，包括非本工具上传的素材；无权限账户时给出明确提示。
5. 前端 `bun run lint`、构建通过；后端相关测试、`scripts/lint.sh` 通过；结果记入 `docs/implementation-progress.md`。
