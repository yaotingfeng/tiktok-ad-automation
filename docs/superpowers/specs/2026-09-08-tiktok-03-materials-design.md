# 素材中心功能设计

日期：2026-09-08。状态：已于 2026-09-08 经用户确认，作为实施计划依据。
上位约束：[整体设计](2026-09-08-tiktok-00-overall-design.md)。本稿只定义功能，不包含实施计划。

## 1. 目标与范围

本模块完成租户素材的批量上传、账户资产记录、搭建时检索和向目标账户分发。
上传文件与剧目无固定绑定；同一素材可在不同搭建批次中使用，实际关系保存在各次搭建快照。
本轮不包含视频剪辑、生成素材、下载版权方正片、素材效果报表或数据同步策略。

## 2. 已确认的业务决定

- 用户本地批量上传素材，系统保存文件名和文件信息，上传时不识别或绑定所属剧目。
- 上传界面固定提示：**请在素材文件名中包含完整剧目名称。广告搭建时，系统会根据剧名自动匹配素材。**
- 用户无需配置素材账户；系统从当前租户、当前 BC 的授权且具备上传权限的账户中指定一个。
- 每次上传记录实际上传账户和远端素材标识，不假设租户永久只有一个素材账户。
- 搭建时按本次已确认剧名查找文件名包含该剧名的素材，预览中允许剔除、补选、调整分组。
- 默认按文件名排序，按策略的每组素材数量顺序拆分，最后一组保留剩余素材。
- 每个素材组生成一个 Ad Group；该组所有 SP 创意共用同一组素材，分别使用不同文案。
- 搭建时把素材分发到本批目标账户，回查并记录目标账户实际可用的素材 ID。

## 3. 页面与用户流程

### 3.1 批量上传

上传页展示当前租户与 BC、命名提示、拖拽区和文件队列，不要求填写版权方或剧目。
用户添加多个本地文件后，列表逐项显示原始文件名、大小、上传进度与错误信息。
文件传入对象存储后，由后台任务上传 TikTok；浏览器关闭不取消已经接收的后台任务。
尚未完整传入对象存储的文件需要浏览器继续上传；页面不得把本地传输完成等同于 TikTok 素材已可用。
列表区分本地传输、等待平台上传、平台处理中、可用、失败及结果待核实。
用户可重试失败项，成功项不重新上传；实际所用账户在结果详情中可查。

### 3.2 素材列表

素材列表按租户隔离，支持文件名检索、上传时间与状态筛选、服务端分页和预览。
列表保留原始文件名；详情显示文件信息、实际所在账户、远端 ID、上传或分发记录。
文件存在不代表在每个广告账户可用，账户资产状态单独展示。
首版不设置剧目归属字段，也不要求用户维护文件名解析规则。

### 3.3 与搭建预览的协作

以下预览、分组和 SP 配置由搭建模块负责，素材中心只提供候选文件、账户资产与分发结果。

1. 接收本次已解析的正式剧名和目标账户列表，在当前租户素材库中检索文件名。
2. 文件名包含完整剧名的素材作为候选，未匹配到时显示该剧异常。
3. 按文件名排序并分组，显示每组素材、数量及对应 SP1～SPN。
4. 用户可以剔除、补选或移动素材，修改只影响本次预览。
5. 预览计算目标账户所需的素材分发范围；已在目标账户核实可用的素材可复用。
6. 提交时冻结文件身份、排序、分组和目标账户需求，后台生成分发任务并补齐目标账户资产。
7. 某一素材分发失败时标记受影响组合，其他满足创建条件的组合可以继续。

## 4. 文件名匹配与分组边界

匹配是“素材文件名包含本次完整剧名”的字面包含查询，仅忽略大小写和剧名首尾空白，不解析版权方、日期或批次格式。
用户输入剧名在版权方模块确认后再用于匹配，避免把尚未解决的同名剧当作确定结果。
命中只表示文件名符合条件，不保证素材语言、内容或版权正确；预览提供人工核对与调整入口。
一条素材可以命中多部输入剧目，系统不据此建立永久归属，也不自动从其他剧目的预览中移除。
同组 SP 使用同一素材清单；创意数量变化只增加文案变体，不重复生成素材组。
素材每组数量必须满足本次广告产品和官方 SDK 接口允许范围，超限在预览中明确提示。

## 5. 账户来源与目标映射

选取上传账户的范围严格限定于当前租户、当前 BC 及当前授权连接，并检查实际上传能力。
同一远端广告账户被多个租户授权时标记归属冲突，管理员处理前不得供第二个租户上传或搭建。
一次上传确定账户后保存该选择；续跑优先恢复同一账户的未完成步骤。
原账户不可用时，允许重新选择可用账户并创建新的上传尝试，原尝试与结果保留。
已成功上传的素材仍记录在原账户，不因后续默认选择变化而改写所在账户。
搭建需要目标账户资产时，先查询本租户已保存的该文件、该账户映射，再回查可用性。
源账户与目标账户相同，也要校验现有资产可用；不同账户不能直接沿用源 VID 或 MID。
TikTok 操作直接使用官方 Python SDK，不增加 MCP 或手写 HTTP 作为替代调用层。
具体跨账户共享能力以 SDK 与目标账户权限联调为准，不能将素材存在于源账户视为共享必然成功。

## 6. 本版采用的补充规则：实体与接口

以下为已审阅的工程结构，具体文件与接口契约在对应实施计划中定义。

| 实体 | 核心字段与职责 |
| --- | --- |
| MaterialFile | 租户、内部文件 ID、原始文件名、对象引用、哈希、大小、格式、时长与分辨率 |
| UploadBatch | 租户、BC、实际操作人、文件清单、批次状态与汇总进度 |
| MaterialUploadAttempt | 文件 ID、实际账户、连接、任务状态、尝试次数、远端响应证据 |
| AccountMaterial | 租户、BC、广告账户、文件 ID、实际 VID/MID 等类型化标识、封面引用、可用状态 |
| MaterialDistribution | 文件、目标账户、可用源资产、分发方式、步骤状态与回查结果 |

剧目与素材关联、有序素材组及 SP 配置仅存于搭建模块的快照，不属于素材目录实体。

远端返回 VID、MID 或其他标识时保留具体类型；不同标识不因都是字符串而混用。
对象存储路径包含不可猜测的租户和文件标识；下载访问需验证当前租户权限。
同租户相同哈希可以复用原始对象存储，但每次导入保留原始文件名和记录，不静默丢失文件名检索入口。
文件名同名但内容不同应保留为不同素材；文件名升序排列，同名用 material_id 作为稳定次序。
检索建议仅忽略大小写和剧名首尾空白，保留标点语义，不自动做翻译、别名或模糊扩展，未命中时允许人工补选。

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| 建立批量上传 | BC、文件名、大小、格式、可选哈希 | batch_id、各文件 material_id、上传会话 |
| 确认文件接收 | material_id、对象上传结果 | 接收状态、平台上传任务 ID |
| 查询上传进度 | batch_id | 每文件阶段、传输进度、实际账户与错误 |
| 检索匹配素材 | 已确认剧名、BC、分页参数 | 候选文件、现有账户资产状态 |
| 确保目标资产可用 | snapshot_id、文件 ID、目标账户 ID | 分发任务 ID 或已核实资产映射 |

服务端从登录上下文确定租户，校验 BC、文件和目标账户均属于该租户。
接口返回的是内部文件身份与账户资产身份两层结果，前端不自行推导或复制远端 ID。

## 7. 本版采用的补充规则：任务与幂等

文件阶段为 `receiving → stored → validating → uploading → verifying → available`。
分发阶段为 `pending → checking_existing → transferring → verifying → available`，已有资产可跳过 transferring。
异常区分 `invalid_file`、`blocked_auth`、`retryable_error`、`result_unknown` 和 `failed`。
接收大文件建议使用对象存储的分片上传能力，完成后检查对象大小与完整性，再调度平台上传。
按租户、BC、文件身份和目标账户建立有效任务约束，避免多个搭建批次并发重复分发相同文件。
Worker 持有任务进度；文件传输、平台上传、平台处理和回查分别记录，重试恢复缺失阶段。
上传超时且无法判断远端是否成功时先回查或核实，不立即开始同一文件的重复上传。
SDK 支持且权限允许时使用原生共享；否则建议使用已保存原文件，经官方 SDK 上传目标账户。
这种上传退路会产生新账户资产和流量成本，必须记录具体路径，不把两种方式当作同一操作。
不存在安全可用的 SDK 路径时标记受影响项不支持，不静默切换手写 HTTP 或跨租户源账户。

## 8. 错误与恢复

| 情况 | 行为 |
| --- | --- |
| 当前 BC 无可上传账户 | 文件可保留在对象存储，平台上传阻塞并展示原因 |
| 文件不满足平台要求 | 单文件失败并显示原因，其他文件继续 |
| 文件名没有完整剧名 | 上传正常；搭建未命中时按命名提示修正输入或人工补选 |
| 源账户失去权限 | 保留历史映射，使用合法可用源或原文件恢复，不改写历史账户 |
| 目标账户分发失败 | 只影响依赖该资产的组合，保留已完成账户结果 |
| 目标返回新的 VID/MID | 保存并使用回查确认的目标标识 |
| 预览期间素材状态变化 | 提交时重校验；冻结后执行遇到失效则暂停受影响步骤 |

## 9. 验收场景与跨模块约束

- 上传界面显示指定命名提示，上传成功记录中没有自动生成的剧目绑定。
- 同一租户前后两批素材上传到不同账户时，每条素材均可追溯正确源账户。
- 文件名包含完整剧名的素材在搭建时命中，重名内容不同的文件不会被误合并。
- 三十条素材、每组十条、创意数量三时生成三个素材组，每组供三个 SP 共用。
- 三十一条素材、每组十条时保留第四组的一条素材，并经过平台数量约束校验。
- 手工调整与分组在预览确认后固定，重试不重新检索新增文件或重新排序。
- 同一素材分发到多个账户后，各账户使用本账户回查确认的远端标识。
- 关闭浏览器后，已接收文件的平台上传继续；未完整接收文件准确显示未完成。
- 一项失败可单独恢复，成功项不重复上传，其他租户不能检索或使用其素材。

[版权方设计](2026-09-08-tiktok-02-provider-links-design.md)提供已确认剧名，不负责素材归类。
[策略设计](2026-09-08-tiktok-04-strategies-design.md)定义每组数量和创意数量；素材模块提供稳定排序的候选列表，搭建模块负责分组。
[广告搭建与执行](2026-09-08-tiktok-05-build-execution-design.md)负责预览版本、冻结、部分提交及广告创建状态。
本稿建议首版保留原始文件与账户资产映射，不设自动过期，也不开放物理删除，以支持已提交批次恢复；后续存储清理策略另行设计。

## 10. 前端交互补充草案，待本轮评审

本节细化 UI-05 素材库，原有业务规则保持不变。页面采用桌面紧凑浅色 shadcn 风格，复用全局左侧导航与顶栏租户、BC 上下文；不增加报表、效果卡片或剧目归属设置。
路由为 `/tenants/:tenantId/materials`，BC 使用 `bc_id` 查询参数；视觉尺寸与全局状态遵循[前端体验设计](2026-09-08-tiktok-06-frontend-experience-design.md)。

### 10.1 UI-05 素材库布局与主操作

主体为“标题及操作 → 素材库/上传队列两个页签 → 筛选工具栏 → 分页表格”。有 `upload` 权限者在标题右侧看到主按钮“批量上传”；“上传队列”页签显示当前范围内未结束的文件数量，关闭上传面板后仍可独立访问。
素材目录默认使用表格，缩略图是文件名的辅助信息；不采用占用大量空间的视频卡片墙。普通表格行高 48 px、复杂行可 64 px，控件高度 36 px，长文件名截断并可查看完整名称。
顶栏租户与 BC 决定所有查询范围，不在素材页再次添加账户选择器。尚未选择有效 BC 时显示上下文提示，上传入口不可用。

| 筛选或操作 | 行为 |
| --- | --- |
| 文件名搜索 | 输入关键词后服务端查询；支持清空，不改写原始文件名 |
| 素材状态 | 全部、等待上传、处理中、可用、需处理；需处理包含明确失败、权限阻塞与结果待核实，行上仍分别显示 |
| 上传时间 | 日期范围；与文件名及状态组合筛选 |
| 批量上传 | 打开 UI-05A 右侧 Sheet；不先要求选择剧目或素材账户 |
| 上传队列 | 切换至 UI-05B，可按批次与处理状态查看文件 |
| 下一页/上一页 | 服务端游标分页；上一页使用已访问游标，筛选改变后回第一页 |

表格默认每页 50 条，可切换至 100 条；仅改变显示分页大小，不限制素材库总量。界面不提供后端尚未支持的任意跳页。

| 素材表格列 | 展示与交互 |
| --- | --- |
| 素材文件 | 小缩略图、原始文件名；点击打开文件预览，文件名可以复制 |
| 文件信息 | 时长、分辨率、大小；元信息尚未取得时显示“待识别文件信息”，不显示猜测值 |
| 平台入库状态 | 已接收、等待上传、上传中、核实中、可用、失败或结果待核实的明确 Badge |
| 上传账户（最近一次） | 实际账户名称与字符串 ID，只读；尚未分配时显示“尚未开始平台上传” |
| 可用账户数 | 已核实可用资产所在账户数；点击打开账户资产详情，不代表全部目标账户都已可用 |
| 上传时间 | 最近上传尝试时间；未开始平台上传时展示本地文件接收时间并标明 |
| 操作 | 预览文件、查看账户记录；失败恢复在上传队列中执行 |

没有批量删除、永久剧目绑定或“设为素材账户”操作。顶部不提供必须勾选整批素材才能继续的流程；剧名匹配发生在广告搭建页面。

### 10.2 UI-05A 批量上传 Sheet

使用带 `SheetTitle`、`SheetDescription` 的右侧 Sheet，桌面宽约 680 px，内容超出时内部滚动，底部操作保持可见。文件命名提示完整显示在拖拽区上方：

> 请在素材文件名中包含完整剧目名称。广告搭建时，系统会根据剧名自动匹配素材。

拖拽区支持批量添加本地视频，并提供“选择本地素材”按钮；添加后以紧凑清单展示原始文件名、大小、可上传状态与移除按钮。这里只校验文件类型、大小和重复选择，不识别所属剧目。
底部主操作为“开始上传 N 个文件”，N 仅包含本次可接收文件；明确列出不能上传的项及原因。开始前可移除某个待上传文件；不把移除待选文件等同于删除已入库素材。
点击开始上传并成功创建批次后，进入独立上传队列；文件传输由页面公共上传管理器继续，不能因 Sheet 关闭或目录页签切换而中断。Sheet 创建批次失败时保留待选文件并展示错误。
面板仅说明“系统自动安排上传账户”，不展示可编辑账户控件、不回填历史固定账户；实际账户分配完成后在队列和记录中显示。

### 10.3 UI-05B 独立上传队列与账户记录

上传队列可直接从 UI-05 页签进入，URL 保留当前页签和批次 ID，刷新后重新读取服务器进度。浏览器尚未完整传输的文件显示“需要继续上传原文件”；已经接收的文件由后台继续。
队列工具栏显示批次、全部/处理中/需处理/已完成筛选和“刷新状态”；有 `upload` 权限且存在可重试项时显示“重试明确失败项”。结果待核实不计入可重试集合。

| 队列表格列 | 展示内容 |
| --- | --- |
| 文件 | 原始文件名、大小 |
| 本地传输 | 已传字节/总字节与 Progress；没有传输进度时不伪造百分比 |
| 当前阶段 | 等待平台上传、上传 TikTok、核实素材、可用、权限阻塞、失败、结果待核实 |
| 实际上传账户 | 已确定的账户名称与 ID，只读；重新尝试使用不同账户时保留各次记录 |
| 处理信息 | 失败原因或下一步说明，不显示凭据和完整签名 URL |
| 操作 | 查看记录；明确可重试失败显示“重试”；结果未知显示“查看核实进度” |

“查看账户记录”打开独立详情 Sheet，分为“来源上传记录”和“账户资产”两段。前者按尝试显示实际账户、时间、阶段和结果；后者显示账户、VID、MID、可用状态及最近回查时间。远端标识按类型分开展示，可复制，不能编辑。
顶栏切换租户或 BC 后，现有上传继续绑定发起时的上下文，当前页面只展示新范围内的数据；不得将尚未完成的文件重新指定给新租户。

### 10.4 加载、异常与权限状态

| 状态 | 页面表现与可用操作 |
| --- | --- |
| 首次加载 | 表头和工具栏稳定，表体使用 Skeleton；上传按钮仅在权限和 BC 已确认后可用 |
| 当前页刷新 | 保留已有行并显示加载状态；返回结果前不清空文件名和失败信息 |
| 尚无素材 | Empty 显示“还没有上传素材”，有上传权限时提供“批量上传” |
| 筛选无结果 | 显示“没有符合条件的素材”及“清空筛选”，不误导用户重新上传已有文件 |
| 查询失败 | Alert 显示错误和“重新加载”，保留筛选条件，不把失败显示为零素材 |
| 无可上传账户 | 已接收文件保留，显示“当前 BC 暂无可上传账户”；账户信息只读，提示管理员处理授权 |
| 文件明确失败 | 行内显示具体原因；可重试时恢复该项缺失阶段，成功项保持不变 |
| 结果待核实 | 明确标记“上传结果待核实”，不显示普通重试按钮，不把它渲染成失败或可用 |
| 只读成员 | 可检索、预览和查看记录；隐藏上传入口和重试动作，服务端仍校验权限 |
| 会话失效（401） | 返回登录并保留合法内部返回地址；重新登录后重新校验权限、读取当前范围 |
| 权限失效（403） | 保持登录、隐藏无权写操作并展示原因；仍有读取权限时保留结果，没有读取权限则显示无权访问 |

组件使用 `Table`、`Tabs`、`Sheet`、`Alert`、`Empty`、`Badge`、`Progress`、`Skeleton` 与标准按钮。状态同时显示文字，不能只靠颜色；上传控件和复制按钮提供可访问名称，Sheet 关闭后焦点回到触发按钮。
