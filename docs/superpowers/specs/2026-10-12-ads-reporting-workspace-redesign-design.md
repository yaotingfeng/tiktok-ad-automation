# 广告报表工作台重设计

日期：2026-10-12
状态：待用户评审
关联：`2026-09-30-ads-management-reporting-design.md`（业务规则、批量操作规则继续有效）、`2026-10-12-ads-reporting-sync-redesign-design.md`（同步链路）、`docs/contracts/tiktok-basic-report-metrics/`（官方指标文档）

## 1. 目标与依据

广告报表页是投手和运营的主工作台，**盯盘、数据分析、查看详情、操作广告**都在这一页完成，不需要跳转到 TikTok 后台。

用户在评审现有页面时提出的问题：

- 横向滚动时固定列错位：勾选框不固定；固定的是账户列而不是当前对象。
- 打开页面默认是系列维度，应默认账户维度。
- "查看详情"和"TikTok 后台"没有实际作用。
- 指标名称是自创的（如"总收入""D3 ROAS"），应与 TikTok 官方一致。
- 缺少点击量、点击率、千次展示成本。
- 批量操作要经过"勾选 → 批量操作 → 选动作 → 填值"四步，应在勾选后直接于表头出现动作按钮。
- 详情应展示历史数据（趋势图与逐日数据）、命名、基本设置、目标出价、ROAS 等搭建参数。

线上测试环境核实到的问题（2026-10-12，只读查询）：

- 近 7 天 915 个系列每行都有消耗，但汇总卡片全部显示"—"：只要有一个账户日缺失，汇总就整体置空。
- 账户行返回其下全部系列引用（一页约 16KB）。
- 状态显示 `DISABLE`、`CAMPAIGN_STATUS_DISABLE` 等原始枚举，账户行没有状态。
- 详情接口已经返回完整配置（系列预算与 CBO、广告组 `roas_bid`/出价方式/优化事件/VBO 窗口/排期/版位/定向/归因窗口/Minis ID、广告文案与创意列表），前端没有渲染。
- 批量预览把状态值写死为 `DISABLE`，无法批量启用；调整方式写死为 `set`，无法增减或按百分比调整。

## 2. 指标命名规则

- 所有指标名称以 `docs/contracts/tiktok-basic-report-metrics/v1.3.zh.md` 的官方中文名为准，不自创名称。
- 表头省略"Native Growth"前缀；悬停说明和导出文件使用完整官方中文名，并附平台字段名。
- 天数按官方写法：平台字段 `dN` 显示为"第 N 天"（点击后 (N+1)×24 小时）。本地存储列 `revenue_d3/d7/d14/d30` 对应官方第 2/6/13/29 天，存储列名不改，只改展示。
- 素材维度使用素材报表的官方名称（广告曝光事件总数、广告曝光总价值、第 N 天广告收入），不套用基础报表名称。
- 后端维护唯一的**指标字典**：指标键 → 各维度平台字段 → 官方中英文名 → 单位（金额/次数/比率/倍数）→ 可加性 → 支持的维度。报表列、汇总卡片、导出、详情、趋势共用这份字典，前端不再硬编码标签。字典里的名称以抓取的官方文档为准，文档刷新时一起核对。

### 2.1 指标列

| 指标键 | 表头（基础报表维度） | 表头（素材维度） | 计算 |
| --- | --- | --- | --- |
| `spend` | 消耗 | 消耗 | 平台原值 |
| `revenue_total` | 广告展示总价值 | 广告曝光总价值 | 平台原值 |
| `roas_total` | 广告收益 ROAS | 广告收入 ROAS | 广告展示总价值 / 消耗 |
| `revenue_d0` | 第 0 天广告收益金额 | 第 0 天广告收入 | 平台原值 |
| `roas_d0` | 第 0 天广告收益 ROAS | 第 0 天广告收入 ROAS | 第 0 天金额 / 消耗 |
| `roas_d3` | 第 2 天广告收益 ROAS | 不提供，隐藏 | 第 2 天金额 / 消耗 |
| `roas_d7` | 第 6 天广告收益 ROAS | 第 6 天广告收入 ROAS | 同上 |
| `roas_d14` | 第 13 天广告收益 ROAS | 第 13 天广告收入 ROAS | 同上 |
| `roas_d30` | 第 29 天广告收益 ROAS | 不提供，隐藏 | 同上 |
| `impressions` | 展示量 | 展示量 | 平台原值 |
| `clicks` | 点击量（目标页面） | 点击量（目标页面） | 平台原值 |
| `ctr` | 点击率（目标页面） | 点击率（目标页面） | 点击量 / 展示量 |
| `cpm` | 千次展示成本 (CPM) | 千次展示成本 (CPM) | 消耗 / 展示量 × 1000 |
| `cpc` | 平均点击成本（目标页面） | 平均点击成本（目标页面） | 消耗 / 点击量 |
| `ad_impression_events` | 广告展示事件总数 | 广告曝光事件总数 | 平台原值 |

配置列（不属于报表事实）：系列维度显示"预算"，广告组维度显示"预算""目标 ROAS""优化目标"，广告维度显示"目标 ROAS""优化目标"（取所属广告组）。账户维度显示"余额"（时点值，不随日期求和）。

### 2.2 回收窗口未结束

第 N 天指标在窗口结束前会继续增长。所选日期的最后一天距今不足 N+1 天时，该列表头标灰，悬停说明为"回收窗口未结束，数值仍会增长"；数值照常显示，不隐藏。判断按各账户本地日。混合时区时，只要有一个账户的窗口未结束就标灰。

## 3. 页面结构

从上到下：

1. **顶栏**：标题"广告报表"、当前 BC、一行同步状态（沿用 `ReportStatusBar`）、"刷新""导出"按钮。
2. **筛选区**：日期快捷项（今日、昨日、近 7 天、近 30 天、自定义）、搜索框、状态筛选、"应用筛选""重置""保存筛选"。默认**今日**、**账户维度**；"重置"同样回到这两个默认值。
3. **汇总卡片**：消耗、广告展示总价值、广告收益 ROAS、第 0 天广告收益 ROAS、展示量、点击率（目标页面）、千次展示成本。点卡片会切换下方趋势图的指标，当前选中的卡片高亮。
4. **趋势图**：默认折叠，展开后才请求趋势接口，折叠状态保存在本地偏好。2026-10-05 曾为首屏性能移除页面趋势和快照内趋势预计算，因此趋势不进入查询快照，也不随列表一起加载。所选范围是单日时按小时显示（数据来自系列小时事实），多日时按日显示。混合时区时显示提示，不伪装成统一自然日（原设计第 6 节）。
5. **表格卡片**：维度页签（账户、系列、广告组、广告、素材、剧）→ 表头工具栏 → 表格 → 分页。

视觉沿用已审定的统一规范（`docs/superpowers/plans/2026-09-10-workspace-visual-rollout.md`）和 shadcn 组件。趋势图使用 shadcn chart（基于 recharts），本轮新增这一依赖。

## 4. 表格

### 4.1 固定列

- 勾选框列固定在 `left-0`，当前维度的名称列紧随其后固定。两列的背景都跟随行悬停和选中状态，名称列右侧加分隔阴影。表头同样固定。
- 只固定当前对象名称：账户维度固定账户，系列维度固定系列，以此类推。素材、剧维度固定各自名称。

### 4.2 名称单元格

- 第一行显示名称（最多两行，超出截断，悬停看全称），第二行用小字显示 ID。第三行显示上级路径：账户 › 系列 › 广告组，路径中的每一段都可以点击，点了就按该上级筛选。父级账户、系列不再单独占列。
- 点名称打开**详情面板**。名称右侧的"›"按钮进入下一级维度（账户 → 系列 → 广告组 → 广告 → 素材），沿用现有 `navigateToChild` 的筛选逻辑。
- 删除"查看详情""TikTok 后台""数据状态"三列。某行数据不完整时，在名称旁显示警示图标，悬停说明缺失的日期。

### 4.3 状态列

- 显示中文状态徽标，按 `operation_status`、`secondary_status`、`review_status` 合成一个主状态，可能的值有：投放中、已暂停、审核中、未通过、预算不足、不在排期、已删除。原始枚举放在悬停说明里。没有映射的枚举原样显示，不隐藏。
- 账户行显示账户状态，数据取自账户目录。

### 4.4 列设置与排序

- 表头工具栏在未选中任何行时显示"列设置"：可以显示或隐藏列、调整顺序，按维度保存在浏览器本地偏好（键含租户和用户 ID）。名称列和勾选框不能隐藏。
- "保存筛选"保存的视图同时记录当前可见列，列键改用指标字典的键。现状下前端提交的 `roas_d0` 不在 `SUPPORTED_VIEW_COLUMNS` 中，保存会被 422 拒绝；本期把允许列表改为由指标字典和显示字段生成。
- 默认排序为消耗降序。排序规则沿用现状：同一列再点切换方向，名称列默认升序，数值列默认降序。

## 5. 批量操作

### 5.1 表头工具栏

- 勾选任意一行后，表头工具栏替换为：**已选 N 条（或"全部 N 条匹配结果"）· 启用 · 暂停 · 修改目标 ROAS · 修改预算 · 选择全部匹配结果 · 取消选择**。
- 各维度显示的动作（依据原设计第 4 节表格）：

| 维度 | 启用/暂停 | 修改目标 ROAS | 修改预算 |
| --- | --- | --- | --- |
| 账户 | 展开系列 | 隐藏（需要展开到广告组，按原设计在预览中展开时再提供） | 展开预算拥有者 |
| 系列 | 是 | 展开广告组 | 是 |
| 广告组 | 是 | 是 | 是 |
| 广告 | 是 | 展开广告组 | 隐藏 |
| 素材 | 支持独立启停的引用 | 隐藏 | 隐藏 |
| 剧 | 展开系列 | 隐藏 | 展开预算拥有者 |

  这里"隐藏"指本期不在工具栏提供该按钮，预览接口的能力不变。
- 只读角色不显示工具栏中的动作按钮。
- 删除底部浮动的 `BulkActionBar`。

### 5.2 预览面板

- 点动作按钮后冻结选择（`freezeAdSelection`），打开 `ManagementPreviewSheet`，动作已预选好，面板里不再出现"操作维度"下拉框。
- 启用和暂停直接生成预览。修改目标 ROAS 或预算时，先填调整方式（设为 / 增加 / 减少 / 增加百分比 / 减少百分比）和数值，再生成预览。
- 预览内容沿用现状：影响计数、父级联动、排除不可用项、原值与新值列表、5 分钟有效期、提交后跳转任务详情。
- **修复缺陷**：状态值按所选动作传 `ENABLE` 或 `DISABLE`；调整方式按所选值传给 `MutationSpec.mode`。后端 `MutationMode` 已支持 `set/add/subtract/increase_percent/decrease_percent`，前端与之一一对应。删除默认值 `25`，数值留空就不生成预览。
- 预览列表中的对象显示名称，而不是"kind · remote_id"。

### 5.3 单对象操作

详情面板顶部提供同样的"启用/暂停/修改目标 ROAS/修改预算"按钮，对当前对象发起同一个冻结选择加预览流程，不另写一条操作路径。

## 6. 详情面板

右侧宽抽屉（桌面端约占视口宽度的 60%，最小 720px），打开时保留表格上下文。页头显示名称、类型、主状态、单对象操作按钮，下面分页签：

| 页签 | 内容 |
| --- | --- |
| 概览 | 名称、ID、层级路径（可点击切换到上级详情）、命名解析（版权方、剧名、备注、规范状态；不规范时提示原因）、操作/审核/投放状态及父级限制原因、所选日期的核心指标卡片 |
| 趋势 | 指标切换折线图（消耗、广告展示总价值、广告收益 ROAS、第 0 天广告收益 ROAS、展示量、点击率）和逐日明细表（全部 2.1 节指标列）。区间可选近 7 / 14 / 30 天或跟随页面筛选，默认近 14 天。单日区间且对象是系列及以上时，可以切换为按小时 |
| 设置 | 按对象类型分组展示同步到的配置，见 6.1 |
| 素材 | 广告：素材使用位置列表（名称、类型、状态、是否本地素材）。广告组和系列：该范围内的素材汇总数 |
| 操作记录 | 本工具对该对象执行过的管理任务：时间、动作、原值→新值、结果，可跳转到任务详情。数据来源改为 `ManagementTaskItem`（按 `ref` 的账户和对象 ID 匹配，动作取自所属预览的 `mutation`）；现有实现读 `AuditEvent`，而管理任务不写这张表，因此一直为空 |

账户和剧没有目录配置。账户详情显示账户状态、余额、币种和时区；剧详情显示版权方、剧名和关联系列列表（来自剧行的 `refs`）。这两类对象的详情直接使用报表行数据和趋势接口，不调用对象详情接口，也没有"设置"页签。

### 6.1 设置页签字段

字段从 `AdDetailPublic.configuration`（TikTok 原始对象）中读取，前端维护"字段 → 中文标签 → 值格式化"的映射：

- **系列**：推广目标（`objective_type`）、推广类型（`app_promotion_type`）、系列类型、预算（`budget`）与预算模式（`budget_mode`）、系列预算优化（`budget_optimize_on`）、Smart+ 广告组模式、创建时间、修改时间。
- **广告组**：推广类型、Minis ID、优化目标（`optimization_goal`）、优化事件（`optimization_event`）、出价方式（`bid_type`）、深度出价方式（`deep_bid_type`）、目标 ROAS（`roas_bid`）、转化出价（`conversion_bid_price`）、价值优化窗口（`vbo_window`）、预算与预算模式、最低预算、排期类型及起止时间、分时投放（`dayparting`）、版位类型与版位、定向（地区、年龄、性别、语言、Smart+ 受众年龄等 `targeting_spec` 子项）、归因（点击/浏览/专注观看归因窗口、事件计数方式）、评论/分享/下载开关、创建时间、修改时间。
- **广告**：文案（`ad_text_list`）、落地页（`landing_page_url_list`）、创意列表（`creative_list` 的素材名称和类型）、广告配置（`ad_configuration` 中的身份、CTA 等）、创建时间、修改时间。

规则：

- 枚举值翻译成中文，没有映射的原样显示；地区 ID 显示为 ID 列表，本期不做地区名解析。
- 映射表之外的字段放在"其他字段"折叠区，用平台字段名原样展示，不丢弃。
- 显示配置的"观测时间"，说明这是最近一次目录同步的结果，不是实时读取。

## 7. 后端改动

### 7.1 指标字典

新增 `modules/reporting/metric_catalog.py`，定义 2.1 节所有指标的平台字段、官方中英文名、单位、可加性和适用维度。`metrics.py` 的字段映射由它生成，不重复维护。新增只读接口 `GET /tenants/{tenant_id}/ads/metric-catalog`，前端据此生成表头、汇总、详情和趋势的名称。导出 CSV 的列名也取自字典的官方中文名。

### 7.2 派生指标

`dimension_query.metric_vector` 增加 `cpm`（消耗/展示量×1000）、`cpc`（消耗/点击量）。排序字段 `SUPPORTED_SORT_FIELDS` 同步加入这两项。

### 7.3 汇总口径

现状：`aggregate_metrics` 只要有一个成员缺值，合计就为空。改为：

- **成员缺值的处理**。某账户日的同步状态为完成、但没有事实行时，按真实 0 参与合计，现有 `empty_metric_values` 已按此产出 0。同步状态为未完成或失败时，该成员不参与合计。
- **合计结果的标注**。合计值标记 `availability=PARTIAL`，同时返回 `excluded_advertiser_count` 和 `excluded_dates`。
- **页面展示**。汇总卡片显示已合计的数值，并附"N 个账户数据不完整"的提示，悬停可看明细。
- **UNSUPPORTED 指标**。所有成员都不支持时显示"平台未提供"；只有部分成员不支持时，与缺值同样处理。
- **适用范围**。行内跨日聚合（同一对象多天）采用同一规则，该行带不完整标记。

这条规则改变了"缺失不能被零覆盖"的显示方式，但仍然满足原则：缺失成员没有被当成 0，只是不阻止其余成员合计，并且明确标注。

### 7.4 账户维度口径

核实结果：账户行指标已经由系列日事实（`CampaignReportDay`）聚合，分天收益、展示、点击都有；线上看到的 0 是当天真实的零消耗。账户层报表（`AccountReconciliationDay`）只用于对账差异提示。本期不改口径，只补一条回归测试：账户行各指标等于其下系列合计。

### 7.5 账户行响应裁剪

冻结选择（`reporting/selection.py`）在服务端从查询快照行读取 `refs`，用来展开账户下级系列，不依赖前端传入的值。因此快照内保留完整 `refs`，只在列表接口序列化时把账户行的 `refs` 裁剪成账户自身；其他维度行的 `refs` 本来就只有自身，不受影响。需要补测试：账户行 `refs` 裁剪后，冻结选择仍能展开全部下级系列。

### 7.6 趋势接口

新增 `GET /tenants/{tenant_id}/ads/trend`，用一个接口同时支撑页面趋势和详情趋势：

- 参数：`bc_id`、`level`（account / campaign / adgroup / ad / material）、`advertiser_ids`（逗号分隔，可空，表示当前 BC 全部授权账户）、`ids`（逗号分隔的对象 ID，可空，最多 200 个）、`start_date`、`end_date`、`granularity=day|hour`。
- 用法：页面趋势传 `level=account` 和当前账户筛选；系列、广告组、广告、素材详情传自身 ID；剧详情传 `level=campaign` 和剧下全部系列 ID；账户详情传 `level=account` 和该账户。
- 返回：按时间点排列的指标向量（2.1 节指标，按币种分桶），每个点带覆盖状态。
- 数据来源全部是本地：account、campaign 用系列日事实；adgroup、ad 用广告日事实；material 用素材日事实；小时粒度用系列小时事实，只支持 account、campaign，区间不超过最近 30 天。
- 区间上限：日粒度 90 天，小时粒度 2 天，超出返回 422。
- 范围：账户必须属于该 BC 的授权账户，不在范围内的账户返回 403，不暴露数据。

### 7.6.1 2026-10-13 修订：快照只冻结成员，筛选排序在数据库内完成

背景：原实现把全部行搬进应用逐行计算、筛选、排序，再把每行完整内容（约 2KB JSONB）写入快照。生产素材维度 3.4 万行、单次约 17 秒，已接近快照事务 30 秒上限；账户数增长后无法扩展。用户选定方案：快照机制保留，改为数据库内一次完成。

- 快照创建：`row_set.insert_snapshot_rows` 用一条 SQL 算出身份（有事实对象 ∪ 目录对象）、目录筛选、关键词/ID 筛选、指标区间、排序与稳定序号，直接写入精简快照行，并在同一语句返回汇总。快照行只存 `row_key`、顺序、`refs`、`material_uses`；`display`、指标、覆盖为空。
- 读取：列表翻页、导出生成只对用到的行调用 `dimension_query.materialize_rows` 补全展示、指标与覆盖，读取量与页大小（导出按 500 行一批）成正比。
- 冻结口径：成员、顺序、总数、汇总卡片、跨页选择的管理对象在快照内冻结；行内展示与指标按读取时的数据补全。快照有效期内同步到新数据时，页面可能显示较新的数值或名称，但不会增减或重排行；"查看最新数据"提示仍以 `publication_versions` 为准。导出创建时冻结成员，后台生成时补全内容。
- 口径保持不变：无事实对象完整覆盖填 0、否则为空；同币种分桶；金额排序先比较币种；多币种与无值行排末尾；并列按 `row_key` 升序；汇总部分合计规则同 7.3。
- 关键词搜索按页面约定匹配名称、剧名、版权方与各级 ID（多关键词 AND）；不再匹配状态、预算等其他展示文本。

## 9. 错误与边界

- 趋势或详情读取失败时，只在面板内显示错误和"重试"，不影响表格。
- 对象已被删除或不在当前 BC 时，详情显示"对象不在当前 BC 范围或已删除"。
- 混合币种时，汇总、表格、趋势都按币种分别展示，不换汇（沿用原设计）。
- 切换 BC、维度或筛选条件时，清空选择并关闭预览（沿用现状）；详情面板在切换 BC 时关闭。
