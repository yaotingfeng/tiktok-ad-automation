# TikTok 自动投放工具：前端页面与交互设计

日期：2026-09-08；前端补充检查：2026-09-09  
状态：2026-09-09 用户确认当前视觉设计与三步搭建主流程，作为前端实施基线。详细页面与状态按本文及功能设计实现，在各阶段演示中核对；已确认的业务规则保持有效。  
关联：[整体设计](2026-09-08-tiktok-00-overall-design.md)、[交付计划](../plans/2026-09-08-tiktok-00-delivery-roadmap.md)、[可点击原型](../prototypes/2026-09-08-tiktok-workbench.html)。

## 1. 页面方案与范围

采用左侧导航、顶部租户与 BC 上下文、右侧工作区。广告搭建使用三个连续阶段：批量输入 → 准备与调整 → 搭建预览；提交后进入独立任务详情。选择这套布局，是因为批量输入、纠错和结果复查各有明确目的，同时返回上一步不会丢失草稿。

单页把全部输入、素材、账户组合和执行结果堆叠在一起，长批次时定位问题困难；传统多层表单向导又容易把剧目和账户变为逐项选择。因此保留三段式工作台，准备结果和预览内部用表格、筛选与侧栏展开。

默认落在广告搭建，已有未提交草稿时显示“继续草稿 / 新建搭建”。不新增经营看板、ROI、消耗数据或自动调价页面。管理页面与投放页面采用同一套布局；平台管理员从平台入口进入租户后，复用租户工作台。

## 2. 页面清单、路由与导航

页面 ID 是设计和验收的稳定标识，`:id` 为应用路由参数。列表 BC 过滤用 `bc_id` 查询参数；详情以记录自身 BC 为准，不随全局选择改写。

| ID | 页面 / 主区域 | 建议路由 | 主要去向 |
| --- | --- | --- | --- |
| UI-01 | 登录 | `/login` | 租户工作台或平台租户列表 |
| UI-02 | 平台租户列表、创建/编辑侧栏 | `/platform/tenants` | 进入租户 UI-03 |
| UI-03 | 广告搭建：输入、准备与调整 | `/tenants/:tenantId/builds/new`、`/tenants/:tenantId/build-drafts/:draftId` | UI-11、UI-05、UI-07 |
| UI-04 | 搭建任务 | `/tenants/:tenantId/build-tasks` | UI-12 |
| UI-05 | 素材库、上传队列 | `/tenants/:tenantId/materials` | 上传侧栏、素材详情 |
| UI-06 | 投放策略列表 | `/tenants/:tenantId/strategies` | UI-07 |
| UI-07 | 新建/编辑策略版本 | `/tenants/:tenantId/strategies/new`、`/tenants/:tenantId/strategies/:strategyId` | UI-06、返回草稿 |
| UI-08 | 账户与授权：账户 / 授权连接 | `/tenants/:tenantId/accounts?tab=accounts` | 账户详情、授权回调结果 |
| UI-09 | 版权方连接：连接 / 链接记录 | `/tenants/:tenantId/providers?tab=connections` | 连接侧栏、剧目准备问题 |
| UI-10 | 成员管理 | `/tenants/:tenantId/members` | 成员侧栏 |
| UI-11 | 搭建预览 | `/tenants/:tenantId/build-previews/:previewId` | 返回 UI-03 或提交至 UI-12 |
| UI-12 | 任务详情 | `/tenants/:tenantId/build-tasks/:submissionId` | 回查、重试、查看原始预览 |

左导航按两组排列：**投放工作**（广告搭建、搭建任务、素材库、投放策略）；**租户管理**（账户与授权、版权方连接、成员管理）。平台管理员额外在底部看到“平台管理”，不混入租户业务菜单。viewer 隐藏新建/编辑/提交入口，仍可读取有权限的页面；operator 可维护业务资源，不管理成员和授权凭据。精确角色范围遵循[租户设计](2026-09-08-tiktok-01-tenants-accounts-design.md)。

顶栏常驻租户全名、BC 全名和当前用户。平台进入租户时显示“平台管理员 · 当前代管：租户名”，并提供返回平台入口。所有详情页显示记录所属 BC。切换时取消旧请求、隔离查询缓存；草稿保存在原租户/BC，切换不迁移草稿。未保存广告草稿提供保存并切换或留在当前页；管理表单/凭据 Sheet 提供留在当前页或丢弃未保存修改，切换本身不能触发凭据保存；不能通过切换沿用别的租户素材或账户。无 BC 时，显示有权限的接入引导，创建入口禁用并说明原因。

## 3. 统一视觉与组件

桌面以 1440×900 为设计画布，1280 宽正常工作。侧栏 208～224px，顶栏 56px，内容内边距 24～32px；阅读区域最大 1440px，数据表占满可用宽度。1024px 以下收起侧栏，表单单列；宽表自身横向滚动，整页不横向溢出。窄屏可阅读和纠错，不另造手机端复杂批量工作流。

浅色为首版默认：白色内容区、浅灰背景、深灰正文、蓝色主操作；状态同时有文字与图标，不能仅靠红绿。页面标题 24px，区块标题 16px，正文/表格 14px，说明 12～13px。控件高度 36px，普通表格行 48px，复杂行可 64px；统一 4/8/12/16/24/32px 间距，圆角 8px。数字右对齐，ID 等宽、可复制，长名称截断后可展开全文。

正式应用使用 shadcn 的语义主题 token 与已有组件，保持模板组件基座一致，不因当前文档默认版本变化切换底层库。工作台采用 Sidebar；数据表组合 Table 与 TanStack Table 的服务端分页、过滤、排序；局部编辑采用 Sheet；独立策略编辑为完整页面。依据官方的 [Sidebar](https://ui.shadcn.com/docs/components/sidebar)、[Data Table](https://ui.shadcn.com/docs/components/data-table)、[Sheet](https://ui.shadcn.com/docs/components/sheet)、[Field](https://ui.shadcn.com/docs/components/field) 文档，组件仅作为组合基础，业务交互由本稿规定。

表单使用 FieldGroup/Field/FieldDescription/FieldError，输入有 label；错误关联到字段并设置 aria-invalid。Sheet/Dialog 具有标题，打开后聚焦标题或首个字段，Esc 关闭并还原触发按钮焦点；存在未保存修改时明确保存或放弃。主操作每个阶段只保留一个，次要操作用 outline/ghost。Toast 用于保存/复制等短反馈，持续异常放在页面 Alert 或对应行内。

## 4. UI-03：批量输入

```text
广告搭建                                  已保存 / 保存草稿
① 批量输入 ───────── ② 准备与调整 ───────── ③ 搭建预览
版权方连接       应用              策略及版本
┌ 剧目名称（每行一部）──────┐ ┌ 广告账户（每行一个）─────┐
│ 多行粘贴文本              │ │ 完整 ID 或完整账户名称   │
└ 行数 / 去重说明 ─────────┘ └ 行数 / 去重说明 ─────────┘
本批全部剧目将覆盖同一批全部有效账户
策略摘要：币种 / 单 Campaign 日预算 / 目标 ROAS / 分组 / SP
                                  [保存草稿] [解析并准备]
```

版权方连接、应用和策略可选择，剧目/账户始终批量粘贴。输入行即时计数只作提示，不在浏览器内伪造可用性。点击“解析并准备”后保存输入、启动版权方准备并进入第二阶段。按钮下短说明“解析剧目与账户，复用或获取推广链接”；这是链接准备操作，尚未创建广告。准备期间可离开并由草稿恢复；请求失败保留文本和选项。

缺少选项时在对应字段提示，连接缺失时按 manage 权限向 tenant_admin 和 platform_admin 显示管理入口，其余角色显示联系管理员；策略缺失时按 strategy_write 权限向可写角色显示新建策略入口。空行移除、重复行报告；原始行号保留。输入错误不清空整批，也不要求把有效行重新粘贴一次。

## 5. UI-03：准备与调整

顶部显示解析摘要：有效剧目、有效账户、重复输入、待处理输入行；其下 Tabs 为“剧目与素材 / 账户解析 / 输入问题”。Tabs 的数量来自完整后台统计，不取当前页行数。

剧目表列：输入行、确认剧名、版权方链接状态、素材数量、分组数量、准备状态、查看链接/调整素材。账户表列：输入行、原始文本、解析名称与 ID、币种、授权状态、结果/原因。名称歧义只在该输入行展开候选并要求明确对象，不替换主批量输入；失败行可以改写或从草稿移除。重复行显示合并目标。修正并重新准备保留其余已完成结果。

**素材调整侧栏**：标题为“调整素材 · 剧名”，固定说明“应用于本批这部剧的全部目标账户”；不提供每账户不同素材的配置。上部显示匹配规则、已用数量、组大小。左侧为本租户素材搜索/分页结果，右侧为当前使用素材及组；支持补入、移除和组间移动。主键盘路径用“移至组”菜单与上移/下移按钮，不把拖拽作为唯一方式。缩略图有播放/文件名详情，真实源账户只读。

默认文件名升序、素材 ID 稳定并列排序，按策略分组，尾组保留。多剧命中只显示信息提示。移除使组变空则去掉空组并重算组号，不留下空 Ad Group。新增匹配素材不会自动改变当前草稿；运营显式重新匹配或添加。保存修改增加草稿 revision，并使旧预览过期；取消侧栏恢复打开前内容。

生成预览可在有有效输入时执行；未就绪单元在预览明确排除，生成中展示已处理/总组合及可离开说明。全阻断允许查看问题但不可提交。素材只待合法分发时显示“提交后分发”，可提交；没有链接、必要权限或合法素材路径时显示“无法搭建”。

## 6. UI-11：搭建预览

```text
搭建预览                         版本 v3 · 已生成       返回调整
租户 / BC / 版权方 / 应用 / 策略版本 / 生成时间
有效剧目 2    输入账户 3    本次 Campaign 6 / Ad Group 12 / Ad 24
[剧目汇总] [账户组合] [排除项 0]                 搜索剧目/账户
剧名       素材 / 组     提交户 / 总户     Campaign / 组 / Ad     查看明细
  展开：组1 → 素材集合 → SP1 文案+CTA / SP2 文案+CTA
  账户明细：完整名称 / 账户ID / 准备状态 / 名称 / 预算 / 链接与资产
固定底栏：本次6 Campaign · 12 Ad Group · 24 Ad    日预算合计 USD 600
                           排除0组合         [创建并立即启用]
```

默认剧目汇总，按需打开一部剧的分组与冻结创意。账户组合为服务端分页表，不渲染所有剧目×账户的整张矩阵。列为剧目、账户名/ID、状态、组/Ad 数、Campaign 日预算、查看详情；详情展开真实推广链接、Minis/Identity、三层完整名称、目标素材准备路径、文案/CTA。可复制链接与名称，资产 ID 仅在详情显示。

固定底栏展示**实际提交**的三级数量、排除组合数、日预算合计和币种；预算文字说明“各 Campaign 配置日预算之和，非预计实际消耗”。仅展示完整统计后的冻结预览总数，不能用已加载页估算。按钮文案“创建并立即启用”，紧邻三级数量；按钮可访问名称包含数量，不能只用图标。

排除项分为无法解析的输入行与已形成但阻断的组合，两者分别计数，避免将一行账户解析失败伪称已产生若干 Campaign。组合排除表显示剧目、账户、原因、影响数量及“返回修正”目标。部分可用时无需再逐项勾选，可一次提交当前显示范围；零可用时禁用按钮并定位阻断原因。排除项修复后另建剩余组合的预览，已成功提交组合不会自动重复补建。

提交前在按钮区域持续说明“将直接创建并启用，审核与实际投放状态由 TikTok 决定”；不弹第二次激活确认。点击后防连点并沿用同一请求标识。网络返回不明显示“正在确认提交结果”，保持原预览范围和幂等键，不显示可再次整批创建的按钮。已确认受理后跳 UI-12。准备/提交状态通过页内 live region 朗读。

## 7. 统一状态与恢复

| 状态ID | 触发 | 页面反馈与可操作恢复 |
| --- | --- | --- |
| S01 初始空白 | 尚无素材/策略/连接/任务 | Empty 说明原因；按角色提供单一下一步入口；搜索无结果提供清除过滤 |
| S02 加载/后台处理中 | 首屏、翻页、准备、生成预览 | Skeleton 保持结构；后台任务显示阶段/完成数，可离开恢复；禁用重复动作 |
| S03 输入失败 | 空值、歧义、越界、链接冲突 | 保留原始行号和文本，行内原因+修复入口，有效行保留 |
| S04 部分阻断 | 币种不符、账户权限/素材路径缺失 | 实际范围摘要+排除项列表，READY/PREPARING 可提交；全部阻断则禁用 |
| S05 旧预览/版本冲突 | 编辑草稿、409 | 显示“草稿已更新，请重新生成预览”；保留本地未保存文本，先对比最新版本再应用，绝不静默覆盖 |
| S06 网络失败/结果未知 | 读取失败、提交响应不明、外部写入未知 | 读取可重试；提交用同一键查受理状态；执行未知在 UI-12 先回查，成功项保持 |
| S07 权限/上下文变更 | 403、租户/连接停用 | 页面内无权限提示，401 才回登录；暂停未执行步骤说明原因，外部成功项保持原状 |
| S08 完成/部分失败 | 后台核查结束 | 三级成功/失败/未知计数、可定位对象；只有已确认失败步骤可重试 |

## 8. 大量账户与页面性能

表格默认每页 50，允许 100；它们是显示分页大小，不限制接入账户数或业务批次数。cursor 用上一页栈/下一页导航，不假装支持后端尚未提供的任意跳页。关键词、状态过滤与排序在服务端执行；筛选变化重置 cursor。搜索时保留输入与已有结果，显示更新状态。

批量输入以原文粘贴，解析/预览分块推进。摘要由后台汇总，浏览器不生成全部组合。展开只读取当前剧目/账户/组明细，折叠后可保留当前页缓存。任务列表进入详情返回时保留筛选与位置。金额以十进制字符串传输，账户/业务 ID 以字符串处理；不因格式化损失精度。

## 10. 原型阅读与覆盖

[可点击原型](../prototypes/2026-09-08-tiktok-workbench.html) 是自包含 HTML 的设计演示，用示例租户、账户 A/B/C、两部示例剧，不读真实资源、不发送广告请求。视觉遵循本稿，正式应用才使用 React/shadcn 组件和真实接口。页面顶部的场景切换属于原型控制栏，不进入产品。

重点可操作：UI-03/11 输入→准备→素材增减→预览；UI-05 素材搜索与本地文件队列模拟；UI-06/07 策略配置示例；UI-04/12 模拟创建、失败重试、未知回查。账户/版权方/成员/平台页用于审阅布局与信息层次，真实授权、成员写入和大量服务端分页由计划实现后验收。

评审首先关注三阶段是否顺手、剧目汇总与账户明细是否清楚、素材侧栏编辑范围是否易懂；业务确认记录不因原型里的示例数字改变。

## 11. 页面确认与实施衔接

2026-09-09，用户回复“可以，这个视觉设计非常好”，确认原型视觉及此前询问的三步布局。正式前端沿用原型的导航、信息层次、配色、表格与侧栏体验，使用 React/shadcn 组件实现；HTML 原型继续作为对照，不作为正式业务页面源码或外部调用实现。

实现按交付总计划推进，每阶段同时完成页面、接口、必要业务逻辑与验收；不再安排一次重复的整体视觉审批。具体管理页与异常交互在阶段演示中核对，有需求变化再更新对应功能设计。当前确认不代表软件已经实现或真实接口已联调。
