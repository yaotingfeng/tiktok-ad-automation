# MCP 一次授权接入多个 BC

用户已在对话中批准“一次授权、拉取可见 BC、选择接入、分别同步、日常切换”并要求实施。本设计替代 2026-09-11 双通道设计中的 MCP 单 BC 限制，其他权限和业务约束继续适用。

## 授权与归属

- TikTokConnection 继续保存同租户同通道的一份授权及加密凭据，保留既有 ID；BCConnectionBinding 是该授权下的独立 BC 接入。只解除 MCP 单 BC 唯一限制，不复制令牌，不把不同登录主体或租户的授权合并。API 凭据及原有发现流程保持独立。
- OAuth 回调先产生候选。完整 tools/list、可见 BC 目录、真实 user_info 主体和 token scope 核对后，用户提交选中的 BC 集合，事务内只发布一次共享授权，再启动独立 BC 发现任务。
- 重新授权使旧授权版本失效；旧 BC 访问证据关闭，新授权仍可见的原绑定重新同步，不可见的原绑定停用。追加或例行同步 BC 不增加共享授权版本；正常 token 轮换由现有连接级锁统一处理。
- 每 BC 绑定有 SYNCING/ACTIVE/ERROR/DISABLED 状态、对应授权版本及绑定代数。解绑提高该 BC 代数并关闭其访问、默认路由和未完成发现；重新接入不能复活解绑前冻结的任务。其他 BC 不受影响。普通同步不改绑定代数。

## 目录和任务

- 新 MCP DiscoveryRun 固定 connection_id、bc_id、authorization_revision、binding_revision；不再消费 OAuth 候选。每 BC 允许一个活动任务，失败独立保留证据并支持重试。
- 工作进程通过管理用途的账户只读工厂取得当前共享凭据；每次发送核对管理员、连接、授权版本与对应任务/绑定代数。管理工厂不开放素材或广告写工具。
- 每 BC 仍核对 SUBJECT/AUTHORIZED/BCS/ASSETS/DETAILS/ROLES 六阶段。完整发布只影响目标 BC 的账户、绑定、默认路由；不得按整条 connection 清除其他 BC 账户。
- 当前授权的可见 BC 目录缓存最多五分钟，并绑定授权及工具合同版本。主动刷新重新读取完整目录；追加接入须核对同版本快照，不能凭前端传入的 BC ID 扩权。最多一次选择 1000 个 BC，外部分页保持 50。
- 日常顶栏 BC 切换仍是单一工作范围；已有任务保存完整原路由。绑定代数加入冻结路由，历史默认值为 0，原有任务不改连接 ID。

## 页面与接口

- 只有一个未接入 BC 时自动选中，仍显示名称并提交；多个支持跨页多选及全选。全选必须覆盖完整候选目录。
- 候选绑定 body 改为 `{bc_ids: string[]}`；返回 `{connection_id, items: [{bc_id, discovery_run_id, status}]}`。废除旧单值请求。
- 当前连接提供 available-bcs、bindings、bcs/{bc_id}/sync 和 bcs/{bc_id} DELETE 操作；读取和追加沿用当前授权，不创建伪 OAuth 候选。
- ConnectionPublic 增 pending_binding_count；连接详情按 BC 展示同步状态/错误/时间，并提供同步、解绑和既有默认通道操作。无当前连接过滤的“默认”只表示用于至少一个 BC，不宣称全局默认。
- 普通操作员不能管理授权或绑定；租户之间严格隔离。停用整份授权明确影响全部关联 BC，单 BC 解绑不调用远端 revoke。

## 迁移、验证和发布

- 新增 Alembic 迁移；回填旧绑定授权版本、默认 ACTIVE/代数 0，保留连接/账户/历史证据。升级时未完成的旧候选发现标为 ERROR，旧消息不能继续发布，用户可从未失效候选或已有授权重新接入。
- 真实 PostgreSQL/Redis 验证多 BC 并发、部分失败、幂等、共享刷新、解绑迟到结果、重新授权和跨租户拒绝；HTTP 替身只放传输边界。前端验证自动选中、多选/全选、追加不 OAuth、独立进度及解绑。
- 验证并推送固定版本后按测试部署手册完整备份和恢复验证，再迁移/发布。单 BC 实际站点回归不能冒充真实多 BC 账号验收。素材上传和广告能力继续单独验收。
