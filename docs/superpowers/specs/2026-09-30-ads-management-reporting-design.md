# 广告管理与报表一体化设计

日期：2026-09-30。状态：书面设计已获用户确认；分阶段实施计划已编写，待审阅和选择执行方式，尚未实现产品。

## 1. 目标与已确认边界

让投手在同一个工作台完成“查看效果 → 搜索筛选 → 批量调整 → 跟踪结果”。广告目录以所选 BC 下已授权账户的真实广告为基础，同时覆盖 TK-ADA 搭建、TikTok 后台搭建及其他工具搭建的广告。

用户明确提出或确认：

- 账户、广告系列、广告组、广告、素材、剧六个维度共用报表和批量操作。
- 必需操作是批量修改目标 ROAS、批量启动和暂停；支持系列、广告组、广告及可操作的广告内素材，剧维度展开关联对象操作。
- 同时建设 MCP 与官方 API 接入；当前通过 MCP 使用，API 尚无可用授权，底层业务不能绑定 MCP。
- 广告完整详情每 3 小时同步，核心报表每 30 分钟主动拉取；未来推送接入复用业务和存储。
- 系列名统一按 `版权方-剧名-其他备注` 识别，剧名在第二段。所有广告使用同一规则，不要求剧 ID、版权方登录或本工具搭建记录。
- 当前 BC 内按“版权方＋剧名”归组，系列下级继承此归属。
- 不区分原剧名和改名后的剧名，不建立人工剧关联流程或独立业务剧目录。
- 本模块不包含分成、返点、赠款、赔付及经营净收益指标。

本稿补充的产品默认值包括批量即时预算、初始历史范围、名称变化后的历史归组、刷新优先级和任务状态语义，已随书面设计确认。真实广告操作仍需产品内具体预览和提交，真实联调需明确 BC 与操作范围。

## 2. 架构选择与已有基础

采用“后台定时同步＋PostgreSQL 存储＋统一查询服务”。页面搜索、分页、筛选、统计和切换维度均查询本地数据；手动刷新创建后台同步任务，不让浏览器直接调用 TikTok。

相比打开页面时直接查询 TikTok，此方案能够完整处理跨账户排序、剧汇总、全部匹配结果选择和历史回补。相比独立数据仓库，本期可复用现有 PostgreSQL、Redis、Celery 和事务 Outbox，减少运维依赖。

已有代码可复用：

| 能力 | 现有位置 | 本次扩展边界 |
| --- | --- | --- |
| 双通道会话与逐操作门禁 | `backend/app/integrations/tiktok/gateway.py` | 增加广告管理、报表合同与适配器，不能由 build 权限推断管理权限 |
| 冻结租户、BC、连接及绑定代数 | `integrations/tiktok/contracts/context.py`、`modules/accounts/routing.py` | 同步和管理任务使用原冻结路由，不随默认连接切换 |
| 账户、币种、时区及访问关系 | `modules/accounts/models.py` | 用于同步范围、日期和金额口径 |
| 完整分页后发布目录 | `modules/accounts/discovery_models.py` | 复用暂存后发布模式，新增广告目录专用模型 |
| Celery、Beat、Outbox、额度准入 | `jobs/`、`integrations/tiktok/admission.py` | 新增同步与管理队列，沿用共享额度域 |
| 素材及实际上传账户映射 | `modules/materials/models.py` | 素材投放关联来自真实广告引用，不来自上传记录本身 |
| 表格、BC 选择与多关键词搜索 | `frontend/src/features/accounts/`、`features/tenants/shared.tsx` | 沿用 shadcn 和既有统一视觉、服务端分页 |

现有搭建读取依赖创建意图，用于恢复和确认创建结果，不能当作全账户广告目录。新模块不伪造创建意图、不把管理操作塞入创建步骤表。

旧总体设计中“报表和投后优化后置”的范围，在本设计获得书面批准后由本稿扩展；既有创建流程、素材上传和版权方取链流程保持各自职责。

## 3. 工作台与查询体验

新增“广告管理”和“管理任务”入口，保留现有搭建任务入口。广告管理顶部共用当前租户/BC、账户选择、日期范围、搜索条件、数据更新时间和刷新入口。

页面结构为：汇总指标与可折叠趋势 → 六维页签 → 同一白色卡片内的筛选、表格、分页和批量工具栏。详情使用侧栏，展示配置、趋势、上下级、素材使用位置、关联系列及操作历史。遵循当前黑色主按钮、shadcn 组件及表内横向滚动规范。

| 维度 | 行身份与展示 | 可用批量操作 |
| --- | --- | --- |
| 账户 | 实际广告账户；余额、账户异常和效果 | 展开系列启停、展开适用广告组改 ROAS、展开预算拥有者改预算 |
| 广告系列 | TikTok 系列 ID；名称、剧、状态和预算 | 启停；改适用系列预算；展开广告组改 ROAS |
| 广告组 | TikTok 广告组 ID；目标、出价、预算和状态 | 启停；改适用目标 ROAS、预算 |
| 广告 | 普通广告或 Smart+ 广告资产集合 | 启停；从所选广告展开广告组改 ROAS时显示扩大范围 |
| 素材 | 远端素材及其广告内使用位置 | 对支持独立素材启停的关联执行启停；调 ROAS须展开广告组并显示联动 |
| 剧 | 当前 BC 内版权方＋剧名 | 展开对应系列启停；展开组调 ROAS或预算拥有者改预算 |

不同维度可以发起批量操作，但最终修改对象取决于平台能力；素材和剧本身没有 ROAS 字段。汇总行的目标 ROAS、预算模式若有多个值，显示范围或“多个”，不计算没有业务含义的平均目标出价。

搜索支持系列/组/广告名称、剧名、版权方、素材名称及对应 ID，多关键词按现有 AND 规则匹配，支持粘贴多个同类 ID。剧搜索来源于系列名第二段，不增加原名、改名名或别名搜索。

筛选包含账户、广告类型、状态、审核状态、预算模式、目标 ROAS、消耗、实际 ROAS、创建时间、命名是否规范。日期支持今日、昨日、近 7 天、近 30 天和自定义，默认今日。

列表、总数、汇总、趋势、导出及“全部匹配结果”共用一个服务端筛选合同。结果排序有稳定 ID 作为并列值排序依据，翻页不能漏行或重复。用户筛选当前状态时，汇总明确显示这是筛选后的对象集合；默认效果统计包含暂停和删除对象。

支持保存个人筛选/列配置、CSV 导出、平台后台跳转、当前范围刷新。大导出异步生成；CSV 转义公式前缀，导出保存日期、币种、时区和数据覆盖说明。

## 4. 剧识别规则

### 4.1 唯一规则

按 ASCII 连字符 `-` 分段，第一段是版权方，第二段是剧名，第三段起全部视为备注。裁剪前两段首尾空白并做 Unicode NFC 规范化；保留中间空格、大小写和文字本身，不做拼音转换、别名合并或模糊匹配。

前两段必须非空；只有 `版权方-剧名` 也有效，备注可以省略。必须保留空段进行校验，`嘉书--测试` 无效，不能把备注当剧名。剧名本身不包含 ASCII `-`，符合用户已明确的“剧名固定第二段”规则。

| 系列名 | 解析结果 |
| --- | --- |
| `嘉书-总裁归来-测试-0930` | 版权方嘉书，剧名总裁归来 |
| `嘉书-总裁归来-账户2` | 与上一行合组 |
| `网眼-总裁归来-测试` | 与嘉书同名剧分开 |
| `嘉书-总裁归来` | 有效，空备注 |
| `嘉书--测试`、`总裁归来` | 命名不规范 |

归组键是 `tenant_id + bc_id + provider_label + drama_name`。账户、连接、通道、日期、备注、剧 ID、YTF/SYS 标签及搭建来源均不进入归组键。同一版权方同名即同组，这是本期明确的名称口径；不依据其他字段偷偷拆组。

系列以下对象通过父子关系继承归组，素材按“广告内使用位置 → 广告 → 组 → 系列”继承。不会将素材库文件永久绑定为某一部剧。

### 4.2 异常及名称变化

命名不规范的系列及其指标进入“命名不规范”汇总，可展开广告明细，基础管理操作不受影响。缺少父系列的对象标为“系列待同步”，定向补齐后再归组。不得从子级名称、素材文件名或旧剧 ID 规则猜测补齐。

历史报表事实始终按远端对象 ID 保存，剧视图按最近一次成功同步的系列名称归组。修改第一段或第二段后，该系列所选历史区间的数据整体转入新组；只改备注不影响归组。保留名称变化和解析版本，页面在发生名称变化时提示历史汇总可能变化。

运行中的批量任务已经冻结具体目标，不因名称变化自动加入新对象；执行前发现已选系列的剧归组发生变化，相关项进入冲突状态并要求重新预览，避免旧剧选择操作到已改名的系列。

## 5. 平台对象与能力边界

普通广告与 Upgraded Smart+ 使用独立接口合同和类型标识。Smart+ 的系列、组、广告资产集合、创意四层不可混用；`smart_plus_ad_id`/`ad_id_v2`、创意 `ad_id`、广告内 `ad_material_id`、素材库 `video_id`/图片 ID 分字段保存。

| 能力 | 官方接口族或 MCP 工具 | 适配要求 |
| --- | --- | --- |
| 普通系列/组/广告读取及启停 | `campaign/*`、`adgroup/*`、`ad/*` 的 get、status/update | 分页、状态和操作对象独立验证 |
| 普通组 ROAS | `/adgroup/update/` 的 `roas_bid` | 只对支持的出价策略开放；核实整体替换字段，保留必需原配置 |
| Smart+ 三级读取及启停 | `/smart_plus/{campaign,adgroup,ad}/*` | 使用对应新广告身份，不按旧广告 ID 猜测 |
| Smart+ ROAS | `/smart_plus/adgroup/update/` | 增量更新；预览系列联动并按系列锁定 |
| 广告内素材启停 | `/smart_plus/ad/material_status/update/` | 使用同一广告内的素材 ID，按接口上限及素材类型拆批 |
| 基础报表 | `/report/integrated/get/` | 每个广告类型、层级、指标组合有明确合同 |
| Smart+ 素材报表 | `/smart_plus/material_report/overview/`、`breakdown/` | overview 不做时间拆分；breakdown 用于支持的小时/日拆分 |
| 历史大报表 | `/report/task/create/`、`check/`、`download/` | 与 SDK 客户端异步线程区别，按真实生成完成状态读取 |

当前工具说明给出同步报表最多涉及 20,000 个广告，需按系列/组/广告 ID 分片，不能只靠翻页绕过。适配器维护真实上限及过滤器合同，不把某一工具的批量上限硬编码到所有操作。

Smart+ 自动系列预算下，组出价修改会联动同系列其他组。当前 MCP 描述对联动范围更宽：非自动系列预算的边界尚未取得足够证据；适配器在验证前按系列影响上界展开，无法确定安全变更合同的组合返回不支持，不能当成单组独立修改。

普通组更新不能把未验证的整体替换接口当成 PATCH。平台没有条件更新能力时，执行前新鲜读取和本地锁只能降低冲突，不能消除外部后台在读取与写入之间修改的竞态；使用最小允许字段集，保存发送配置，后续同步发现差异时明确显示。

素材报表支持什么指标由实际维度合同决定，尤其不能仅凭 `metrics: string[]` 就认定 Minis 收入可查询。不可取得的指标标为“平台未提供”，保留可取得的指标，不用广告金额平均分摊。Smart+ 自动添加创意需补充平台支持的创意目录来源，缺失部分标覆盖不完整，不能宣称手动选择素材列表是完整投放列表。

旧版 Smart+、Smart Creative 等类型按实际通道能力展示读取或管理支持情况。没有对应 MCP 工具时，不以 API 的存在推断 MCP 支持，也不静默替换成其他广告类型的接口。

## 6. 指标合同与聚合

| 组 | 指标及口径 |
| --- | --- |
| 投放核心 | `spend`，D0 收入 `native_growth_ad_revenue_value_d0`，D0 ROAS＝D0 收入/消耗 |
| 总收入 | `native_growth_total_ad_impression_value`，总收入 ROAS＝总收入/消耗；与 D0 收入分别展示，不能相加 |
| 流量 | 展示、点击、CTR、CPC、CPM；百分比/成本指标由同口径原始量重算 |
| 效果 | 优化结果及成本、支持的转化和 IAA 事件；IAA 事件数与展示数不是同一指标 |
| 配置 | 目标 ROAS、预算、排期、操作/审核/实际投放状态；不混入报表金额事实 |
| 辅助 | 账户余额及可用性、同步时间、观测变化；余额为时点值，不随报表日期求和 |

字段内部维护平台字段名、业务名称、单位、可加性、币种、归因口径、支持的粒度和广告类型。结果类指标只有相同优化目标和事件定义才可合计，混合目标显示拆分；目标 ROAS 不与实际 ROAS 混同。

所有 ROAS 按合计收入/合计消耗计算，不平均各行 ROAS。分母为零时为无值；未提供、未同步、同步失败和真实零分别表示。金额使用十进制定点数，保留上游精度，显示层才舍入。

账户、系列、组、广告层选择各自经过验证的事实作为汇总来源。同一报表不能把父级和子级金额相加；上级报表与子级合计不一致时记录覆盖/修正差异，不擅自分摊差额。剧视图以系列同口径事实聚合；素材视图以真实素材事实聚合。

主素材与文案、CTA、组件等可能存在重叠归因。默认素材视图使用支持的主视频/图片口径；不同资产类型和粒度不可拼接后求总计。无法得到某剧或某广告筛选下的素材拆分时，该组合显示不支持，不能用素材全账户金额替代。

所有金额保留原币种，跨币种展示分币种小计，首期不做汇率换算。日期默认按广告账户本地时区解释，混合时区的“今日”明确表示各账户当地今日；趋势按时区分组展示，不伪装统一自然日。归因口径不同的指标不能直接合并。

暂停和删除广告的历史事实继续保留。目录尚未同步到的有消耗对象以远端 ID 显示并补取目录，不因关联失败丢失金额。

本期“累计”指用户所选区间累计，并显示已成功同步的实际日期覆盖。初始回补近 30 天；选择更早区间时发起历史回补，在回补完成前显示不完整覆盖，不能把已存数据冒充完整历史。

观测快照保留账户和系列粒度的近期事实，剧趋势按最近同步的系列命名投影重新归组，不能只存无法迁组的剧合计快照。仅在日期、时区、币种、筛选范围、归组及成员集合、相邻采集完整性可比时计算“较上次同步变化”；成员或命名归组变化的相邻观测标记口径变化，不计算差值。保存实际间隔，不声称差值就是该半小时真实发生额。负变化原样保留并标明可能修正；跨日或缺失观测时不计算。明细事实按小时/日 upsert，不把每次累计快照重复相加。

## 7. 同步调度、频率与新鲜度

| 任务 | 默认频率与范围 |
| --- | --- |
| 完整广告目录 | 每 3 小时逐账户同步系列、组、广告及支持的素材引用；查询暂停、删除等平台可见对象 |
| 活跃配置 | 每 30 分钟刷新启用或近 7 天有消耗对象的状态、预算及目标 ROAS，支持字段裁剪时减少返回体积 |
| 核心报表 | 每 30 分钟更新当日及前一日的核心事实，支持时包含小时事实；包含当前停投但仍处归因窗口的对象 |
| 近期回补 | 每 3 小时重拉最近 7 天的日事实 |
| 完整归因回补 | 每日 13:00 UTC 回拉“已知最大归因窗口＋7 天缓冲”；无法取得窗口时默认回拉最近 35 天并标记窗口未知 |
| 长周期修正 | 每周回拉最近 90 天已请求的历史范围，修正近期窗口外变化 |
| 初始历史/手动回补 | 首次近 30 天，按账户和日期分片；更早范围按请求补齐 |
| 账户余额 | 每 30 分钟独立读取；不可见或失败不填零，不阻塞效果报表发布 |
| 操作后同步 | 明确成功回执立即更新本地请求结果，合并调度受影响对象刷新；不等待下一次 3 小时扫描 |

以上是应用采集频率，不是上游实时性承诺。常用基础报表通常已有约 30 分钟延迟，某些指标更慢，次日仍可能修正。页面分别显示目录同步时间、报表采集时间和已覆盖日期，不把采集完成时间等同于平台数据绝对最新时间。

Beat 只扫描到期计划，由数据库唯一任务键和 Outbox 投递小分片；相同账户、报告合同、时间窗任务合并去重。每个分片保存分页/游标、冻结路由、开始时间、成功覆盖和失败原因，可中断续接。超过一个周期仍未完成时延续原任务，不堆叠整批重复任务。

预览读取和明确用户管理操作优先，其次当日同步，历史回补最后；管理、目录、报表有独立队列及有界资源预算，后台任务保留最低公平执行份额。所有物理调用仍经过现有 API app/MCP 上游共享额度准入，增加连接不能绕过限流。

完整目录扫描使用暂存页及发布版本。部分失败不能把未出现的对象标成删除；完整扫描缺失也先标为本次未见/待核实，只有明确远端事实才写删除状态。失败保留旧有效版本并显示过期；取消授权按当前访问策略停止读取和操作，不泄漏其他 BC 数据。

报表按“账户＋报告合同＋时间分片＋指标组”完整分页成功后原子发布。部分分页不覆盖已有完整事实，也不能把尚未取得的行填零；确认为完整空结果时，按该报告的空结果合同更新。较旧任务晚到不得覆盖较新版本。某账户失败时允许其他账户完成，汇总同时标明缺失账户和覆盖数量。

手动刷新经过相同队列和额度门禁，短时间重复点击合并任务。页面轮询本地任务状态，不产生额外 TikTok 查询。同步延迟、失败率、分页完整性、配额等待及未识别命名数用于运维观察。

## 8. 批量操作业务规则

### 8.1 目标 ROAS 与预算

支持设为固定值、增加/减少固定值、增加/减少百分比。预览读取新鲜配置，计算明确最终值，保存原值和最终值；任务重试只使用最终值，不重复执行百分比运算。预览有效期 5 分钟，超时或关键配置变化重新准备。

ROAS 仅适用于支持目标 ROAS 的出价策略。按广告类型、账户资格、范围和精度校验，无支持能力的行列出原因。Smart+ 同系列联动必须展开全部影响对象，同系列多个冲突最终值禁止提交；不会使用“最后一条覆盖前一条”的处理。

预算只做即时调整，按平台实际预算拥有者操作。系列预算模式下，不把组行预算相加或发成多个组预算更新；预览先去重到系列。定时预算和自动增预算不进入本期。

### 8.2 启停及实际投放状态

系列、组、广告按原生层级启停；素材按具体广告内引用启停，遵循保留可用素材等已确认的平台限制。素材没有独立开关时，不把停用整条广告伪装成停用素材。

剧启停展开当前归组下的系列；账户启停展开账户内系列，绝不调用禁用广告账户接口。暂停父级不重写所有子级开关；启用父级保留子级原有状态，预览说明仍停用的下级对象数量。

从下级启动而父级暂停时，预览提供“同时启用这些父级”的具体列表。只有用户在同一预览中选入这些父级才写入；否则只改变选中对象并提示父级仍阻止投放。审核、余额、排期等限制不会因开关 ENABLE 就被称作已投放。

恢复某次暂停依据该任务的修改前状态生成新预览，仅恢复该次确实改变的对象，保留原本停用项。对象之后又被修改时列为冲突，不覆盖新决定。恢复同样是可审计的新任务，没有跨账户原子回滚承诺。

### 8.3 选择与确认

支持勾选当前页、跨页保留选择、选择全部匹配结果。生成预览时固定目录/报表版本、筛选条件和具体目标 ID；执行不会重新搜索并吸收后来新建广告。

预览包含当前 BC、账户、操作、选中数量、去重后目标数量、联动数量、原值/新值、不可操作项和原因。用户可以明确排除不支持项后提交支持项，不能静默丢弃后报整批成功。预览提交一次即授权该具体任务，不增加第二套激活流程。

## 9. 任务可靠性、并发与权限

任务模型分为预览、批次、目标项、请求尝试和回执。批次状态为准备中、待提交、排队、执行中、成功、部分成功、失败、需核实、已取消；目标项另记录无需修改、配置冲突和不支持等结果。

提交在同一事务内保存不可变目标和 Outbox，使用请求幂等键。批次冻结 tenant、BC、connection、channel、授权版本、绑定代数及适配器合同版本。执行每个请求前重新验证操作者当前权限与冻结路由；撤权、解绑、合同不兼容时停止相关项，不改用另一通道。

新增明确的广告管理权限及精确操作注册。租户管理员、具有投手权限且平台允许管理的成员可提交；只读成员可查看/筛选/导出，不可提交管理任务或修改同步配置。定时同步使用租户授权的后台执行身份，不借用页面用户的短期会话。

普通对象按租户、账户及实际对象加互斥执行约束，不按 BC 或连接拆分同一对象的锁；Smart+ ROAS 按系列加约束，父级启停与下级操作也按祖先范围协调。所有会修改重叠状态的既有搭建隔离路径和新管理路径共用冲突协调，不能只在新模块内部加锁。Redis 用于配额/租约，数据库保存领取代数及恢复状态，工作者失联后旧代不得发布新结果。

执行前分组读取必要的远端配置，比较预览原值、父子关系和剧归组。配置漂移时相关项进入冲突，由新预览承接；未受影响项可继续。平台若不提供条件更新，本地不能保证阻止 TikTok 后台同时修改，任务界面及审计记录保留可核查事实。

正常明确成功回执直接记为接口已成功接受/更新，不逐项串行阻塞回读；后台合并同步投放状态，单独展示同步是否确认及实际投放状态。正常成功后出现不同状态，作为后续差异处理，不把旧任务不断重发。

遇到超时、断连或崩溃发生在请求可能发出后时，进入“需核实”。读取当前值等于期望值时可记为已观测目标达成，同时保留原请求归因不明；不等于期望值不能证明原请求没执行，不自动重发。明确未发送或平台明确拒绝的可重试项，重试前再次检查权限和原值；只有必要条件仍成立才续接。

取消只取消尚未发送项；已发送项继续收集结果。任务部分成功不自动反向恢复成功项，避免覆盖外部的新变更。日志保留修改前值、请求值、返回结果、平台请求 ID、通道、操作者和时间，不记录令牌。

## 10. 后端模块与数据边界

新增职责清晰的模块，不重构无关搭建/素材代码：

| 单元 | 职责与依赖 |
| --- | --- |
| `modules/ads` | 远端广告目录、父子关系、名称解析、素材使用关系；依赖账户访问范围 |
| `modules/reporting` | 指标合同、事实存储、覆盖状态、六维查询与导出；依赖 ads 身份及范围 |
| `modules/ad_management` | 预览、影响展开、任务、互斥、回执；依赖 ads 当前配置和 gateway |
| 领域同步任务 | 由 ads/reporting 各自负责计划和分片，复用 jobs/Outbox/准入，不另建通用工作流引擎 |
| `integrations/tiktok/contracts` | 通道无关的广告读取、管理和报表 DTO 及能力描述 |
| `integrations/tiktok/adapters` | MCP 与官方 Python SDK 各自的管理/报表适配器 |

核心数据模型：

- 广告对象：`tenant_id + advertiser_id + entity_kind + remote_id` 作为稳定身份，保存广告类型、父级、名称、配置、三类状态、更新时间及版本。BC 访问关系、读取来源和通道单独记录；接口切换不能重复生成广告。
- 系列命名投影：系列 ID、原始系列名称、版权方、剧名、解析状态及规则版本；通过授权账户和当前 BC 计算归组，不新增可人工维护的剧实体。
- 素材引用：账户、广告、广告内素材 ID、平台素材 ID、可选本地 material_id、操作状态、引用完整性。同一视频跨广告/跨剧分别保存引用，外部素材无本地记录仍可展示。
- 报表事实：账户、对象类型/ID或素材事实键、时间桶、粒度、报告合同、币种、时区、归因口径、指标值和采集版本。指标集合发布边界与事实唯一键一致，不能用只含部分字段的响应抹掉其他完整指标。
- 采集覆盖：计划/运行/分片/页、水位、成功范围、错误、冻结路由、版本；BC 通过访问关系限制查询，同一账户在同一报表中去重。
- 管理任务：冻结选择与影响范围、前后值、版本、尝试、请求回执和审计。

素材库是租户共享的；`MaterialFile.bc_id` 只代表历史上传来源，不能据此筛选当前 BC 的投放素材。报告的素材归属必须由实际投放账户和广告引用确定。

所有新增数据通过 Alembic 迁移，部署遵循现有备份与验证手册。索引围绕租户、账户、父级、日期、名称搜索与任务状态建立；首期使用 PostgreSQL，不预设 ClickHouse。

## 11. 产品接口合同

接口命名在实施计划中映射到仓库约定，下述职责和行为在设计层固定：

- `GET /tenants/{tenant_id}/ads`：按显式 `bc_id`、维度、日期、条件、排序、游标查询，返回行、总数、汇总、覆盖/新鲜度、行能力。
- `GET /tenants/{tenant_id}/ads/{kind}/{id}`：在账户和 BC 范围内查询详情、父子关系及审计。
- `GET /tenants/{tenant_id}/reports/trend`：同一筛选合同下的支持粒度趋势，返回时区/币种分组及缺失信息。
- `POST /tenants/{tenant_id}/ad-sync-runs`：请求当前范围刷新或历史回补，返回可合并复用的本地任务。
- `POST /tenants/{tenant_id}/ad-management-previews`：冻结筛选/显式 ID，读取必要配置并生成可审阅的影响列表。
- `POST /tenants/{tenant_id}/ad-management-tasks`：携带预览版本/摘要与幂等键提交；GET 列表/详情读取进度；取消、重试、恢复均为明确独立动作。
- `POST /tenants/{tenant_id}/report-exports`：冻结筛选和报告版本，异步生成当前用户权限范围内的导出。

所有查询从服务端当前成员与 BC 访问关系开始，不信任客户端传来的账户池。详情 ID 还需账户及对象类型定位，不能凭同数字 ID 跨账户读取。百分比、排序、总数和导出使用相同版本，页面刷新后提示可重新生成选择。

## 12. 双通道及未来推送

MCP 与 API 适配器在本期同时实现和测试，业务不得出现“只有 MCP 才能管理广告”的分支。官方 API 继续使用仓库官方 Python SDK 客户端；缺失的 SDK 方法只通过官方客户端允许的调用机制适配，不增加自建业务 HTTP 网关。

能力按通道、广告类型、操作、维度和指标组合登记，分为已通过合同测试、已通过真实联调、不支持或未获授权。MCP 工具 schema/名称和 API SDK 方法各自验证；某通道未授权时显示不可用，不自动切换。

当前 API 未获真实授权：可以完成实现、传输边界替身测试、数据库/队列测试；真实 API 读写验收单独保留为未完成，不能称作已接通。MCP 同样按具体 BC、账户类型和指标组合验收，不以 tools/list 成功代替业务成功。

未来推送作为另一个同步触发来源，转换成相同账户/对象/时间窗口的刷新任务，复用去重与事实发布。当前不创建无能力的回调接口，不改变定时拉取的完整性职责。报表变化订阅有白名单及指标范围限制，开发者审核通过不等于能接收全部报表数据。

## 13. 分阶段交付与验收

本设计作为共同接口和业务边界；正式实施计划按以下三个独立可验证阶段编写，不将所有模块塞入一次大改动。

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| A：目录、双通道与采集 | 广告身份/命名投影、素材引用、指标合同、同步任务、MCP/API 适配器 | 本工具及外部对象使用相同目录；完整分页/分片、隔离、去重、回补和失败发布行为可验证 |
| B：六维工作台 | 六维列表、搜索筛选、汇总趋势、详情、刷新、导出和命名异常展示 | 同一筛选下列表/汇总/导出/全选一致，外部广告无本地素材也不漏数 |
| C：批量管理 | ROAS/预算/启停预览、管理任务、逐项结果、取消/重试/恢复 | 实际影响范围明确，联动冲突阻断，未知结果不盲重发，多任务互斥和撤权停止通过验证 |

关键验收场景：

1. 相同版权方＋剧名的跨账户外部系列合组；不同版权方同名分组；无剧 ID/YTF 标记照常识别；两段名称有效、空第二段无效；备注变化不迁组。
2. 修改系列第一/第二段后历史报表及系列观测事实按最新名迁组，归组/成员变化不计算相邻观测差值；冻结任务不吸收新系列，已选系列归属变化触发冲突；异常名称仍能查看和启停。
3. 同一广告被 API/MCP 读取不重复；普通创意 ID 与 Smart+ 广告集合 ID 不混用；同一素材跨剧按真实引用统计；不能拆分的素材收入明确不提供。
4. 暂停/删除对象历史金额保留；零消耗 ROAS 无值；比率正确加权；不混币种、时区、优化目标或归因口径；命名异常金额可对账。
5. 失败分页不发布半份事实、不清空旧值；完整空结果正确处理；较旧分片晚到不能覆盖新版；负修正、跨日及延迟回补符合口径。
6. 搜索跨全部分页，全选按同一筛选冻结；批量对象去重；Smart+ 联动同系列目标冲突被拒绝；不支持项可见且不默默跳过。
7. 暂停父级不改子开关，启用父级不复活原停用子项；恢复按原任务变化生成预览；素材不支持独立停用时不替换成停整条广告。
8. 使用真实 PostgreSQL/Redis 验证双提交、重复投递、领取代数、请求发出后崩溃、配额租约、相交对象锁、撤权/解绑、取消与执行竞态。外部替身只放在传输边界。
9. 前端验证筛选/汇总/选择一致性、部分失败和新鲜度、只读权限及既有响应式视觉；运行相关行为测试、类型检查与构建。
10. 真实联调单列 MCP 和 API 的证据，逐项指定 BC、账户和具体操作；没有授权的通道明确未验收。容量验证记录账户/对象量、30 分钟采集周期是否按时完成及搭建队列影响，不把未压测的规模写成承诺。

本稿没有执行上述产品测试；它定义后续验收要求。当前轮次只进行设计文档检查。
