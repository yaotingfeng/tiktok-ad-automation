# 广告报表一分钟首屏缓存

用户已明确允许最多一分钟缓存和后台刷新。本设计只影响首次打开/重新筛选的首屏；游标分页、冻结选择、导出继续绑定原快照。点击加载最新结果等待新一代结果。无新布尔开关，无 TikTok/MCP/广告写入。

Redis保存压缩后的完整首屏（行、排序、总数、汇总及覆盖一起缓存），按租户、BC、操作者、完整筛选、页大小及实时权限标签隔离。每次请求重查权限与快照有效性；撤权、绑定代数/范围变化不能命中旧缓存。缓存有效期从构建的数据库视图开始计时最多60秒，构建时间也计入；不以后台失败续期，不返回过期结果。

API只读取和登记缓存需求，等待期间释放DB连接、支持请求取消。Control每5秒扫描活跃需求；ads-reporting负责构建和刷新。每键令牌租约与全局两个构建槽控制并发，过期/重放任务不能覆盖新结果。任务执行前后均核验当前权限。活跃需求3分钟不再访问就停止刷新；失效缓存/Redis故障不能伪装成最新结果。首次无缓存仍须构建，前端如实展示加载状态。

后台构建使用独立RR事务，单语句及整轮90秒预算，Celery软/硬时限100/110秒，租约120秒；只用于后台，不放宽交互精确查询预算。超过60秒才完成的视图拒绝发布为一分钟缓存。旧快照保留期和不可变版本生命周期继续生效。

验证：真实PostgreSQL/Redis下的缓存命中、绝对60秒到期、权限/BC/操作者隔离、撤权、强制新一代、请求取消、并发去重/槽上限、失租不得写回、后台失败不续期。UI显示实际缓存数据时点。生产无DDL；先注册并正常更新Worker，再更新API/Beat，保持资源/配置/退出宽限，共享发布锁及CI协调。通过后预热并测六维缓存命中与冷构建，分别记录。
