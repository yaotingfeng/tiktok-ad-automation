# 目标素材确认的必要性与自动恢复

## 评估结论

用户要求评估核查是否多余，必要时优化到常见暂态故障无需人工介入。本轮判断：目标素材首次确认必要；每次搭建重复读取已充分确认的素材不必要。这里是取得实际目标 VID、内容摘要及可用证据，不是人工审核或二次启用广告。

当前 native_share 类型化回执只有请求证据与逐账户失败 MID，没有目标 VID 映射。不能用“源账户有此视频”代替“当前目标账户可用”，也不能将源 VID 未经验证直接填成目标 VID。成功上传已返回真实 VID 的回执以及已确认的目标映射继续复用；现有代码已取消900秒本地年龄导致的自动失效。本轮保留这些免回读路径。

## 方案选择

- 全部取消：会把共享受理、真实目标身份和可用性混为一谈，将缺素材或错误内容推迟到广告写入时发现；不采用。
- 全量逐项反复检查：多请求、多锁竞争，而且已经确认的证据被反复刷新；不采用。
- 按证据确认、自动恢复：第一次共享缺少目标证据才查询，同账户批读，已成功证据直接消费；本轮采用。这个选择由本轮技术评估作出，不冒称用户另行确认过具体退避数值。

## 本轮具体修改

1. 批量视频核查的请求前检查改为一条按租户/执行人/冻结成员约束的联合读取，不取跨账户共用素材主记录的排他锁。单项 verify 同样只读检查。prepare 写路径仍保留原锁；真实结果发布仍锁定并重验租约、代数、请求摘要、内容及冻结路由。权限每次实际请求重新查。
2. 本地资源、准入或本次执行期限错误不计远端 claims/no_progress；保留既有远端计数，30秒后由原 outbox 消息自动续读，不靠人工重开。记录 last_reconciliation_error，保持 broker/业务冷却期限。
3. 已 ACK 的原生视频共享，短轮三次无进展/15分钟/120次耗尽或完整空扫描后，改为5、10、15、20、25、30分钟、之后最多30分钟间隔的只读自动确认。旧轮预算及原因保留。新一轮保持原 operation/request digest，不重新共享、上传或创建；下一次投递和当前 revision 同事务登记。其他批次和重复消息不得提前绕过冷却。
4. 权限撤销、身份冲突、内容歧义不自动视为成功；原授权/源对象需处理的边界仍保留。无 ACK 的未知发送和其他上传来源的历史人工核查规则不在本轮扩大，本轮不宣称所有业务异常都可自行修复。
5. IMAGE 的新主线流程不纳入本轮自动轮次策略；不发布尚未上线的图片轮播合同。没有新增DDL、队列、业务开关、Worker并发、平台配额或 task payload 字段。
