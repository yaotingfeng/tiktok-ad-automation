# 经营比例按时间段配置

状态：待用户审阅；本轮只完成设计，不修改业务代码或线上配置。

## 需求与选择

用户的比例由版权方协议按季度或指定日期调整，可能事后追溯。用户已选择按时间段展示，并要求持续有效的比例可以改成确定的截止日期。版权方抽成与 BC 其他返点使用一致交互，保持各自作用域及现有计算公式。

考虑过三种方式：

1. 保留生效日期和版本优先级，仅补说明：成本低，但用户仍需理解覆盖规则。
2. 保留生效日期，自动展示下一条配置推算的截止日期：查看更清楚，但从较早日期统一调整仍需多次操作。
3. 按时间段编辑，保存前展示完整调整结果，版本仅保留在修改记录：直接表达结算协议。本方案采用该方向。

以下细节为本次提出的设计默认，待用户审阅：截止后可明确待配置；新范围覆盖重叠旧范围，保留范围外部分；同一作用域并发修改时要求刷新；从未设置及首次配置之前仍沿用现有默认 0%，明确显示默认来源。

## 页面与操作

沿用现有 RateSettings 管理抽屉和 shadcn/ui 组件，不另建配置页面。顶部显示当前适用比例、下一次变化日期；主要列表展示开始日期、结束日期（或持续有效）、比例、状态及操作。版本移至独立的“修改记录”区域。

新增/调整比例填写开始日期、结束日期或持续有效、比例及选填说明。结束日期包含当天，按广告账户当地业务日期核算。默认开始日期沿用现有日期默认值，不因打开表单更改历史数据。

支持三种操作：

- 新增/从某天调整：用新比例替换填写范围，范围外配置保留。
- 修改本段：修改选中时间段的日期或比例；先移除该段，再将修改后的段应用到其余日程。缩短后没有其他配置覆盖的日期为待配置，不自动复活被覆盖的历史配置。
- 结束本段：填写截止日期，可同时填写下一日起的新比例。未填写后续比例时，直到下一条已安排配置开始之前明确为待配置。

接续比例同样有明确的结束日期或持续有效选项。默认结束于下一条已安排配置开始的前一天；没有后续配置时默认持续有效。表单明示这个日期并允许修改，不能暗中覆盖更晚的已安排配置。例如已有8月至9月6%、10月起4%，将首段结束于8月31日并接续5%，默认得到9月5%、10月起仍4%；只有明确将接续5%选为持续有效，预览才会展示替代10月起4%。此项为设计审阅后选定的默认，待用户审阅。

保存分为预览和提交。预览展示调整前后时间段、被替代范围、待配置范围和历史重算提示。使用已有抽屉中的预览步骤及最终“确认保存”按钮，不新增弹窗叠层。取消预览不写数据。修改记录保留操作者、时间、说明、调整前后日程与内部修订号；允许直接修订历史，不删除审计记录。

主要列表的待配置区间支持“设置比例”。设置 0% 是明确的有效配置，与待配置不同。不能直接删除整个作用域、也不提供恢复旧修订按钮，避免未明确范围的回退。

## 范围替换规则

每个作用域的最终时间轴不允许有效段重叠。用户填入区间 [开始, 结束] 时，裁剪所有重叠段，保留它们在新范围外的左右部分，再插入新段；结束为空代表无限期。相邻且比例相同的有效段可合并，审计仍记录原操作。

例子：

| 已有配置 | 操作 | 最终配置 |
| --- | --- | --- |
| 10月1日起4% | 新增8月1日起持续有效6% | 8月1日起6%，原10月4%被替代 |
| 10月1日起4% | 新增8月1日至9月30日6% | 8月至9月6%，10月起4% |
| 8月1日起6% | 从10月1日起调整为4% | 8月至9月6%，10月起4% |
| 8月1日起6% | 结束于9月30日，未填后续比例 | 8月至9月6%，10月起待配置 |
| 8月1日至9月30日6%，10月起4% | 将6%结束日期改为8月31日 | 8月6%，9月待配置，10月起4% |
| 8月起6%，10月起4% | 9月1日至10月15日改为5% | 8月6%，9月1日至10月15日5%，10月16日起4% |

修改开始日期同样不恢复旧记录；移动后产生的空档列入预览。新建较早的配置可以替代原本默认0%的日期。首次配置之前默认0%；一旦某个日期被明确终止或移出有效段，原有效覆盖范围内的空档保持待配置，不能因首次日期变化再次退回默认0%。实现必须存储明确的默认边界/待配置段，不只根据最新有效段的最早日期猜测。

## 存储、接口与并发

建议采用每个作用域的完整时间轴修订快照，包含有限数量的有效段与明确待配置段。每次保存生成不可变修订，而不是直接改写旧比例记录。日期及 Decimal 比例统一由后端验证；截止日期早于开始日期拒绝。日期上界与系统支持范围一致，避免最大日期加一天溢出。

作用域仍为 tenant_id + kind + scope_id：provider 对应本租户版权方连接，rebate 对应本租户 BC。修订号只表示整个日程的保存顺序，不再与生效日期竞争。保留当前管理权限和 BC/版权方存在性检查。前后端统一移除旧的“追加生效日期即保存”行为，无双轨回退。

读取返回当前完整日程、修订号及必要的待配置边界；历史接口分页返回修改记录。预览和提交使用相同的后端时间轴变换函数。提交携带预览所依据的修订号及同一操作内容；事务中锁定同一作用域、重新验证修订号并应用相同变换，原子写入快照、审计和重算围栏。并发变更返回409，页面保留输入并提示刷新后重新预览，不能覆盖他人的修改。预览结果不作为可直接信任的提交数据。

已有按天查比例的辅助函数和批量投影统一读取新日程解析器，禁止分别维护两套规则。批量核算按作用域加载日程，避免逐系列查询。计算任务冻结所用日程修订，期间配置变化仍通过已有 scope revision 围栏阻止旧任务发布；不能同一任务部分日期读取新配置、部分读取旧配置。

## 待配置与核算

保留未设置过的作用域及迁移后首次生效日期之前原有默认0%行为，页面明示“默认0%，未设置”。明确终止、修改缩短或移走形成的空档标记待配置，不自动续用前一比例，不从已失效修订回取，也不自动变为0%。

版权方比例待配置：平台消耗、平台收入及平台ROAS仍显示；抽成、分成后收入、经营收入、经营ROAS及依赖经营收入的情景结果显示待配置。其他返点若有效仍可展示。

返点比例待配置：平台数据、有效的抽成和分成后收入保留；返点、经营收入、经营ROAS及依赖经营收入的情景结果显示待配置。赔付、新剧补贴各自的独立预估仍按原规则计算，不受比例缺失抹除。

日明细、系列/剧目/版权方汇总、五卡、各情景、排序与CSV都遵循缺失传播，不把缺项按0计入合计或展示部分合计为完整结果。使用明确的缺配置问题码，帮助用户定位作用域和日期。真实0%保持正常数值。历史冻结导出不重写，新查询及新导出使用重算后的完整发布版本。

## 迁移与重算

通过新增 Alembic 迁移将旧记录按原规则（生效日期优先，同日最高版本）归一成不重叠时间段；最后一段持续有效。原始记录保留作为旧修改历史，不能丢弃同日被修订的记录。迁移不改变旧业务日的费率与原默认0%语义，不擅自将历史8月高版本解释成覆盖10月。上线后只使用新日程解析，不运行旧选择器回退。

版权方修改推进当前租户相关 BC 的经营修订，BC返点修改只推进对应 BC，沿用已有后台调度和原子发布。涉及历史的预览明确说明后台重算；完成前继续显示上一完整版本并标记更新中。未来区间只影响对应业务日期，不能提前改变当前日费率。迁移需推进计算合同版本/修订，确保已冻结旧格式任务不能发布。

本轮开发不改线上业务配置、不执行真实广告写入、不推送、不发布。数据库迁移的生产执行另按部署手册准备具体发布方案，不把本地迁移验证当作线上完成。
