# MCP 账户解析搭建权限修复

用户在已有草稿输入剧名及两个账户后，账户行显示 `account_build_unverified`，无法继续搭建。服务器账户已识别、目录与角色有效、可上传，但 MCP 的 `observe_authorization` 将 `build_authorized` 固定返回 None；24 小时内的能力缓存还会复用这个未知值。问题发生在本地权限判断，尚未请求创建广告。

## 修正

MCP 已接入 Smart+ Campaign/Ad Group/Ad 创建适配器；官方服务支持广告创建及管理，参见[官方介绍](https://ads-useast2a.tiktok.com/resources/help/article/about-tiktok-for-business-mcp-server?lang=en)。基于实际授权令牌的 `mcp:tt4b`、匹配注册客户端/issuer/resource 及真实 `user_info_get` 主体，将搭建与上传同样解释为已授予服务调用范围。不是根据公开 metadata 中的 supported scope、工具可见性或此前一次上传成功授予账户操作权。

账户可搭建仍须完整 BC 目录、用户可访问账户交集、有效账户详情、ADMIN/OPERATOR 角色、租户权限、冻结连接/绑定代数等共同通过。ANALYST、未知角色、主体/范围变化、失权、未接入接口继续阻断；实际创建仍按原用户预览提交流程执行，上游拒绝保留真实错误，不预设广告创建成功。

当前 MCP 权限事实中若上传或搭建为未知，新的准备/显式能力重检必须先重新观察；不能复用旧的完整能力任务，也不能直接在数据库改 can_build。GET 不发任务，不改授权/绑定代数、不更换连接。完成观察后按原角色发布账户能力，再通过原草稿的准备接口重新解析，保留用户输入。

## 验收与发布

回归覆盖 ADMIN/OPERATOR 可搭建和上传、ANALYST/未知角色拒绝，两种动作同样检查；新鲜但只核实上传的旧事实触发新重检，正常完整事实继续复用。保留主体变化、令牌刷新未知及运行中权限撤销测试。

无新开关、无迁移；沿用 `mat_response_archive` head 和现有导入/清理开关。完整备份与隔离恢复通过后部署。线上验收只重新准备用户原草稿、检查同源账户解析与下一步准备结果，不提交或创建广告。浏览器未连接时明确记录只能验证同源接口及服务器任务，不能声称完成浏览器点击验收。
