# 租户统一素材库与按 BC 集中分发

日期：2026-09-16。状态：用户已确认产品方案并授权先完成设计、计划，再实施。本文将该授权具体化；本轮实施限本地代码、迁移演练和测试，不包含推送、环境发布或真实平台写入。

## 1. 问题与目标

当前素材库、搭建剧名匹配和手动选材都限定 `MaterialFile.bc_id == 当前 BC`。跨 BC URL relay 虽已存在，但 A 有视频、B 没有素材记录时，B 的正常搭建入口根本选不到素材。仅扩大列表会被草稿/预览/操作数据库外键以及执行阶段的 BC 校验阻断。

目标：同租户只有一个素材目录；顶栏 BC 决定新上传及新搭建的目标。A 上传一次，在 B 可查看、匹配和选择；提交后系统先把缺少的素材转存到 B 的主素材账户，再在 B 内原生共享给投放账户。浏览和预览均不得触发分发。

## 2. 已确认的产品行为

| 场景 | 行为 |
| --- | --- |
| 切换顶栏 BC | 素材目录范围不变；新上传、新搭建使用新 BC |
| 上传 | 窗口显示上传目标 BC；提交后批次固定 BC/授权/账户，后续切换不重定向 |
| 素材目录 | 按租户读取；显示原文件名、上传来源与现有状态；详情能查看实际 BC/账户副本 |
| 自动匹配、手动选材 | 同租户全部素材，保持已有按剧名/文件名规则；同名不同内容不能合并 |
| 重复内容 | 经核实 SHA-256、MD5、大小相同的记录在一次匹配/选材中去重；保留原上传历史及文件名，不改写旧任务 |
| 预览 | 纯本地判断可直接使用、提交后准备或不可用；不创建转存任务，不选择并持久化主账户 |
| 提交 | 仅为本次涉及素材及目标账户准备视频和封面，然后继续既有广告创建流程 |
| 目标已有副本 | 核实有效则复用；过期证据只读核实，不直接重新转存 |
| B 内已有合法来源 | 使用该来源同 BC 共享，不为了统一历史再转存到主账户 |
| B 内没有来源 | 仅转存到 B 的主素材账户，核实后共享 B1/B2/B3；主账户本身是目标则直接用 |
| 结果不明确 | 保留同一操作和来源/目标冻结授权，只读核实，不换账户或重复上传 |

无需新增来源 BC 选择框、独立同步按钮、自动全库复制或额外广告启用确认。

## 3. 素材身份与真实平台位置

`MaterialFile.id` 是租户内素材身份。保留现有 `MaterialFile.bc_id` 作为原始上传来源 BC，明确注释其含义；不重命名历史对象存储路径，不改写上传批次、源占用和原件代数。是否能用于某目标 BC 不能再通过该字段判断。

平台副本 `AccountMaterial.bc_id` 表示真实所在 BC；`advertiser_id/connection_id/video_id/mid` 继续记录实际位置与证据。分发/操作/封面/搭建中的 `bc_id` 表示目标 BC。素材内容读取按 tenant+material ID；平台操作按 tenant+目标 BC+账户+冻结授权校验。

拆分两种数据库关联：

- 原始上传相关表继续引用 `(tenant_id, origin bc_id, material_id)`；源文件、入库和清理仍严格原位置。
- 搭建草稿、预览、目标操作、平台副本、目标分发、封面引用 `(tenant_id, material_id)`。各自 BC 与账户、操作、授权的外键和冻结 JSON 检查保留。
- BC 首次转存登记按租户、内容身份、目标 BC 和准备代数唯一；同一时刻仅复用最新代，保存实际素材 ID、固定主账户及分发依赖。可信内容键为 SHA-256/MD5/大小的摘要；缺少可信摘要时只能使用素材 ID，不能按名字推断相同。

历史重复文件不物理合并，不更新已有冻结 material_id。自动匹配分页续跑按内容检查已选项；即使原代表不再可见、另一条同内容上传记录成为候选，也不重复入组。候选去重在 SQL 分页前进行，优先有实际可用副本、其次有原件的代表，再按文件名和 ID 稳定排序；同租户可信内容别名共享选材可用性，保留全部历史名称用于匹配；手动组提交也拒绝重复内容。分发来源允许经核实相同内容的历史 ID，既有实际平台副本优先。

## 4. 两段分发与持久依赖

路径：目标账户有效副本 → 当前 BC 合法来源原生共享 → 当前 BC 主账户首次 URL 转存 → 明确不可用。

入口仍为 `ensure_target_asset`，浏览器不直接调素材写接口。内部把“进入某 BC”与“分发给目标账户”分开：

1. 校验当前目标账户/租户及冻结搭建授权，检查已存在目标操作/未知结果，不能因本次新来源绕过旧请求。
2. 存在同 BC 来源则沿现有单次/批量 native_share。
3. 缺少同 BC 来源时，通过短数据库事务取得该内容+目标 BC 的唯一转存登记。复用 BC 已固定的主素材账户；首次合法选择与上传共用主账户选择服务，不调用会改写原 IngestSessionFile 的源上传分配函数。
4. 冻结源 BC 读取授权和目标 BC 上传授权，使用既有 URL relay 执行器及完整响应归档。
5. 消费者等待同一个主账户分发；视频核实后再准备各目标分发。消费者的目标仍是 B1/B2，不得把主账户分发冒充目标账户成功。
6. 主账户的上传失败/未知状态传递到等待原因；原任务恢复不能跨来源、授权代数或账户。只有旧分发 blocked、操作 failed、具有明确未生效证据且没有在途 claim/成功 VID 时，新准备才可登记下一代，并冻结当前合法授权；主账户保持旧登记账户，旧等待者仍引用旧代。UNKNOWN、超时或尚未终结的操作不得换代重传。
7. 等待者复用过期主账户副本时，沿既有 existing_target 路径只读核实。封面延迟恢复也使用原预览冻结路由；证据过期则将同一个封面任务排为 VERIFYING，核实后继续搭建。

唯一登记及数据库锁承担跨进程幂等，Celery/outbox 只负责可靠投递。锁不跨 HTTP。过期租约只允许接管核实，不能重新发送已 armed 请求。重复投递、不同用户同时搭建、多个目标和重复内容别名不得产生多个首次 URL 上传。冷却/授权失效不自动更换主账户。主账户复用现有分发执行契约，须在冻结目标授权下同时具备上传、搭建及后续读取所需能力；预览会检查前提，不能将只有上传权限的账户报告为可准备。

## 5. 封面

视频 URL relay 经严格回读后是目标 BC 的真实上传来源，复用既有 SOURCE 封面流程；同 BC IMAGE 共享使用真实图片 MID，目标 image_id 单独回读，不假定与来源一致。

仅去除封面内容查找中“素材原始 BC 必须等于任务 BC”的条件；封面 job、图片共享批次及账户授权仍限定真实 BC。SOURCE 仅允许实际上传回执/已严格核实的 URL 上传证据；native_share 派生不能冒充原始所有者。图片 UNKNOWN 不重发，图片失败不改写已成功视频。

同内容不同上传记录可复用真实 SOURCE：source job/operation/asset 保留其实际 material_id，通过可信内容键关联目标别名；HTTP 前后核实双方内容身份及源授权。主账户本身以别名搭建时只读核实并复用已有 IMAGE，不向自己共享，也不伪造别名的上传回执。

## 6. 读取、权限与前端

素材目录/单条元数据/候选查询以租户成员权限为边界，不要求当前顶栏 BC 与原始 BC 相同。平台远程预览和资产可用性仍要求所选实际来源的当前授权；目录可见不等于平台可用。

原件签名、上传重试、分片、上传队列严格使用素材或批次的原始 BC。资产详情展示实际副本 BC，不能向全租户目录传入顶栏 BC 并误当作来源。跨租户 ID、游标、批次、素材引用全部拒绝。

前端使用租户级素材缓存键；切 BC 不重置目录搜索/页码。上传管理器按冻结批次目标管理，不因目录统一扩大上传权限。无有效目标 BC 时允许读租户目录，上传明确禁用。上传记录保存实际 BC；记录查看与新上传目标分开。沿用 shadcn 和既有页面布局。

## 7. 历史数据迁移与发布

新增迁移链 `material_share_receipts → tenant_material_library → material_bc_seed → material_target_scope → material_seed_generations`：依次分离消费引用、建立唯一转存依赖、补齐操作及分发独立的租户目标 BC 外键，保持原上传外键；新 BC 转存登记初始为空，不伪造上传回执或 MID。原素材、上传尝试、分发、操作、封面、历史草稿/预览与响应归档字段保持不变。准备代数迁移仅将已有 seed 标为第 1 代，保留旧依赖；存在后续代数时拒绝丢弃历史的降级。增加租户候选排序索引；精确 total 在去重和筛选后、分页前计算。

旧已提交任务继续引用原素材及冻结授权，不改其配置和结果。新行为统一替换旧 BC 库行为，不增加旧模式回退开关。存在新跨 BC 引用或首次转存记录时，降级必须拒绝，不能静默删除或重写数据。

本轮不发布。以后发布必须冻结入口、正常排空任务，按部署手册全量备份并完成独立恢复演练，再迁移及前后端/Worker 同版切换；不能直接回退不兼容数据库。

## 8. 验收

使用真实 PostgreSQL/Redis、外部服务仅 HTTP 传输替身，至少覆盖：

1. A 上传、切 B 列表/自动匹配/手动选择/预览均可用；第三方租户不可见。
2. B 无副本，B1/B2/B3 并发只产生一次到 B 主账户的 URL 上传，随后 native_share；B4 后续只共享。
3. B 主账户是目标、B 已有历史合法来源、目标已有有效副本、同名异内容、同内容不同上传记录。
4. 双通道 API/MCP，源/目标不同授权，撤权、绑定代数变化、冷却、超时未知、任务重投及工作进程中断。
5. 视频和 IMAGE 封面贯穿到广告创建素材参数；未知或失败不会冒充素材 ready。
6. 预览、目录、切换均零写操作；上传中切换不重定向批次；缓存和游标不跨租户。
7. 旧 head 升级保留历史数据；新跨 BC 记录可写，跨租户/错账户/错路由受约束；不兼容降级拒绝。
