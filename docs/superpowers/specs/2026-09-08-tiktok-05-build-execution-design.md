# TikTok 自动化投放工具：广告搭建与执行设计

日期：2026-09-08  
状态：已于 2026-09-08 经用户确认；执行行为以本次已确认需求为准。  
范围：批量输入、自动准备、搭建预览、创建即启用、后台执行与失败恢复。

关联文档：[总体设计](2026-09-08-tiktok-00-overall-design.md)、[租户与账户](2026-09-08-tiktok-01-tenants-accounts-design.md)、[版权方与链接](2026-09-08-tiktok-02-provider-links-design.md)、[素材](2026-09-08-tiktok-03-materials-design.md)、[投放策略](2026-09-08-tiktok-04-strategies-design.md)。

## 1. 必须保持的业务行为

单次提交只能包含一个租户、一个 BC，以及该上下文授权范围内的目标账户。
版权方与投放策略可以选择；剧目名称和目标广告账户均通过批量粘贴输入。
不把剧目或账户输入替换为下拉选择器，不在解析后要求再次逐项勾选。
本批次全部有效剧目覆盖全部有效账户，生成完整的“剧目 × 账户”组合。
不使用旧 skill 中的滑动轮转、窗口编号、每剧 K 户或固定账户池。
用户提交的动作明确为“创建并立即启用”：三层创建请求都直接带 `ENABLE`。
回读只核查实际结果，不作为开启投放的门槛，不存在第二次启用授权步骤。
本模块不包含投放数据同步、经营分析库或创建后的自动调价策略。

## 2. 搭建页面与输入

本节业务规则保持有效；页面结构已在[前端体验设计 UI-03 / UI-11](2026-09-08-tiktok-06-frontend-experience-design.md)补齐输入、准备与调整、冻结预览三个阶段的布局、表格列、素材 Sheet、底部摘要、错误与版本状态，新增交互为本轮待评审草案。[可点击原型](../prototypes/2026-09-08-tiktok-workbench.html)可用于审阅核心流程。

页面显示当前租户和 BC，平台管理者操作时同时显示实际被管理租户。
运营依次选择版权方连接与策略，批量粘贴剧名，再批量粘贴目标广告账户。
剧名按行解析，保留输入行号和原始文本；去除空行，并报告重复输入。
同一版权方连接、应用和链接配置下解析到同一剧目时，合并为一个剧目目标，保留全部原始行反馈。
账户输入支持完整账户 ID 或完整账户名称；名称必须唯一命中才接受，不能按短后缀猜测。
重复账户只保留一个执行目标，在解析结果中显示去重数量和对应输入行。
解析结果直接进入准备明细，运营无需重新勾选已经粘贴的内容。
输入不改变当前租户或 BC，账户越界不能触发系统自动切换连接。
草稿可以修正剧名、删除输入行、调整素材或修改策略，然后重新生成预览。
删除某行是编辑草稿，不是通过隐藏勾选状态改变执行范围。

## 3. 自动准备与素材匹配

版权方模块按当前租户连接解析剧名、回查或获取推广链接及必要信息。
同名多版本、不同语种或不完整匹配需要在该行明确处理，不能静默取首个搜索结果。
取链可能涉及版权方创建渠道或链接，由独立准备任务记录结果，预览生成本身不重复取链。
素材匹配只在搭建时发生，做完整剧名字面包含，仅忽略大小写与剧名首尾空白，不使用别名、翻译或模糊规则。
素材库上传不要求归剧，搭建中的匹配或调整也不永久修改素材库归属。
匹配到多个输入剧目的素材在各剧预览中展示多剧命中提示，允许分别使用，不增加必须确认的阻断步骤。
运营可在预览前增减素材、检查文件与封面；默认文件名升序、素材 ID 稳定并列，按策略分组并保留尾组。
每份素材引用它实际已上传的源账户；上传账户由系统从当前授权账户中选择。
搭建页不要求运营配置统一源账户，也不假设本批素材都来自同一个源账户。
目标账户已有可用资产则复用；没有时生成源账户到目标账户的分发任务。
素材尚待分发可以显示为“待准备”，明确可用源资产或原文件上传路径；来源无权限时可使用租户内其他合法资产或保存的原文件，经官方 SDK 上传目标账户。所有合法路径均不可用才阻断，不静默更换素材内容。
素材分发和广告创建使用官方 Python SDK，具体字段、资产可用性和平台限额由联调验证。

## 4. 预览内容与部分提交

预览先展示租户、BC、版权方、策略版本、剧目数、账户数和预计三层对象数量。
明细按剧目展开账户与素材组，显示推广链接、Minis/Identity、预算、目标 ROAS、文案和完整名称。
每个“账户 × 剧目”单元明确显示可提交、待素材准备或阻断状态，并能查看原因。
仅剩可执行素材分发步骤的单元可以提交；版权方信息未就绪或不存在合法素材分发路径的单元必须列为排除项。
全部有效剧目和账户先形成笛卡尔积，再逐单元检查，不因某一失败项重新分配其他账户。
如部分单元无法搭建，页面集中列出被排除的剧目、账户或组合、原因及数量变化。
允许提交已具备条件的部分，按钮明确显示“创建并立即启用 X 个 Campaign / Y 个 Ad Group / Z 条 Ad”。
预计预算按实际提交的 Campaign 汇总显示，并标明是各 Campaign 日预算之和，不是预计实际消耗。
排除项不会在当前批次自动补入，修复后通过新的预览明确提交原先未提交的剩余组合；系统不将已提交组合自动带入补建预览。
全部单元阻断时禁用提交，保留可操作的问题列表。
不通过新的账户选择器或二次勾选来确认这些已解析结果。
已提交范围不能因后台新到素材、推广链接变化或策略更新而扩大。

## 5. 不可变预览与数据持久化

以下实体、状态名和接口路径属于本稿工程建议，供文档审阅时核对边界。

`BuildDraft` 保存可编辑输入、策略引用、匹配关系与草稿版本。
`BuildPreview` 保存草稿版本、内容摘要、批次号、统计、已解析的策略配置和生成时间。
`BuildUnit` 按“目标账户 × 剧目”逐条持久化，保存链接、资产引用、就绪结果及排除原因。
`PlannedGroup` 保存素材顺序、组号和内部素材 ID 集合；`PlannedAd` 保存 SP 序号、名称、文案与 CTA 配置。
`Submission` 引用一个已冻结预览，记录提交人、租户、BC、请求幂等键和提交范围。
`ExecutionStep` 保存对应单元的步骤、远端 ID、尝试次数、错误类别和回读证据。
预览和执行按单元分页读取，后台分批准备；不把全批次全部参数塞进一个巨大 JSON 字段。
不可变快照可以由多张带版本的记录共同组成，不要求单个大文件或大响应。
随机文案保存条目 ID 和正文；命名保存最终字符串，不在执行时再次随机或计算日期。
提交前比较草稿版本与预览版本；草稿已改动则要求重新生成预览。
修改已提交内容必须产生新预览和新提交，不能原地修改已有远端 ID 所对应的执行意图。
原参数下恢复已提交批次的失败步骤，始终使用原 Submission；修改参数后再次创建属于新批次，预览明确提示对应组合已有的创建结果。

## 6. 提交权限与幂等

提交时校验操作者权限、当前租户、BC、全部实际提交账户、版权方连接、策略版本及素材可见性；已展示的排除项不阻断其余合法单元。
worker 领取任务后再次验证权限，避免排队期间权限撤销仍继续写入。
权限失效时暂停受影响单元尚未执行的步骤，不改变已创建广告的启用状态，也不切换到其他租户凭据或其他 BC 继续执行。
前端首次提交生成请求幂等键；同一键重复请求返回同一个 Submission。
服务端对同一已确认预览限制创建一个 Submission，防止网络重试换键后重复建批次。
每个执行步骤有稳定键，包含提交、单元和步骤定位；worker 重复领取只恢复该步骤。
批次号与最终名称一起冻结，用于远端核查，但不把名称当作唯一可靠的幂等机制。
用户主动再次投放同样剧目和账户时，必须新建预览与批次号，形成可区分的新提交。

## 7. 官方 SDK 与执行职责

执行模块直接调用官方 Python SDK 已提供的能力，不另造 HTTP 客户端或 MCP 接入实现。
已核实 SDK 覆盖 Smart+ 三层 create/get/status、素材上传与共享，以及授权资产发现。[官方 Python SDK](https://github.com/tiktok/tiktok-business-api-sdk/blob/main/python_sdk/README.md)
系统只保留业务参数转换、租户凭据选择、权限校验、限流、编排、日志和结果持久化。
SDK 能调用接口不代表当前租户拥有相应权限；每个单元仍须校验实际账户与资产。
具体 Minis 请求字段、CTA 组合和平台限额以后续联调为准，不能把历史实测数字写死为通用限制。
分页读取、分批调用和并发配置依据已验证接口能力与返回错误调整。
日志记录必要请求摘要、远端 request ID 和错误类别，凭据、Cookie、token 不进入业务日志。

## 8. 创建顺序与立即启用

每个执行单元先完成必要的目标账户素材分发、回查和封面准备。
按需要准备 CTA 资源，并保存其远端 ID，复用当前单元已成功完成的准备结果。
随后创建 Campaign，创建请求明确为 `operation_status=ENABLE`，成功后立即保存 Campaign ID。
逐组创建 Ad Group，同样直接为 `ENABLE`，保存各组 ID 后继续创建该组 SP 广告。
每条普通 Smart+ Ad 的创建请求直接为 `ENABLE`，成功后立即保存 Ad ID 和使用的目标素材映射。
对象成功创建后即可按 TikTok 实际状态参与投放，后续组或广告可能仍在创建。
回读分层核查对象、名称、参数、素材集合、操作状态和审核状态，只记录实际结果。
执行流程不先创建 DISABLE 对象，也不安排“验收后统一激活”的阶段。
若回读显示状态不是 ENABLE，标记差异并显示平台原因，不把异常写成成功启用。
平台审核中、已启用和已开始消耗是不同概念，本模块不能凭创建成功声称已经消耗。
任一后续步骤失败时保留已成功的结构与广告，不自动回滚或关闭已开始投放的成功部分。
空 Campaign 或未完整组保留在结果中说明原因，不自动清理；后续可对缺失步骤续建。

## 9. 状态与失败恢复

预览单元状态为 `READY`、`PREPARING`、`BLOCKED`；PREPARING 仅表示存在已核实的合法素材分发路径，剩余分发可在提交后执行。READY 与 PREPARING 均可提交；链接未就绪、所有素材分发路径均不可用或必要权限不明为 BLOCKED。
提交状态为 `QUEUED`、`RUNNING`、`COMPLETED`、`PARTIAL`、`FAILED`、`NEEDS_REVIEW`。
步骤状态为 `PENDING`、`RUNNING`、`SUCCEEDED`、`RETRYABLE`、`FAILED`、`UNKNOWN`。
`COMPLETED` 表示计划创建步骤已完成且实际结果已核查，不代表审核通过或发生消耗。
部分成功且存在确定失败为 PARTIAL；远端写入结果无法确认或回读存在参数/状态差异时为 NEEDS_REVIEW，并保留已成功数量。
网络超时、连接断开或进程在返回后落库前终止，都可能意味着远端已经创建。
此类创建结果标为 UNKNOWN，先依据已知 ID、精确最终名称、账户和父级关系回读。
核实已创建则补存远端 ID 并继续缺失步骤；确认未创建后才允许再次调用 create。
回读仍无法确定时保持待核实，不能因超过等待时间便认定不存在并重放。
限流或明确可重试的失败使用延迟重试，保留冻结参数，只重试失败步骤。
权限、素材不可用、场景不支持等确定业务错误不无限自动重试，向运营展示可修复原因。
“重试失败项”保留成功 ID、原批次号、名称、素材分组和文案，不重建整个 Campaign。
Celery 负责任务调度，业务步骤使用数据库执行租约防止并发重复写入；过期 RUNNING 写入步骤进入核查，不直接退回 PENDING 重放。
素材分发与广告创建分别记录进度，避免将素材共享失败误报为广告创建失败。

## 10. 必要接口与进度

| 接口 | 职责 |
|---|---|
| `POST /api/tenants/{tenant_id}/build-drafts` | 创建当前租户、BC 下的搭建草稿 |
| `PATCH /api/tenants/{tenant_id}/build-drafts/{id}` | 更新批量输入、策略和本次素材调整 |
| `POST /api/tenants/{tenant_id}/build-drafts/{id}/prepare` | 解析剧目/账户并启动明确的版权方准备任务 |
| `POST /api/tenants/{tenant_id}/build-drafts/{id}/preview` | 冻结配置并分页生成可审阅单元 |
| `GET /api/tenants/{tenant_id}/build-previews/{id}/units` | 分页查看计划、排除项及具体参数 |
| `POST /api/tenants/{tenant_id}/build-previews/{id}/submit` | 以幂等键提交创建并立即启用 |
| `GET /api/tenants/{tenant_id}/submissions/{id}` | 查看各阶段数量、实际远端 ID 与异常 |
| `POST /api/tenants/{tenant_id}/submissions/{id}/retry` | 仅恢复符合条件的失败或缺失步骤 |
| `POST /api/tenants/{tenant_id}/submissions/{id}/reconcile` | 对 UNKNOWN 及状态差异发起只读核查 |

进度按已准备素材、Campaign、Ad Group、Ad 和待核实步骤分别显示，不能仅显示一个百分比。
结果保留计划数、提交数、成功数、失败数、排除数与待核实数，并能按剧目或账户定位。

## 11. 验收示例

- 输入 2 部剧、3 个账户：先形成 6 个单元，正常情况下每剧都覆盖这 3 个账户，不进行轮转。
- 两剧各有 23 份素材、每组 10 份、创意数量 2：总计 6 Campaign、18 Ad Group、36 Ad。
- 某剧在一个账户上 Minis 不可用：预览明确排除该组合及原因，其余 5 个单元可提交。
- 素材来自两个系统自动选择的上传账户：分别记录源账户并分发，不能把全批来源改成一个默认账户。
- 双击提交或 HTTP 重试：只产生一个 Submission，同一预览不生成重复广告。
- Ad 创建超时但远端已成功：回读补存 ID，不再调用该 Ad 的 create。
- 回读无法确认超时结果：界面保持待核实，其余无依赖单元继续执行，不盲目重放。
- 某组 SP2 失败：保留该组 SP1 和其他成功广告，续建只处理 SP2，文案和名称保持不变。
- 三层 SDK create 请求直接为 ENABLE；回读前后都没有等待人工启用或统一激活的任务。
- 运行期间素材库新增文件或策略被编辑：当前批次的素材、预算、ROAS 和文案保持冻结值。
- 用户只拥有当前租户权限时，粘贴其他租户账户返回明确排除或阻断原因，不能用平台凭据兜底。

## 12. 执行任务页面交互草案

本节为本轮新增、待用户评审的前端交互草案；前文已确认的执行规则、输入与预览行为保持有效。
页面编号固定为 UI-04「搭建任务」和 UI-12「任务详情」；UI-03「新建搭建」与 UI-11「搭建预览」由对应页面设计定义。
UI-04 路由为 `/tenants/:tenantId/build-tasks`，以 `bc_id` 保存列表范围；UI-12 路由为 `/tenants/:tenantId/build-tasks/:submissionId`，使用任务自身的租户和 BC 绑定。
本节只呈现已有提交、重试、核查与权限失效后的暂停行为，不新增主动取消、关闭成功广告或重新激活入口。

### 12.1 共同布局与状态表达

- 桌面浅色、紧凑 shadcn 风格；建议以 1440px 宽设计，兼容 1280px，正文以表格为主，不用大面积仪表盘卡片。
- 左侧固定导航依次为：广告搭建、搭建任务、素材库、投放策略、账户与授权、版权方连接、成员管理；成员管理只向管理员显示，本组页面高亮「搭建任务」。
- 顶栏显示当前租户和 BC。任务详情另固定显示任务所属租户与 BC，不能因切换顶栏而把原任务结果呈现在另一上下文。
- 切换租户或 BC 时回到新上下文的任务列表，清理旧查询与选择状态；浏览器后退需重新校验访问权限。
- 标题、表格和操作区优先呈现剧目、账户、素材准备、创建结果和处理建议；不向运营展示 SDK、队列、worker 或内部重试算法。
- 状态同时用文字与颜色表达：排队中/进行中为蓝灰，已完成为绿色，部分失败为橙色，全部失败为红色，待核实为橙色描边及明确原因。
- 「已完成」只表示本次已提交范围创建和核查完成；有排除项时并列显示「另有 X 个排除组合」，不能写成全部输入均成功。

### 12.2 UI-04：搭建任务列表

标题区左侧为「搭建任务」及说明「查看创建进度并处理异常」；有 `build` 权限者在右侧看到「新建搭建」，跳转 UI-03 的 `/tenants/:tenantId/builds/new` 并保持租户和 BC。只读成员不显示新建入口。
标题下是一行状态快捷筛选「全部 / 排队与进行中 / 需要处理 / 已完成」。需要处理包含 PARTIAL、FAILED、NEEDS_REVIEW，不能把仅有预览排除项的已完成任务当作创建失败。
第二行提供搜索框、提交日期和版权方筛选；搜索提示「任务编号、剧名或账户」，账户 ID 按完整 ID 匹配，文本按字面包含检索。
日期默认最近 7 天，可改为最近 30 天或自定义日期；筛选由服务端执行，任一筛选改变都回到第一页。

| 列 | 展示与交互 |
|---|---|
| 任务 | 批次短编号为详情链接，下一行显示提交时间；完整编号可复制 |
| 状态 | 中文状态标签；异常时附一条最优先原因，不用最终 Ad 数量推算状态 |
| 剧目 / 账户 | 冻结范围内去重剧目数、去重账户数；版权方与策略版本作为次要文字 |
| 创建结果 | 主行「已创建 X / 已提交 Y 条 Ad」；次行分别列 Campaign 与 Ad Group 的已创建/已提交数 |
| 异常与排除 | 「失败 X 个对象」「待核实 Y 个对象」「排除 Z 个组合」，每项可跳到详情对应筛选 |
| 提交人 | 任务提交人名称；保留平台管理者代管时的实际操作者信息 |
| 最近更新 | 业务进度最近更新时间，悬停显示完整时间；不伪装成实时投放数据 |
| 操作 | 仅「查看详情」，恢复操作统一在详情执行，避免列表中跨任务误点 |

失败/待核实对象数为三级广告对象计数之和，排除数为账户×剧目组合数，列标签始终标明单位。
列表按提交时间倒序、任务 ID 稳定并列；服务端游标分页，默认每页 50 条、可选 100 条，提供上一页/下一页，不用当前页长度推算总任务数。
进入详情再返回时恢复搜索、筛选和当前游标；分页期间新任务通过「有新任务，刷新查看」提示进入首屏，不让当前行突然跳动。
默认不提供多选框、批量重试或批量停止，防止把不同任务的冻结范围混在一次操作里。
无任务显示「还没有搭建任务」，有 `build` 权限者显示「新建搭建」，只读成员只显示说明；筛选无结果显示「没有符合条件的任务」与「清除筛选」，两种空态分开。
加载时保留筛选区并展示表格骨架；刷新失败保留上次结果并标注最后更新时间，提供重试读取，不重复提交任务。

### 12.3 UI-12：任务详情

页面上方为返回任务列表、批次编号、任务状态与最近更新时间；右侧提供「查看提交预览」，打开该任务的只读冻结版本。
元信息行显示租户、BC、版权方、策略版本、提交人和提交时间。任务范围及预算取提交时冻结值，不跟随策略后续修改。
日预算显示为「已提交 Campaign 配置日预算合计：币种 + 金额」，旁注「不代表实际消耗」；不增加消耗、收入、ROI 或财务报表卡片。
元信息下用一张紧凑计数表展示各层，不只展示单一完成百分比。

| 对象层级 | 计划 | 已提交 | 已创建 | 失败 | 待核实 | 待处理 | 排除 |
|---|---|---|---|---|---|---|---|
| Campaign / Ad Group / Ad 各一行 | planned | submitted | succeeded | failed | unknown | pending | excluded |

每行满足「计划 = 已提交 + 排除」和「已提交 = 已创建 + 失败 + 待核实 + 待处理」。素材准备、CTA 准备和结果核查在独立阶段进度行展示，不加进三级对象计数。
已创建对象的参数或操作状态差异单列为「结果差异」，触发任务待核实；该对象仍计已创建，不能同时计入创建结果未知。
计数下方是场景提示与动作区，按钮携带实际可处理的步骤数量，并由服务端返回权限及可处理条件。

| 当前情况 | 提示和入口 |
|---|---|
| 排队或进行中 | 展示正在准备素材、创建对象或核查结果的实际阶段；其他组合持续执行 |
| 全部已提交对象成功 | 显示「本次提交已完成」；保留三层远端 ID、平台状态和全部操作记录 |
| 部分确定失败 | 显示「已创建部分保持现状」，提供「重试失败步骤（N）」；只恢复原参数下可重试的缺失步骤 |
| 全部确定失败 | 展示首要原因与修复入口；有可重试步骤才开放重试，需修改参数时说明需生成新预览 |
| 创建结果未知或存在差异 | 提供「核查待核实项（N）」；明确「先确认是否已创建，避免重复创建」，不把核查称为启用 |
| 失败与未知同时存在 | 整体优先显示待核实；两类动作分开，失败重试不能包含未知步骤 |
| 权限失效 | 显示受影响账户、暂停原因和账户与授权入口；剩余步骤停止继续写入，已成功部分保持现状 |

核查与重试直接操作当前任务，不再弹出第二次启用确认。请求处理中禁用对应按钮；返回后提示「已安排 N 个步骤」，刷新进度，不提前宣称成功。
没有可处理步骤时不提供空操作；无操作权限但仍有读取权限时隐藏对应动作、展示原因并保留已有结果。若读取权限也失效，显示无权访问并返回当前可访问列表；401 重新登录，403 保持登录且不循环跳转。

### 12.4 详情明细、分页与问题定位

内容区使用「搭建明细 / 异常与待核实 / 排除项 / 操作记录」四个页签，默认进入搭建明细；从列表异常数字进入时携带相应页签和筛选。
搭建明细按账户×剧目一行，每行列出剧名、账户名称及完整 ID、素材准备状态、Campaign 名称及 ID、Ad Group 已建/提交、Ad 已建/提交、当前结果和「展开」。
展开一行后分页读取素材组；每组可展开 SP1…SPN，列出冻结文案、素材缩略图、目标素材标识、Ad ID 与平台状态。页面不一次加载整个任务的素材和广告。
账户、剧目、阶段、创建结果筛选均由服务端执行，默认每页 50 个组合、可选 100；组、步骤、排除项和操作记录表格同样使用 50/100 页长。切换页签或筛选重置该页签游标，返回上一页签保留其筛选。
明细中的操作列只提供「查看原因」或「查看对象」；重试/核查仍从当前任务动作区发起，避免引入尚未定义的逐行批量选择接口。
异常与待核实页签按步骤展示剧目、账户、对象层级/组号/SP 序号、失败或未知原因、已知远端 ID、最近核查时间与建议动作。
点「查看原因」打开侧栏，使用业务语言展示发生了什么、已经创建什么、受影响的后续对象和如何恢复；不默认展示原始请求、令牌或内部堆栈。
排除项独立显示账户×剧目组合及提交前排除原因，不出现重试按钮；修复后去新预览明确提交原未提交范围，已有成功组合不会自动带入。
操作记录按时间倒序分页，显示提交、开始创建、创建成功、失败、发起核查、确认远端结果和权限失效等事件，以及操作者/系统标识；不包含凭据。
三级对象同时区分「创建结果」「操作状态」「审核/投放状态」，平台状态旁显示最后核查时间。尚未读取则写「暂未获取」，不能把 ENABLE 渲染为「已投放」或「已消耗」。
窄窗口将次要元信息折叠，表格容器横向滚动；固定剧名/账户定位列和表头，完整名称可复制，键盘可打开行和侧栏，状态含文字说明。

### 12.5 本轮 UI 评审样例

- 正常样例：2 剧×3 账户、每剧 23 份素材、每组 10 份、N=2，详情显示 6/18/36 的三层提交量；成功完成后没有激活按钮。
- 部分排除样例：计划 6/18/36、提交 5/15/30、排除 1/3/6；列表提示排除 1 个组合，不能将它写成失败 6 条 Ad。
- 部分失败样例：某组 SP1 已创建、SP2 确定失败；重试后 SP1 原 ID、原文案和操作状态保留，仅 SP2 的缺失步骤变化。
- 未知样例：SP2 请求断连，界面先提供核查；查到原远端 Ad 后补回 ID，不能通过普通重试再建一条。
- 混合样例：一个账户有确定失败、另一个账户有 UNKNOWN；任务显示待核实，两类动作的数量各自准确，成功结果持续可见。
- 权限样例：运行中某账户授权失效；展示暂停原因及已建结果，无主动取消、停止远端广告或换 BC 继续的按钮。
