# 图片与轮播广告：批量搭建设计

> 2026-10-29 第二次修订。用户要求重做设计和计划，本稿以批量工作流取代逐个配图的主流程。属于可评审方案，未实现；下述默认值由设计者建议，不冒称用户已确认或平台效果最优。

## 1. 目标、依据与方案选择

目标：几百张图片、多部剧、多账户，只配置一次规则即可生成有序轮播、配乐并进入既有批量搭建。人工只处理异常和少量内容调整。图片仍由用户手动上传。

已确认依据：

- [UI 调研](../../../../../docs/research/TikTok与BI4图片轮播交互调研-20261029.md)：TikTok 在创意内配置图片和音乐；BI4 在批量搭建组合区域配乐。TikTok 音乐 iframe 本轮未成功加载，不能宣称自动配乐已实测成功。
- [历史 API 实测](../../../../../outputs/cross-bc/20261027-image-carousel-probe/validation-results.md)第 7/8 章：新骏伯停用创建接受单图、三图 CAROUSEL_ADS，缺音乐拒绝；推荐至少 2 张，结果不稳定。35 张来自合同，边界尚未创建验证；审核与真实投放未验证。
- 现代码 `strategies/structure.py` 将有序素材包分配到广告组、基础广告，再按 `creative_count` 复制不同文案的广告；`previews.py` 会展平草稿素材组。**撤回上一版“一素材组对应一条广告”的描述。**

| 方案 | 收益与代价 | 决定 |
|---|---|---|
| 先逐个建图集，再搭建 | 复用方便，但上百张图片需大量手工配置 | 只保留为可选复用入口 |
| 整批规则 → 按剧生成 → 例外调整 → 原结构规划 | 匹配现有批量流程，能确定计数和重试内容 | 本稿采用 |
| 最大化图片排列组合 / 同批混视频图片 | 组合和预算容易膨胀，现 FIXED 组数、广告数语义需重做 | 不纳入本期 |

本期一份草稿选择 `VIDEO` 或 `CAROUSEL`；旧草稿按 VIDEO 迁移。一次图片批次可同时包含单图与多图，不能混视频。需要两类投放时分别建两个批次，预览各自预算；不能把两池分别跑同一策略后悄悄增加固定组数。可复用轮播不是批量搭建前置条件。

## 2. 用户主流程

```mermaid
flowchart LR
  A[批量上传原始图片] --> B[批量输入剧目与账户\n选择图片投放]
  B --> C[匹配并冻结本次图片候选]
  C --> D[整批图片规则\n按剧覆盖可选]
  D --> E[逐剧生成单图或轮播\n批量配乐]
  E --> F[异常汇总与局部调整]
  F --> G[现有广告组/广告分配\n文案复制]
  G --> H[具体预览与提交]
```

在现有“批量输入”添加投放素材类型；默认视频以保持现有行为。图片类型在“准备与调整”展示图片配置卡、全批进度和逐剧统计。切换类型不就地覆盖已编排草稿，提供“以另一类型新建草稿”，复用输入和策略选择，重新匹配素材。

图片配置卡不是租户设置。先看规则试算，再点“应用并生成”一次启动全部剧目的编排及配乐。规则有默认值，仍需该动作才写入生成结果。上传完成不会自动建广告。

### 2.1 一次填写的配置

| 配置 | 取值与建议默认 | 作用 |
|---|---|---|
| 图片组合 | 单图；顺序轮播（默认） | 单图 N=1；轮播 N=2–35 |
| 每轮播图片数 N | 默认 3，可修改 | 仅决定一个轮播包含几张图，不决定广告数 |
| 排序 | 自然文件名（默认）；上传批次与批内序号 | 每部剧分别排序，绝不跨剧拼图 |
| 尾部不足 N 张 | 保留为较短创意（默认）；本次不使用 | 尾部 1 张按单图配乐；不使用项必须在试算中列明 |
| 音乐 | 按轮播推荐（默认）；整批指定一首 | 推荐按轮播进行；统一曲按创意复制保存 |
| 单图用曲 | 推荐模式下可选一首批次用曲 | 只在实际出现单图时必需；没有则统一显示待配乐 |
| 广告结构 | 继承所选策略，可在本次覆盖 | 用现有 FIXED/BY_MATERIAL、SHARED/SEQUENTIAL_AVERAGE 规则 |

默认 3 张是编排便利值，不代表最佳投放效果。音乐不预填任何固定 ID。组合/配乐可按勾选剧目批量设置；按剧覆盖是字段级 patch，未覆盖字段跟随整批规则。“恢复整批配置”只清除该剧覆盖，仍需试算应用。

广告结构覆盖独立于图片规则，仅作用本次整批，不支持逐剧不同结构，避免预算语义和固定数失控；继承/修改原策略的整套结构字段，不并列创造另一套 M。图片页面把 `max_materials_per_ad` 标为“每广告最多创意单元 M”，把 `creative_count` 标为“每基础广告文案版本数 K”。FIXED 模式不展示无效的 M。

### 2.2 界面布局与例外

配置卡下显示“匹配图片 / 已编排 / 本次不使用 / 待处理图片；创意单元 / 已配乐 / 配乐失败；理论广告数 / 可提交广告数”。图片使用次数和去重图片数分列，复用图片不得混算。

逐剧表显示：剧名、规则来源（整批/有覆盖）、候选图片数、轮播与单图数、配乐进度、结构试算、问题数量。可筛选“待配乐”“有未使用图片”“有手动调整”。批量操作有：改规则、指定音乐、重试失败配乐、恢复整批规则。

点某部剧展开创意卡片：有序缩略图、张数、曲名、状态、是否手动保护。可以增删图片、排序、换曲、复制为另一个变体、将多个原图组合、将一个创意拆开。只改本次草稿。修改后显示变化，重新结构试算；不承诺原广告组编号不变。

手动设音乐保护 music 字段；手动改图片、顺序或增加创意保护 composition 字段。两种保护独立显示。默认重生成保留这些保护项，无需逐项重填。

在原单元内增删/重排图片保留已有曲，提示可重新推荐。复制继承原曲及其 music 保护状态，新副本保护 composition；合并/拆分生成新单元并进入待配乐，不猜选原曲。合并/拆分涉及受保护音乐时先返回冲突，用户解除相关保护或取消该操作后再继续。所有操作通过后端幂等修改接口验证，失败不留下半成品。

## 3. 确定性编排与计数

### 3.1 输入快照和排序

匹配先形成每剧候选快照，包含本地素材 ID、文件名快照、类型、上传批次/批内顺序、内容摘要以及来源。同 material_id 去重；同图跨剧可能命中时列入冲突清单，需明确分配或显式允许复用，不能自动跨剧重复投放。

自然排序由后端唯一实现：文件名 NFKC + casefold，ASCII 数字段按整数比较；同值用完整规范化文件名、原文件名、material_id 字符串打破平局。上传顺序使用已持久化的批次创建时间、批次 ID、批内序号、素材 ID；不得用并发完成时间。旧文件没有批内序号时试算给出提示并以该文件的持久化 created_at/id 排序。

候选快照不随新上传/重命名漂移。“刷新匹配”生成新快照和差异，等待应用；不自动把晚到图片加入正在配乐的结果。

### 3.2 生成规则

在每部剧内，从当前候选排除显式禁用图片、已由受保护组合/载入轮播占用的图片，然后按确定顺序切分 N 张。自动生成每张图至多使用一次；同图多创意只由明确复制/手工添加产生，试算显示复用次数。不得复制同一张图片凑数推荐音乐。

尾部保留时 `C=ceil(R/N)`，R=可自动编排图片数；尾部不使用时 `C=floor(R/N)` 并生成明确未使用记录。手动保留和载入创意另计。无图片不创建空创意；仅推荐失败不能自动丢创意。单个创意 1–35 图且内部不重复。

每个视频或完整轮播是一个 `CreativeUnit`。图片子项不直接进入结构规划器。沿用现有策略先分广告组，再分基础广告，最后乘文案版本 K；固定共享会有意复用整个单元，固定均分不足时报错，不能复制图补足。50 为已有单广告合同上限，实际还取冻结场景限制；创意单元不能在组/广告切片时被拆开。

示例仅在“1 个共享广告组、BY_MATERIAL 每广告 M=6、K=1、所有账户可用”下成立：60 图 / N=5 → 12 单元 → 每账户 2 广告 → 10 账户 20 广告。K=3 则 60 广告；2 个 SHARED 广告组、K=1 则 40 广告。最终数必须用真实规划器逐账户计算，不能只用 `图片数÷N÷M×账户数`。

保留现有单策略规划 10,000 条广告工程上限、固定广告组/固定广告数量各 100 上限以及场景限制；新增全批预计展开上限 10,000 条最终广告（设计建议，复用同一常量），跨剧/账户/文案版本先试算再分配对象。超过时提示拆批；这是资源保护参数，不是业务开关。

## 4. 批量配乐与失败处理

优先级：手动保护曲 > 该剧曲目/模式覆盖 > 整批模式。载入可复用轮播的音乐默认受保护。推荐模式只有多图调用推荐；单图使用该剧或整批的单图用曲。指定曲模式用显式选择的 music_id。缺曲不影响入库或保存草稿，但影响可提交预览。

推荐采用所选执行连接、BC 内已记录的可用种子账户及新鲜真实 image_url；不从其他 BC 借用。原图不满足推荐入口要求时记推荐不可用，可手动搜索选曲，不把推荐入口尺寸限制升级为入库限制。本期不自动裁剪/变换原图。

后台每个不同的有序图片组合只推荐一次，同批重复组合复用结果；键包含 tenant、BC、connection/binding generation、种子账户、推荐参数版本、有序图片内容摘要。按账户分发时不乘倍推荐。过滤缺 music_id 的条目，优先第一首正时长候选，写入实际曲目及展示快照；只有 0 时长候选时不自动选，提示搜索，不推断平台禁止该曲。

配乐状态：NOT_REQUIRED（视频）、NEEDS_SELECTION（单图无曲）、PENDING、RUNNING、READY、FAILED；推荐失败可手动改曲或“重试失败项”。多图图片改变后若已有曲，保留并提示“图片已变，可重新推荐”，不自动换曲；显式重新推荐才替换。name 为空用 file_name，试听 URL 过期重新读，不持久化为身份。

推荐任务按内容版本和 music_request_generation 栅栏写回；手动改曲、重生成、撤销绑定后，迟到结果不得覆盖。任务使用现有队列/outbox、准入限流和恢复机制，最多 20 个创意单元或 10 秒一片，遇服务限制采用已有有界重试；网络等待不持数据库事务。不把建议 worker 数写成固定配额。

界面分页显示，进度聚合查询；100 剧×100 图、N=5 时只生成 2,000 个推荐单元，而不是按所有广告账户展开。全部就绪后只对目标账户/曲目组合做可用性核验。

## 5. 修改规则与重生成

“修改规则”先保存候选规则并试算，不修改当前已应用创意。试算结果包括新增/删除/保留单元、受保护项、未使用图、待配乐项、广告及预算变化。后端返回 `plan_id`、输入摘要、expected_revision；“应用”只能提交该计划。

默认 `PRESERVE_MANUAL`：

1. composition 受保护单元保持内容及相对位置；其图片从自动输入中排除。未保护的旧单元用新规则替换，尾部策略重新计算。
2. 结果顺序为：受保护/手工载入单元按既有 position 在前，其后自动生成单元按排序；此顺序变化要在试算中可见，不偷偷维持旧广告编号。
3. 完全相同的有序图片组合复用原 creative_id；只在有效配乐规则摘要也未改变时复用未保护的已选音乐。批次指定曲 A 改 B、推荐改指定、单图用曲改变时，未保护项按新规则更新；受保护项仍保留。内容变化生成新 ID。只改曲目或图片顺序不复用历史执行身份摘要。
4. music 受保护、composition 未保护的旧单元，如果新切片中不再有相同有序图片组合，标为冲突并阻断应用。用户可一键“保留这些组合”（提升 composition 保护）或“解除这些曲目保护后重新生成”。不猜把旧曲分配给哪个新组合。
5. 手动删除自动生成单元时记录其图片的本次排除；再次生成不会复活。仅显式恢复候选才重新纳入。

提供独立 `REPLACE_ALL` 操作，可覆盖本次范围内手动创意/音乐保护，但必须在差异页明确列出损失并由用户选该操作；它不清除输入候选的显式禁用项。不是默认确认。

版本分工：用户规则、候选、内容和手工选曲修改增加 draft.revision；系统推荐进度/完成只增加单元 music_revision，不增加 draft.revision。试算摘要只绑定结构输入和配乐规则，不承诺尚未完成的具体推荐曲。应用事务在基准 draft.revision 未变时读取最新已完成曲目，仅对内容、有效规则和 music_request_generation 全部相同的单元继承；其余按新规则进入待配乐。迟到结果不直接跨 generation 写回，可作为同 fingerprint 的不可变结果供新任务核验复用。用户手工改曲一定使旧 plan 409；单纯后台配乐完成不使 plan 过期。冻结则绑定全部 music_revision 且要求 READY，在同一受锁快照内确认。

应用采用 request_id 幂等、expected_revision 乐观锁和新 generation。异步大批生成在暂存 generation 中按片写入，全部结构生成完成后一次原子切换 active_generation；失败/取消保留旧 active_generation，不能半批更新。配乐可在新 generation 激活后异步进行，未 READY 时只允许存草稿。一个草稿同时只有一个待应用生成任务；编辑与应用冲突返回 409 并刷新差异。

冻结前要求“当前规则已应用、没有生成中的切换、未解决跨剧冲突、未配置音乐、待处理图片”为零；显式排除项可继续但在预览列出。不允许悄悄把有错的剧目从整批删除来变成可提交。

## 6. 结构、执行与报表边界

原始素材文件不绑定音乐。新增创意单元及有序子项；库中可复用轮播保存不可变版本，载入时复制为受保护单元，不再同时自动使用其成员图。可在新批次复制上一批图片规则，但指定曲目只作为候选重新核验，不设租户默认曲。

按顺序：候选快照 → active_generation 创意 → 结构规划 → 冻结全内容与账户范围 → 用户提交。音乐/图片准备是内部资源工作，用户界面不展示 SDK/MCP 字段。

`VideoCreative` 保留视频与封面；`CarouselCreative` 包含主图有序引用和 music_id。CAROUSEL_ADS 请求不含 video_info，image_info 是主图；视频封面逻辑不适用于图片。media_kind 和编译合同版本进入场景 scope/缓存身份，不能复用视频资格作为轮播资格。场景能力读回不支持或未验证时明确阻断相应账户，不自动退视频。

图片单元具有原子性：一个轮播内任何图片不可用，不能删除该图后发布剩余图片。新图片广告默认整条广告校验原定所有单元，缺图/缺曲导致对应账户广告失败，不自动缩减单元数。其他账户和独立广告可继续。视频既有可跳过素材规则保持；预览已知失败按原原因列出并排除该广告，冻结后新失败只标失败，不能悄悄改正文。

多单元广告的真实创建回读尚需联调；未通过之前阻断多单元轮播广告的发布验收，不能自动降成一个单元改变数量。执行前按目标账户核验同一曲目，缓存只用于当前执行尝试；新恢复尝试重新核验。已 REQUEST_ARMED 的步骤仍走现有 UNKNOWN 协调，不因音乐读失败重发或换曲。

冻结包含 tenant/BC/connection/binding generation、creative_id 与版本、ordered material IDs/内容摘要、music_id/选择来源、策略与覆盖、文案复制、账户排除及预算。所有目标账户复用同一编排和曲目；目标 image_id 各自分发回读。授权/原始文件/主图不可用分别报告。

报表最小上线要求：广告级消耗收入继续可见，格式和冻结创意链接可识别。只提供真实返回粒度，不把广告收入复制给每张图或每个单元；图片素材自动控损暂不接入，明确标“图片创意暂不支持素材级自动规则”，广告/系列级既有规则按其现有范围工作。后续取得只读报表证据再增加精细粒度与素材规则。

## 7. 持久化与迁移合同

具体新增类型/接口由阶段计划定义；以下业务边界不可省略：

- MaterialFile 增加 VIDEO/IMAGE；AccountMaterial 的可用主资产按类型约束；IMAGE 无视频 duration、不生成封面任务。内容去重包含类型。图片上传、推荐输入、广告使用三种校验独立；上传上限先查合同并实测，不能沿用旧稿推荐接口的 50 MB/尺寸当作平台上传规则。
- BuildDraft 增加 media_kind、active_image_generation、applied_image_rule_revision 和本次 structure_override；整批 image rule 和逐剧字段 patch 独立存，不修改租户/策略版本。
- 新建 ImageCandidateSnapshot/Item、ImageCompositionRun（状态、游标、plan 摘要、基准 revision、generation）、DraftCreativeUnit/Item（有序引用、内容版本、两类保护）、MusicSelectionJob，以及 CarouselPreset/Version/Item。唯一键、外键带租户与 BC 范围；图集引用不绕过现有租户素材库权限。
- 文件名和策略不作为实体身份；创意 ID 与原始 material_id 不共用主键空间。结构规划器统一改接 `unit_id`，输出同样有序单元；视频一素材一个单元。相关计数、查询及 API 明确区分 unit/image/ad/copy。
- 本次不增加部署级业务开关。图片业务入口由 media_kind 和数据状态约束；阶段 1/2 可合并验证，不能在阶段 3 合同未就绪时把半成品发布为可投广告。
- Alembic 分阶段新增迁移，开工时分配实际 revision，不预占编号。未冻结视频草稿迁成一文件一单元、保留原顺序与 request_id；新算法不改变视频结构结果。
- 历史已冻结正文、哈希与 request_id 不重写。新预览使用显式 V2 合同；迁移发布前旧可执行任务必须正常排空，仍有无法终结的旧任务时中止切换，不强改状态。旧 V1 已冻结但未提交的预览切换后只能历史查看；不改原冻结正文，提交门槛返回 preview_contract_expired，要求从草稿重生成 V2。已有提交 request_id 的幂等重放只返回原记录，不能重建任务。历史只读展示使用原冻结记录，不新增猜测型解码回退。旧表移除仅在引用审计完成后单独迁移；不能双写两套现行业务模型。
