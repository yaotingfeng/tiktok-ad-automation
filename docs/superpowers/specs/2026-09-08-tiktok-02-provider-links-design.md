# 版权方、剧目与推广链接功能设计

日期：2026-09-08。状态：已于 2026-09-08 经用户确认，作为实施计划依据。
上位约束：[整体设计](2026-09-08-tiktok-00-overall-design.md)。本稿只定义功能，不包含实施计划。

## 1. 目标与范围

本模块让租户使用自己的版权方账号，在批量搭建时查找剧目、获取推广链接及投放需要的归因信息。
首版接入网眼、嘉书；后续版权方通过适配器扩展，搭建模块使用统一结果结构。
本轮不包含版权方经营报表采集、收入同步、剧集下载或版权结算。

## 2. 已确认的业务决定

- 每个租户独立管理版权方连接；相同版权方在不同租户之间不共享凭据、可见应用或推广链接。
- 搭建时选择版权方及对应连接，批量粘贴剧名，不逐部选择剧目。
- 同一租户、连接、应用、剧目及推广配置，复用已有链接；先查，缺失时才创建。
- 自动解析成功的剧目直接进入预览；重名、多语种等歧义由用户处理，不能自动猜测。
- 无链接、无权限或解析失败的剧目保留异常信息，其余已就绪部分可以继续提交。
- 同一部剧铺到本批全部有效目标账户；取链结果可以供该剧的多个账户组合复用。

## 3. 页面与用户流程

### 3.1 版权方连接管理

管理员查看本租户连接列表、账号显示名、授权状态、已发现应用和最近验证时间。
新增连接时选择网眼或嘉书，填写该版权方要求的认证信息；验证后发现账号可访问的应用及渠道配置。
连接编辑不展示原始密码、会话或令牌；凭据更新后重新验证，已有任务保持原连接归属。
列表中的“重新验证”刷新登录与应用可见性；普通投手可以使用连接，但不能读取或修改凭据。

### 3.2 搭建中的搜剧与取链

1. 接收搭建页选定的连接、应用、批量剧名和本次推广配置。
2. 清理输入首尾空白与空行，保留原始行号；同一批重复输入合并并显示提示。
3. 逐行查询当前连接可见的剧目，返回剧目 ID、正式名称、语言及应用范围。
4. 唯一匹配进入取链；无结果或多个候选保留在异常列表，用户修正原输入或确认候选。
5. 按复用条件查询本地记录，必要时回查版权方；缺失时执行版权方创建流程。
6. 预览展示正式剧名、应用、链接、归因基础名及取链状态，不要求再次逐项勾选。
7. 已确认的搭建快照保存实际链接结果，后续执行使用该快照。

### 3.3 链接记录

记录页支持按版权方、连接、应用、剧名或剧目 ID 搜索，查看可复制的原始 URL 与归因名称。
链接可回查；本轮不提供批量改写既有链接或跨租户复制链接的操作。
版权方返回的配置与当前请求不兼容时，展示差异和影响范围，由用户调整本次配置。

## 4. 版权方协议边界

适配器接受明确的连接上下文，不读取进程级“当前账号”，不依赖 CLI 的全局登录切换。
现有网眼、嘉书 CLI 可作为协议与错误处理参考；服务中的会话必须按连接独立保存和刷新。
适配器负责账号验证、应用发现、剧目搜索、已有链接查询、缺失链接创建、结果回查和错误归类。
连接外部调用使用该版权方的协议；所有 TikTok 调用直接使用官方 Python SDK。

| 版权方 | 必须保留的差异 |
| --- | --- |
| 网眼 | 项目、推广链 ID、原始 Minis URL，以及版权方返回的广告系列归因基础名 |
| 嘉书 | 账号可见应用、账号渠道前缀、剧目渠道、链接生成与保存后的回查结果 |
| 后续版权方 | 明确应用范围、复用条件、远端唯一约束、归因字段及可回查方式 |

不得把某个版权方全局绑定到一个 Minis ID。应用与 Minis 信息随租户连接发现，并结合 TikTok 账户权限校验。
版权方提供的应用标识与 TikTok 广告侧 Minis 标识分别保存，未经核实不能视为同一个 ID。
网眼返回名称中的归因部分保持原样；不从旧 skill 推导 `s`、`c` 的业务含义或自行重建前缀。
本地参考文档中 `s` 表示推广链 ID、`c` 表示跳转集数；具体生成仍以版权方原始返回值为准。
嘉书现有 CLI 采用每个账号前缀下“一剧一渠道”的约束，生成、保存、回查是不同步骤。
同一嘉书渠道要求不同起播集数或其他互斥配置时，不承诺能够独立新建多条链接，也不静默覆盖已有配置。

## 5. 本版采用的补充规则：实体与接口

以下命名和结构是工程建议，不代表已经确认的页面字段或最终数据库表名。

| 实体 | 核心字段与职责 |
| --- | --- |
| ProviderConnection | 租户、版权方类型、账号显示名、凭据引用、状态、凭据版本 |
| ProviderApplication | 连接、远端应用 ID、显示名、渠道配置、已核实的 Minis 关联 |
| ProviderDrama | 连接、应用、远端剧目 ID、正式剧名、语言、最近查询信息 |
| PromotionLink | 租户、连接、应用、剧目、配置摘要、远端链接或渠道 ID、原始 URL |
| LinkAttribution（PromotionLink 内的值对象） | 原始归因基础名、不可修改部分、版权方元信息、回查时间 |
| LinkResolutionTask | 请求上下文、原始输入、步骤状态、错误分类、尝试记录与最终结果 |

本稿将 LinkAttribution 作为 PromotionLink 内的结构化字段保存，不单设归因表；链接与归因信息一起形成可追溯版本。
凭据只保存加密值或凭据存储引用，业务日志仅记录连接 ID 和脱敏错误。
连接和应用归属由服务端解析；请求体里的租户 ID 不能直接作为授权依据。

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| 验证连接、发现应用 | connection_id | connection_status、applications、validation_error |
| 批量解析剧目 | connection_id、application_id、lines | 原始行、唯一匹配或候选、错误原因 |
| 批量取得可复用链接 | 已确认的剧目 ID 列表、配置、request_id | task_id、各剧处理状态 |
| 查询任务结果 | task_id | 各剧原始 URL、归因信息、复用或创建来源、失败原因 |
| 回查单个链接 | promotion_link_id | 当前有效性、远端原始结果、配置冲突信息 |

搭建模块使用统一结果中的剧目身份、应用身份、原始 URL、归因信息和有效性，不解析版权方会话。
具体 HTTP 路径与客户端类型由整体 API 约定生成，避免两个模块各自定义取链结果。

## 6. 本版采用的补充规则：任务与幂等

单剧状态为 `pending → resolving → checking → creating → verifying → ready`；已有链接可直接从 checking 进入 verifying。
异常状态区分 `needs_resolution`、`blocked_auth`、`config_conflict`、`retryable_error`、`result_unknown` 和 `failed`。
批任务由各剧状态汇总为进行中、全部就绪、部分就绪或全部异常，不丢弃失败行。
复用键由租户、连接、应用、远端剧目 ID 和规范化推广配置摘要组成。
规范化只处理语义等价的配置表示；改变起播集数、渠道等有效参数必须形成不同请求意图。
复用键上的唯一约束或互斥任务防止本平台并发重复建链；同时按版权方真实远端约束防冲突。
嘉书等远端约束比本地复用键更窄时，使用连接、应用、渠道范围的串行检查，返回配置冲突。
远端创建成功但响应丢失时标记 result_unknown，先按剧目、渠道或已知请求证据回查，再判断是否重试。
每步保存远端 ID 和回查结果，重试从缺失步骤恢复，不从新建渠道重新开始。
无法安全确认远端结果时保留待核实状态，不把超时自动解释为“未创建”。

## 7. 错误与恢复

| 情况 | 行为 |
| --- | --- |
| 凭据过期 | 暂停该连接取链，提示管理员重新认证，其他连接继续 |
| 剧名无结果或不唯一 | 返回原始行与候选，不生成猜测链接 |
| 应用权限不匹配 | 阻止该剧就绪，显示连接与应用不兼容 |
| 已有链接配置冲突 | 展示现有与请求配置，不覆盖远端既有链接 |
| 链接已失效 | 回查后更新本地有效性，当前未提交预览重新校验 |
| 已冻结链接发生变化 | 不静默修改快照，标记受影响组合并要求重新生成预览 |
| 远端限流或暂时异常 | 由任务调度重试，保留进度和下一次尝试状态 |

## 8. 验收场景

- 两个租户使用同一版权方、相同剧目输入，各自使用独立账号、应用和链接记录。
- 十部剧分别铺到十个账户时，同配置取链按剧目复用，不为一百个组合重复建链。
- 两个并发批次请求同一链接，只有一个流程创建，其余复用已确认结果。
- 嘉书创建渠道后中断，恢复时只补生成、保存或回查步骤。
- 嘉书同一渠道收到不兼容起播配置，预览显示冲突且不覆盖已有配置。
- 相同剧名出现多语种结果时保留候选；用户确认后使用明确的远端剧目 ID。
- 网眼 URL、归因前缀，以及嘉书渠道与链接参数从远端结果到搭建快照保持完整。
- 一个连接失效或部分剧取链失败时，其余已就绪剧仍可提交搭建。

## 9. 跨模块约束

[策略设计](2026-09-08-tiktok-04-strategies-design.md)只能按版权方契约拼接名称，不能改写归因必需部分。
[广告搭建与执行](2026-09-08-tiktok-05-build-execution-design.md)负责冻结取链结果及对应版本，校验目标账户可用 Minis。
[素材中心](2026-09-08-tiktok-03-materials-design.md)以本次已解析的正式剧名检索文件，不反向修改版权方剧目记录。
数据库租户隔离、凭据保管、操作审计和任务公平调度统一遵循整体设计。

## 10. 前端交互补充草案，待本轮评审

本节对应 **UI-09 版权方连接**，补充列表、连接表单、链接记录与异常处理的呈现方式。前文已确认的取链复用、租户隔离和异常恢复规则保持不变。

### 10.1 页面位置与布局

租户工作台“版权方连接”入口打开 `/tenants/:tenantId/providers?tab=connections`。顶栏持续显示当前租户和 BC；版权方连接本身属于租户，不因切换 BC 被复制或改绑。
页面从上到下为标题及说明、Tabs“连接 / 链接记录”、筛选工具条、表格和分页。URL 使用 `tab=connections|links` 记录页签；不新增独立剧目选择中心或经营报表页面。
从搭建异常进入时可携带 connection_id、task_id 定位相关连接或本次取链结果，页头显示“本次取链结果”及回到来源草稿的入口。来源地址必须属于当前租户，不能通过任意返回地址跳转。
用户只浏览连接、应用与链接记录时读取本地已有状态，不自动重新登录版权方或创建渠道；明确的验证、取链和回查操作才交给现有业务流程执行。

### 10.2 连接页签

工具条为连接名称/账号标识搜索、版权方筛选（全部/网眼/嘉书）、连接状态筛选和“清除筛选”。管理员显示主按钮“新增连接”，投手/只读成员显示已有连接及业务状态。

| 表格列 | 具体内容 | 行操作 |
| --- | --- | --- |
| 连接 | 连接名称、版权方 Badge、账号显示标识；不显示密码/令牌 | 查看详情 |
| 验证状态 | 可用、待验证、需要重新认证、验证中或异常的文字状态 | 管理员可重新验证 |
| 应用 | “查看已发现应用”；详情 Sheet 内显示名称与应用 ID | 应用列表按连接分页 |
| 最近验证 | 已有验证时间，未验证显示“尚未验证” | 不将打开页面时间当作验证时间 |
| 操作 | 查看；管理员更多菜单内编辑连接、更新认证信息、重新验证 | 不提供批量覆盖既有链接 |

新增连接使用右侧 Sheet，分为“基本信息”和“认证信息”两区：连接名称、版权方类型、该版权方协议所需的账号与认证字段。只展示当前版权方支持的字段；认证字段标签来自已核实的接入契约，不让运营编辑原始 JSON 或 HTTP 参数。
底部固定“取消 / 保存并验证”。必填校验先在表单内完成；开始验证后 Sheet 显示“正在验证连接”，阻止重复提交。失败保留连接名称与账号显示信息，认证秘密字段清空；错误显示具体可恢复原因，不展示原始请求头或响应密钥。
编辑既有连接时，版权方类型与连接 ID 为只读，避免改变历史任务引用的含义；“更新认证信息”以空输入框接收新值，并显示“已保存凭据不会回显”。不把掩码星号当作真实密码提交。
保存成功后返回连接列表并保留原筛选，相关行显示验证中或实际结果。重新认证不清空历史链接；用户关闭 Sheet 后可以从行状态查看后台验证结果。

### 10.3 应用与连接详情

“查看详情”打开 Sheet，顶部为连接名、版权方、状态和最近验证时间，下方为“已发现应用”列表以及最近一次异常说明。
应用行包含应用名称、远端应用 ID、渠道前缀/项目等业务配置的可读摘要、已核实的 Minis 关联状态；长 ID 可复制。未知关联显示“待核实”，不能自动填入其他租户的 Minis。
连接详情可切到“该连接的链接记录”，定位 UI-09 的链接页签并带 connection_id 筛选。页面不要求投手重新确认每个已发现应用；搭建页继续选择明确的连接和应用。

### 10.4 链接记录与本次取链结果

历史链接工具条为剧名/剧目 ID 搜索、版权方连接、应用、链接状态筛选。本次结果模式额外显示任务范围说明，以及“全部 / 异常”筛选；显示的已就绪和异常数量来自任务摘要，不为统计下载全部明细。

| 表格列 | 历史记录 | 本次结果模式 |
| --- | --- | --- |
| 输入 | 正式剧名与剧目 ID | 原始行号、原文；已解析后补正式剧名 |
| 版权方与应用 | 连接名称、应用名称及语言 | 同左，未解析明确显示状态 |
| 链接状态 | 可用、已失效、待核实等实际状态 | 处理中、已就绪、待选候选、认证异常、配置冲突、结果待核实等 |
| 推广链接 | 单行截断的原始 URL，提供复制入口 | 就绪后同左；未就绪不提供无效复制按钮 |
| 归因信息 | 原始归因基础名，详情显示完整值 | 保留版权方返回的完整信息，不能在此编辑 |
| 操作 | 查看详情、复制链接；有权限者可发起明确回查 | 处理候选、查看异常或回到搭建，根据状态显示 |

长链接和归因名称只在列表视觉上截断，复制与详情始终使用原文。详情 Sheet 将“推广链接”和“归因名称”分为两个可复制字段，不拼成一个难以核对的字符串。
成功行没有勾选框，不要求运营再次确认。待选候选行打开窄 Dialog，固定显示原始输入，候选表列为正式剧名、语言、应用、剧目 ID，每行一个“使用此剧目”动作；不能批量猜测或默认选中首个候选。
选定候选后只有对应原始行进入后续取链，其他成功行保持原状。无结果的行显示“未找到剧目”，提供回到搭建修改原文入口，不要求维护全局别名规则。
配置冲突在详情 Sheet 使用两列“已有配置 / 本次请求”逐项展示差异；提供回到本次草稿调整的入口，不提供“一键覆盖远端链接”。结果待核实行显示原因和可执行的回查入口，不把网络超时呈现为“未创建”。
投手可以处理自己租户的候选与明确取链操作；只读成员只能查看和复制已有结果。管理员负责连接凭据；投手遇到认证异常看到“请联系租户管理员重新认证”，不会弹出凭据编辑表单。

### 10.5 加载、空白、异常与分页

| 状态 | 表现 |
| --- | --- |
| 连接为空 | 显示“尚未添加版权方连接”；管理员有新增入口，其他成员看到联系管理员说明 |
| 应用为空 | 区分尚未验证与已验证但无可见应用，分别显示相应原因，不将连接自动标为可用 |
| 链接为空 | 显示“尚无推广链接记录”；有 `build` 权限者可前往广告搭建，只读成员仅查看说明，不在空列表自动建链 |
| 筛选无结果 | 显示“没有符合条件的记录”和清除筛选 |
| 首次加载 | 保留表头和工具条，表体 Skeleton；不能先显示无记录再跳到结果 |
| 分页或重新获取 | 保留现有行，表格显示正在加载；当前页失败时显示重试入口和旧数据提示 |
| 401 | 跳转 UI-01 重新登录，保留合法内部返回位置；不把全平台登录失效当成版权方密码错误 |
| 403 | 当前角色无权操作，保留已登录工作台，显示错误并刷新可用动作，不跳登录 |
