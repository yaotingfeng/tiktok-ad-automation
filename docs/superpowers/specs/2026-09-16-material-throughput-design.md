# 素材集中入库与搭建吞吐优化

用户已确认：集中新素材、减少请求、提前准备封面、用足执行资源；不引入复杂租户公平系统，不保留新旧兼容/失败回退路径。

## 边界

- 所有身份、权限、源与目标 MID/VID/image_id 必须来自同租户/BC 的真实映射。UNKNOWN 请求只核实，不重发或改用另一种写入路径。
- 已有素材/在途任务保留实际来源；新素材使用 BC 持久化的主素材账户。首次选取当前冻结通道内已授权可用账户并固定，账户繁忙不再更换；明确失效时报告原因，不自动回退其他账户。
- 取消单源账户只能在途一项的业务容量规则，计数只统计；同一个文件的操作身份及发送锁保留。账户锁只覆盖短数据库事务，不覆盖网络。
- 视频入库后异步准备源封面，失败不撤销视频成功。源封面保存可验证图片和共享 MID。目标优先复用，缺项才分 VIDEO/IMAGE 拼批共享；共享后回读实际目标 ID，不复制源 ID。
- 20×10 仅合并已授权完整组合，不扩大目标；不足满批立即执行。已存在批读能力复用，不另写同类旧路径。
- 并发与 QPS 分开；不把本地值当上游合同。先测物理调用、执行槽及资源，再确定测试环境参数。没有真实证据不声称吞吐提高倍数。
- 正在上传的批次不重建、不迁移；生产环境不在本次范围。任何测试环境部署先完整备份及隔离恢复验收。

## 验收

真实 PG/Redis 覆盖同账户不同文件并发、相同文件幂等、主账户稳定、租户/BC/撤权隔离、未知请求不重复、满批/不满批与图片目标回读。外部请求在 SDK/MCP 传输边界使用严格回执，真实业务与模拟证据分开记录。
