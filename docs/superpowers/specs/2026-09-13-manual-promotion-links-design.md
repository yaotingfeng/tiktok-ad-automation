# 其他版权方与手动推广链接

用户已确认实施：保留「批量输入 → 准备与调整 → 搭建预览」。第一步保留剧名文本框，版权方增加「其他」及名称输入；次要入口「已有推广链接？批量添加」接收 Excel 剧名、链接两列，保存后只显示数量摘要。第二步复用现有剧目表，允许逐行补链。没有自动/手动模式选择，没有新版权方管理前置流程，没有页面合并。

## 数据与处理

- 每个草稿仍只有一个版权方范围。其他版权方按租户和名称建立本地资料范围，不存凭据、不登录、不伪造远端应用或验证结果；沿用现有关系表，明确标为 other/local，本地 application 标识只作数据命名空间。
- 输入行携带可选手动链接、外部剧目 ID、归因基础名。第一步可批量录入，第二步可补充。外部 ID 缺省时使用明确标识的稳定本地编号。
- 手动链接与自动链接分开记录来源；用户输入 URL 原样保存，格式与 Minis 目标检查不能替代版权方业务核验。仅支持当前 Minis 搭建可用的 HTTPS TikTok Minis 链接。网眼手动链接必须提供归因基础名，不能自动编造。
- 只有没有手动链接且支持自动取链的输入进入版权方任务，保持原始行号；other 缺链保留待补充状态。手动补链禁止旧版权方任务覆盖新输入，旧请求结果未知时不自动重发。
- 第二步修改采用现有草稿版本和幂等请求机制，清除该行旧绑定，保留其他剧目及手动素材分组；下一次准备读取新版本。准备期间不允许逐行补链，原有整稿编辑规则保持。
- URL、名称、来源和本地/外部编号保存在记录与预览中；既有广告与冻结预览不回写。TikTok 授权、账户、BC、素材、Mini 和最终提交检查不放宽。

## 验收

其他版权方无需连接即可保存/准备；缺链可原地补齐；已知版权方手动行不发起远端取链；混合行号正确；URL 无损；缺少网眼归因基础名明确提示；幂等重试、跨租户拒绝和冻结预览不变；原有三步、草稿箱、批量剧名和自动取链保持。
