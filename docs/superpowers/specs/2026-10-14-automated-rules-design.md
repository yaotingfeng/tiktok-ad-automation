# 自动规则(投后运营)设计

日期:2026-10-14
状态:待用户评审
关联:`docs/integrations/2026-10-13-tiktok-automated-rules-research.md`(TikTok 原生自动规则调研与 API 写入验证)、`2026-09-30-ads-management-reporting-design.md`(广告管理与批量操作)、`2026-10-12-ads-reporting-sync-redesign-design.md`(报表同步链路)、`2026-10-12-ads-reporting-workspace-redesign-design.md`(指标字典)

## 1. 目标与背景

TK-ADA 已覆盖投前准备、搭建和投后数据,缺少投后的自动运营规则。短剧投放是多账户大量铺剧,需要能一次性作用于多个账户、整个租户,并能按剧维度判断的规则,在指标达到阈值时自动暂停、启用、调预算、调 ROAS,或只发预警。

TikTok 原生自动规则只能按单个广告主设置。调研结论(详见调研报告第 10 节):

- 开放 API 对我们的账户**不能写入规则**。新骏伯 BC 子账户 `7683818840198987797`(归属代理商 BC「Max Engine Number 3」),授权用户在 BC 和账户上都是 ADMIN,`optimizer/rule/create` 仍返回 `40002`。网页后台可以正常创建,API 能读到网页创建的规则。这与文档「仅支持直客广告主」一致。
- 原生规则无跨账户、无剧维度、只覆盖账户最近 500 个广告,通知只发开发者邮箱。

因此 TK-ADA **自建规则引擎**:规则结构、条件、操作、频控、排期对齐 TikTok 原生规则;判断使用 TK-ADA 已同步的报表数据;执行复用广告管理任务通道;通知改为租户级飞书群机器人。

## 2. 范围

包含:

- 租户级规则,适用账户可跨 BC。
- 判断对象:每个对象、每部剧合计、所有对象合计;对象层级覆盖系列、广告组、广告、素材。
- 三种执行模式:自动执行、确认后执行、仅通知。
- 运行时冲突检测与通知。
- 租户级飞书 Webhook 卡片通知,确认在 TK-ADA 确认页完成。
- 规则列表、编辑器、试运行、模板、待确认、执行记录页面。

不包含:

- 调用 TikTok 原生规则接口创建或同步规则。导入网页已建规则为后续可选项,本期不做。
- 飞书自建应用、卡片按钮回调。
- 保存规则时的静态冲突检查。
- 跨租户规则;TK-ADA 未同步的指标(视频播放、商店事件、SKAN 等)。

## 3. 规则模型

一条规则由下列部分组成,保存为一个版本化对象。每次运行记录所用的版本快照。

### 3.1 适用账户

| 模式 | 含义 |
| --- | --- |
| 全部账户 | 租户下所有已接入 BC 的全部账户;每次运行按当时的账户目录展开,新账户自动纳入 |
| 按 BC | 选择一个或多个 BC;每次运行展开为这些 BC 当时的全部账户 |
| 指定账户 | 勾选的账户列表(可跨 BC) |

账户含多个时区时,编辑器提示时间周期按各账户自身时区计算。

### 3.2 应用至

- 对象层级:系列 / 广告组 / 广告 / 素材。
- 状态范围:投放中 / 已暂停 / 指定对象(勾选具体对象)。
- 指定对象:直接列出范围内该层级的对象(名称、账户、状态、ID),可筛选、全选当前结果、加载更多,打勾选择。
- 按名称过滤使用条件里的「名称」指标,应用范围不再单独设剧名、名称包含/不包含过滤框(2026-10-15 调整)。

### 3.3 判断对象(统计口径)

| 口径 | 判断方式 | 命中后的执行范围 |
| --- | --- | --- |
| 每个对象 | 范围内每个对象单独计算指标、单独判断 | 命中的对象(或其下级,见 3.5) |
| 每部剧合计 | 同一剧名在范围内所有账户、所有 BC 的数据合计后判断 | 该剧在范围内的全部执行对象 |
| 所有对象合计 | 范围内全部数据合计后判断 | 范围内的全部执行对象 |

剧名使用报表剧维度同一套解析逻辑(规范命名的系列名解析出剧名);跨 BC 按剧名合并。命名不规范、解析不出剧名的系列不参与「每部剧合计」,并计入运行记录的跳过数。

### 3.4 条件

- 最多 5 个,全部满足才触发(AND)。
- 每个条件:指标 + 时间周期 + 运算符 + 数值。
- 时间周期:今天 / 昨天 / 最近 3 天 / 最近 5 天 / 最近 7 天 / 投放以来;按各账户自身时区取本地日期。「投放以来」受报表库保留天数约束,实施时核实;不满足时本期不提供。
- 运算符:大于 / 小于 / 介于(开区间,两个值) / 等于。名称类为包含 / 不包含 / 开头 / 结尾 / 等于。
- 合计口径下,比率类指标用分子、分母分别求和再相除(如合计 ROAS = Σ收益 ÷ Σ消耗),不做平均。分母为 0 时该条件判定为不满足。

可选指标(以已同步数据为准,取自报表指标字典):

| 分组 | 指标 | 素材层级可用 |
| --- | --- | --- |
| 投放数据 | 消耗、展示量、点击量(目标页面)、点击率(目标页面)、千次展示成本、平均点击成本(目标页面) | 是 |
| 收益数据 | 广告展示总价值、广告收益 ROAS、第 0 天收益与 ROAS | 是 |
| 收益数据 | 第 2/6/13/29 天收益与 ROAS | 否 |
| 收益数据 | 广告展示事件总数、单次广告展示事件成本 | 是 |
| 对象属性 | 名称、创建天数、当前预算、当前 ROAS 出价 | 名称、创建天数 |

指标名称与单位以指标字典为准,前端不硬编码。

### 3.5 操作与执行对象

每条规则只有一个操作。

| 操作 | 支持的执行层级 |
| --- | --- |
| 暂停 / 启用 | 系列、广告组、广告、素材 |
| 调整预算 | 系列、广告组 |
| 调整 ROAS 出价 | 系列(现有投放结构;以广告管理现有 `roas` 变更支持的层级为准) |

执行层级必须在判断对象的范围以内:

| 判断对象 | 可选执行层级 |
| --- | --- |
| 每部剧合计 / 所有对象合计 | 范围内任意层级 |
| 系列 | 系列本身或其下广告组、广告、素材 |
| 广告组 | 广告组本身或其下广告、素材 |
| 广告 | 广告本身或其下素材 |
| 素材 | 素材本身 |

不合法的组合在编辑器中置灰,后端保存时同样校验。

调整类配置:

- 方式:提高 / 降低(金额或百分比)/ 调整至。
- 提高必须设上限,降低必须设下限;调整至直接给目标值。数值下限遵循平台约束与广告管理现有校验。
- 频控(同一规则对同一对象执行该动作的次数上限):仅一次 / 每 24 小时一次 / 每 48 小时一次 / 每周一次 / 自定义「N 分钟 | 小时 | 天内最多 Y 次」。
- 暂停 / 启用不设频控;对象已是目标状态时跳过。

素材启停的含义:在范围内所有使用该素材(同一平台素材 ID)的广告中启停该素材。广告中最后一个在投素材不能关闭,遇到时跳过并记录原因。

### 3.6 执行模式

| 模式 | 命中后 |
| --- | --- |
| 自动执行 | 直接执行,执行后发飞书执行结果卡片 |
| 确认后执行 | 生成待确认批次,发飞书待确认卡片,在 TK-ADA 确认页确认后执行 |
| 仅通知 | 只发飞书预警卡片,不执行 |

只有租户管理员能保存「自动执行」模式的规则;普通成员可保存其余两种。

### 3.7 运行排期

- 运行频率:30 分钟 / 1 小时 / 2 小时 / 4 小时 / 每天固定时刻。下限 30 分钟(报表热数据同步周期);判断对象或应用层级为素材时下限 60 分钟(素材报表同步周期)。
- 生效时段:持续 / 自定义(按天、周、月,最多 7 个时间段)/ 仅一次(到点运行一次,运行后规则自动关闭)。
- 运行时区:按账户时区(新规则默认)或按规则时区(租户设置)。按账户时区时,每天固定时刻与自定义时段按各账户自身时区解释,每个账户在当地时刻判断当地日期,不同时区的账户分批运行、分别通知;下一次运行取规则范围内各账户时区中最早的槽位,运行时只判断当地正处于该槽位的账户,试运行不分批。跨账户合计口径(每部剧合计、所有对象合计)需要同一时刻取数,与「仅一次」一样只能按规则时区。
- 按规则时区时,自定义时段按租户设置的时区解释。

### 3.8 通知设置

- 开关;发送时机:每次运行都发 / 固定时间汇总发送(可设多个时刻);是否在无命中时也发(默认否)。

## 4. 运行流程

1. **调度**:Beat 每 60 秒扫描到期规则;同一规则同一时间只有一个运行实例(数据库行锁或 Redis 锁,用真实 PostgreSQL/Redis 测试)。
2. **展开范围**:按规则版本展开账户和对象。
3. **数据新鲜度**:账户最近一次报表同步成功距今超过 90 分钟(素材 150 分钟)的,本轮跳过该账户并记入运行记录和通知。
4. **判断**:计算指标,得出命中对象;保存指标快照。
5. **执行计划**:展开到执行层级,计算动作。已是目标状态、被频控拦截、与其他规则反向冲突的对象标记跳过。
6. **冲突检测**(第 5 节)。
7. **执行范围**:规则作用于选定的全部范围,命中多少就执行多少;不设单次执行对象上限(2026-10-15 调整)。
8. **分流**:自动执行 → 第 9 步;确认后执行 → 生成待确认批次并通知;仅通知 → 通知。
9. **执行**:对命中对象做定向目录刷新,拿到最新状态和预算/ROAS 值后重新计算「执行前 → 执行后」,丢弃已不需要执行的对象;按所属 BC 拆分,生成广告管理任务,复用现有重试、对账、回读核对。调整幅度由动作必填的上限/下限与执行频率约束,不另设每日累计涨幅上限(2026-10-16 移除)。
10. **记录与通知**:写入动作台账、运行结果,发送结果卡片;广告管理操作记录标注来源「自动规则:规则名」。

确认后执行的确认:

- 打开批次时用最新数据重新判断,并排显示判断时与当前的指标值;已不满足条件的对象默认不勾选;状态已变化的对象跳过。
- 可部分确认、全部确认或忽略批次。
- 下一次运行开始时,该规则未处理的批次自动失效。
- 确认后进入第 9 步,补发执行结果卡片。

## 5. 冲突检测

只在运行时检测,不在保存时检查。以下情况视为冲突:

1. 同一轮运行中,同一对象被不同规则计划执行相反动作:暂停对启用、提高对降低,或「调整至」目标值不同。
2. 反向冲突:同一对象同一字段最近一次是被另一条规则做了相反动作,且那条规则按当前数据(忽略其作用状态)仍命中该对象——两条规则条件重叠,继续执行只会来回反复。对方规则已不命中(如延迟归因后 ROAS 回升)、已关闭、已删除或改为仅通知时,相反动作正常执行。2026-10-16 起替代原「反向冷却期」:固定时长的冷却会拦下关停后归因回升的正常启用,也会拦下启用后再次变差的正常关停。

处理:冲突对象上的冲突动作都不执行,发飞书异常卡片,写明涉及的规则、对象和各自动作。其他对象照常执行。仅通知模式的规则不参与冲突判断。

## 6. 飞书通知

### 6.1 租户设置

- 每个租户一个飞书群自定义机器人:Webhook 地址 + 可选签名校验密钥,使用现有 `core/credentials.py` 加密存储;页面只显示掩码。
- 「发送测试消息」验证可用后保存。

### 6.2 卡片

| 卡片 | 触发 | 内容 | 按钮(跳转链接) |
| --- | --- | --- | --- |
| 执行结果 | 自动执行或确认执行完成 | 规则名、命中数、成功/跳过/失败数、前 10 个对象的指标值与执行前 → 后 | 查看全部明细 |
| 待确认 | 确认后执行模式命中 | 待执行动作、有效期 | 去确认 |
| 预警 | 仅通知模式命中 | 命中对象与指标值 | 查看明细 |
| 异常 | 冲突、最终执行失败、因数据过期跳过账户 | 原因与对象 | 查看明细 |

### 6.3 发送

- 每条规则每次运行最多一张卡片;超过 10 个对象时截断,其余通过链接查看。满足飞书自定义机器人频率与 20KB 卡片体积限制。
- 固定时间汇总:到点合并该时段内的运行结果为一张卡片。
- 通过发件箱在事务提交后发送,失败重试,发送状态记入运行记录。
- 链接使用环境配置的公开站点地址。

## 7. 前端

位于侧边栏「投放工作」,在「投放策略」后新增「自动规则」。页面使用 shadcn/ui 与现行视觉规范,顶部标签页:规则管理 / 待确认 / 执行记录。飞书设置放在「租户管理」下的设置页。

### 7.1 规则管理

- 概览卡片(近 7 天):执行动作总数、暂停、启用、调预算、调 ROAS 次数,待确认批次数,失败/冲突数。
- 工具栏:新建规则、从模板新建;按状态、执行模式、操作、执行层级筛选;按名称搜索;批量开启/关闭/删除。
- 表格列:开关、规则名、条件摘要、操作与执行层级、执行模式、适用范围、运行频率、最近一次运行结果、创建人、行操作(编辑、复制、试运行、查看记录、删除)。

### 7.2 编辑器

右侧抽屉(约 60% 宽),卡片顺序:适用账户 → 应用至 → 判断对象 → 条件 → 执行操作(仅发送通知 / 暂停 / 启用 / 调预算 / 调 ROAS;改广告时再选自动执行或确认后执行)→ 运行排期 → 飞书通知 → 规则名称。底部固定「试运行」「保存」。

- 条件行的时间周期、运算符、单位随指标联动,不适用项隐藏;素材层级只列可用指标。
- 执行层级只列合法项;不支持的层级置灰并说明原因。
- 非管理员不显示「自动执行」。
- 未配置飞书时显示「去设置」。
- 试运行:当前数据下的命中数、按账户与剧分组的明细(指标值、计划动作、执行前 → 后)、被跳过的对象和因数据过期跳过的账户。不执行、不通知、不写动作台账。

### 7.3 模板

按投放生命周期预置推荐规则(2026-10-16 重做),阈值为示例值,用户按预算规模微调;全部默认仅通知。收益统一看第 0 天 ROAS;关停、降预算、降目标用昨天等已结束日期每天判断一次;单对象规则按账户时区运行;加预算以「对象自身预算 > 0」限定预算持有者。

| 场景 | 模板 | 运行 | 条件 → 动作 |
| --- | --- | --- | --- |
| 冷启动 | 新建不起量预警 | 账户当地每天 10:00 | 系列创建满 2 天且近 3 天消耗 < X → 仅通知 |
| 测试期 | 广告组止损 | 账户当地每天 10:00 | 创建满 2 天、近 3 天消耗 > X、第 0 天 ROAS < Y 且昨天 < Y' → 暂停广告组 |
| 测试期 | 低效素材淘汰 | 账户当地每天 10:00 | 近 7 天消耗 > X、第 0 天 ROAS < Y 且昨天 < Y' → 暂停素材 |
| 测试期 | 剧目测试不过线 | 规则时区每天 18:00 | 每部剧合计近 3 天消耗 > X、第 0 天 ROAS < Y 且昨天 < Y → 暂停该剧广告组 |
| 放量 | 优质广告组加预算(组预算) | 账户当地 08:00–18:00 每 2 小时 | 自身预算 > 0、昨天与今天消耗和 ROAS 均达标 → 预算 +30%,上限 Z,每 24 小时一次 |
| 放量 | 优质系列加预算(CBO) | 账户当地 08:00–18:00 每 2 小时 | 同上,系列层级 → 预算 +20%,上限 Z,每 24 小时一次 |
| 放量 | 高 ROAS 跑不动降目标 | 账户当地每天 10:00 | 创建满 3 天、昨天消耗在区间内且 ROAS 远高于目标 → 目标 ROAS −0.05,下限 1.0,每 48 小时一次 |
| 衰退 | 效果回落降预算(CBO) | 账户当地每天 10:00 | 自身预算 > 0、昨天消耗 > X 且 ROAS < Y、近 3 天 < Y' → 预算 −20%,下限 Z,每 24 小时一次 |
| 风控 | 单系列盘中异常消耗 | 每 2 小时 | 今天消耗 > X 且 ROAS < Y → 仅提醒 |
| 风控 | 全局日消耗超计划 | 每 2 小时 | 所有对象合计今天消耗 > X → 仅提醒 |

### 7.4 待确认与执行记录

- 待确认:批次列表(规则、时间、有效期);批次详情为对象勾选表,并排显示判断时与当前指标值。
- 执行记录:运行维度列表(规则、时间、检查数、命中数、成功/跳过/失败/冲突、飞书发送状态);下钻到对象维度(指标快照、动作、前后值、结果、原因),可跳转到现有操作记录。按规则、时间、结果、账户、剧筛选。

## 8. 后端

### 8.1 模块与队列

新增 `backend/app/modules/automation_rules`,不新增服务或队列。

| 环节 | 队列 |
| --- | --- |
| 到期扫描 | `control`(Beat 60 秒) |
| 判断与试运行 | `ads-reporting` |
| 定向刷新与执行 | `ad-management` |
| 飞书发送 | `control`(发件箱) |

### 8.2 数据来源

- 系列 / 广告组 / 广告指标:`ad_report_day`,按需向上汇总。
- 素材指标:`material_report_day`;素材与广告的使用关系:`ad_material_reference`。
- 剧名:与报表剧维度共用的命名解析。
- 对象属性与状态:`ad_object`(目录,约 3 小时刷新;执行前定向刷新)。

### 8.3 数据表

所有表包含 `tenant_id`,所有查询按租户隔离;命中对象记录 BC 与账户。

| 表 | 内容 |
| --- | --- |
| `automation_rule` | 规则定义各部分(JSON 字段按 Pydantic 模型校验)、开关状态、版本号、创建/更新人 |
| `automation_rule_run` | 规则版本快照、计划/开始/结束时间、状态、检查数、命中数、各结果计数、跳过账户、通知发送状态 |
| `automation_rule_hit` | 运行 ID、对象引用(BC、账户、层级、远端 ID、素材使用)、剧名、指标快照、计划动作、执行前后值、处理结果与原因、关联广告管理任务项 |
| `automation_confirmation` | 运行 ID、状态(待确认 / 已确认 / 已忽略 / 已失效)、有效期、确认人与时间 |
| `automation_action_ledger` | 规则、对象、动作、执行时间;用于频控与反向冲突判断 |
| `tenant_feishu_setting` | 加密的 Webhook 地址与签名密钥、启用状态 |

租户设置新增:自定义时段时区、暂停全部规则(反向冷却期与每日累计涨幅上限已于 2026-10-16 移除,迁移 `0036_drop_rule_safety_settings`)。

### 8.4 部署开关

新增 `AUTOMATED_RULES_ENABLED`,控制 Beat 是否调度规则运行和是否允许执行动作(试运行不受限)。按 AGENTS.md 要求在同一提交补齐 Settings、`.env.example`、启动注入与部署手册「功能开关清单」,首次发布前向用户确认取值。

### 8.5 TikTok 调用

执行全部经广告管理现有通道(官方 SDK / 已批准的 MCP 通道),受 `TIKTOK_CALL_POLICIES` 限流与配额约束;不新增自定义 HTTP 网关。

## 9. 分阶段实施

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| 1. 规则与预警 | 数据表与迁移、规则增删改查、判断引擎(全部层级、三种口径)、试运行、仅通知模式、飞书设置与卡片、规则管理/编辑器/执行记录页面 | 试运行结果与报表同口径数字一致;按排期收到飞书预警;不改动任何广告 |
| 2. 执行 | 自动执行、确认后执行、定向刷新、动作台账(频控与反向冲突)、冲突检测、待确认页、部署开关 | 在授权测试账户上真实完成暂停、启用、调预算、调 ROAS 并回读一致;冲突与频控按预期跳过并通知 |
| 3. 完善 | 素材启停执行、模板、固定时间汇总发送、租户「暂停全部规则」 | 模板可直接使用;素材启停真实验证 |

每个阶段单独写实施计划并独立验收。

## 10. 测试

- 单元测试:三种口径判断;比率指标分子分母求和;多时区「今天」;边界值与分母为 0;执行层级合法性;冲突检测;频控与反向冲突。
- 集成测试(真实 PostgreSQL、Redis):规则运行锁;确认与新一轮运行并发;执行任务重试;定向刷新后的重新计算。
- 外部依赖:TikTok 与飞书只在传输边界做替身;开发期间不做真实写入。
- 真实联调单独记录:授权测试账户上的真实执行、测试群的真实卡片。
