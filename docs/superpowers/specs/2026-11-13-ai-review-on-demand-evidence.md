# 复盘证据按需读取：最小实现

用户要求在当前仓库完成实现与本地验证，不做广告写入或生产部署。本设计落实已有权限、截止时间和成熟窗口合同，不引入新的平台读取或授权通道。

## 现状与选择

`reviews.frozen_evidence()` 在创建任务时组装报表、归因、历史和规则事实；原有输入预算会截断这些正文，且所有被冻结的 ID 都可引用。报表已有 `freeze_review_page()`，知识工具已有任务 JWT/fence、行锁、当前投手版本和账户授权检查。

本轮选择在 `DSHReviewTask` 新增私有 `evidence_store` JSONB，继续在创建时冻结业务事实，模型只收到摘要及目录。优点是无需改变报表版本/清理生命周期，之后读取不会混入实时发布；代价是任务创建仍需计算和保存详细事实，读取任务行时仍会加载该 JSONB。与复用短期 QuerySnapshot 相比，不受其 15 分钟有效期及清理影响；与新增规范化证据表相比，迁移和接入范围更小。

## 合同

- 初始业务输入：optimizer 范围与参数、账户 D0/D3/D7 独立窗口汇总（无 rows）、当前策略/规则版本及定义、冻结证据目录。仅保留现有方法/能力 Schema 与空的知识读取状态作为任务工具合同；不预载知识目录，知识和外部参考正文继续按需读取。
- 报表复用现有构建/快照/游标，账户、Campaign、剧、素材分别冻结；每账户/维度/窗口至多 5,000 行，超过明确 `rows_truncated`。其他来源保留原有有界采样及完整性标记，不声称无限历史。
- `tkada_query_evidence` 按分类查询元数据，每页 10 项；`tkada_read_evidence` 按冻结源 UUID、offset、limit 读正文，默认 1 项、最多 10 项。归因拆成精确映射、单窗口单行；历史列表按条分页。
- 目录不授予引用权限。初始已送达的账户汇总、成功返回的页、实际读取的知识和回测结果才可引用。每页记录源 ID、摘要、offset、limit；页 ID 绑定任务和完整源摘要，重读幂等。规则源 ID 仅在对应条目已读后允许回测。
- 任务身份依赖继续校验 JWT 的 tenant/optimizer/task/fence/expiry、租户写权限、投手启用状态。读取/回测/完成进一步复验当前 optimizer 版本及全部冻结账户授权；请求不能传入额外 BC、账户、日期或报表过滤器扩权。
- 所有正文从本任务私有冻结源返回，索引 ID 和摘要必须匹配；工具不重查当前业务报表。汇总、覆盖、成熟资格和窗口随报表返回；成熟不足或平台不支持时保持原状态。
- 当前投影不能重建 cutoff 前的任意历史状态。创建任务时若报表观测晚于 cutoff，明确返回 UNAVAILABLE，不把未来数据作为上下文；经营和操作日志同样增加截止过滤。
- 单工具响应至多 64,000 字节；读取账本受任务 512,000 字节预算及 1,000 个引用 ID 上限限制；超限失败不授予新引用权限。初始摘要/索引超限明确拒绝，不再截断正文凑提示词。
- 规则清理独立保护全部私有冻结源，不能因尚未读取而提前删除回测事实。

## 迁移与后续决定

新增 `0130_ai_review_reading`，仅新增 JSONB 列；取消旧 PENDING/RUNNING 任务，因其没有逐页读取账本，必须重建。已完成历史不改。将来发布必须明确接受这一任务合同切换，后端与插件 1.4.0 配套更新。本轮不部署。

后续需要产品/架构决定：是否改用独立证据表或对象存储并真正延迟报表物化；是否支持突破 10 账户/5,000 报表行及原有历史样本边界；是否建设可按 cutoff 回查的发布历史，替代当前遇到过晚投影时拒读。当前实现不推断这些选择，也不引入实时查询回退。
