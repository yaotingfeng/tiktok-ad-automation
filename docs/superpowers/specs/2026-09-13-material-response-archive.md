# 素材接口完整响应留档

用户要求完整保存素材接口返回，以便查清上游实际给了哪些字段。沿用已确认的成功 VID 直接入库：保存现有上传及异常恢复查询的响应，不为了留档增加正常上传后的回查。

## 范围与形式

- 页面 URL 原件导入链路的 `materials.upload_video_url`、`materials.search_videos`、`materials.get_videos`。其他账户浏览、分发、广告或授权调用不在本次采集范围。
- SDK 在反序列化前保存收到的响应正文及 HTTP 状态；SDK 异常提供的正文同样保存。字节正文原样保留，SDK 提供字符串时按 UTF-8 保存。
- MCP 保存官方客户端返回的完整工具结果 JSON，包含完整 `content`、文本原文、`structuredContent`、错误标记等。它是客户端模型的完整序列化，不声称为 HTTP/SSE 原始字节流。
- 成功、业务报错及收到后无法解析的正文都留档；连接失败等没有响应的情况不伪造正文。历史未保存的上传返回无法补回；查询接口返回不能标成当时的上传响应。

## 存储与边界

新增 `material_response_archive` 独立表。按租户、BC、素材、源账户、原操作与冻结连接关联；每次响应追加独立行，不覆盖上传或此前查询。正文 gzip 压缩后通过既有租户绑定加密封装保存，保留接收时间、格式、字节数、SHA-256。签名地址等响应内容留在密文中，不写入页面状态、队列参数或普通日志；不采集请求头、令牌或请求参数。

仅受控运维通过 `read_material_response` 读取，先重新核对当前租户管理权限及租户/BC/素材范围，再解密并校验归属、长度和摘要。当前没有公开下载接口或页面原文入口。业务 VID/MID 等继续使用原有白名单结构，不让未知字段影响成功判断。

## 可靠性与负载

收到响应后、业务解析前，在独立有界事务中保存。短暂数据库错误最多本地重试一次，复用相同归档 ID，不重发远端调用。两次保存均失败时使用脱敏错误码 `material_response_archive_failed`；已发送上传保持 UNKNOWN，按原恢复流程查询，不直接重传。进程在收到响应但尚未落库时被终止，或数据库持续不可用时，不能保证当次正文可恢复。

正常上传新增一次本地压缩、加密及落库，没有新增 TikTok 请求或定时等待。已有传输响应上限为 8 MiB；MCP 模型 JSON 含转义和重复载体，归档上限为 32 MiB，超限明确失败，绝不截断后声称完整。首版不按时间自动删除；需监控独立表及备份增长。未来保留期限须明确确定，不能随原件清理删除响应证据。

## 发布

无新增环境变量或功能开关，沿用既有 `CONNECTION_ENCRYPTION_KEY`。先完成冻结写入、排空及完整备份/隔离恢复，再执行 `mcp_multibc_runtime -> mat_response_archive`。数据库与加密密钥必须成套恢复；新增表不能被备份过滤。回退应用须核实兼容并保留表，禁止 downgrade 删除已存响应。测试与环境实际验收分开记录。
