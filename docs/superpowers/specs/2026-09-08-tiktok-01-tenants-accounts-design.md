# TikTok 自动投放工具：租户、权限与广告账户功能设计

日期：2026-09-08  
状态：已于 2026-09-08 经用户确认；不代表已经完成实现或真实 API 联调。  
上位文档：[整体设计](2026-09-08-tiktok-00-overall-design.md)。

## 1. 功能目标与范围

为平台管理员和租户成员提供统一的工作台，明确每次操作属于哪个租户、哪个 BC、哪个授权连接。
接入当前租户授权范围内的全部可用广告账户，不设置几十、几百个账户的业务上限。
本模块负责登录上下文、租户、成员、TikTok 授权、BC 与账户目录；账户目录更新属于连接管理。
投放指标同步、报表刷新频率、分析数据库与经营数据处理后置，不纳入本稿。

## 2. 已确认决定与本稿建议

**已确认：**平台管理员切换租户后复用投放页面；租户内部不按投手划分账户范围；单次搭建限定一个租户和一个 BC。
**已确认：**租户间的账户、连接、素材及其他业务资源独立管理。
**已确认：**平台统一管理 TikTok 开发者应用，各租户分别授权；API 调用直接使用官方 Python SDK。
**已确认：**广告搭建通过批量粘贴账户 ID 或完整名称输入账户，解析歧义不能静默选择。
**已确认：**素材上传账户由系统指定，每次上传记录实际账户；用户无需配置固定素材账户。
**本版采用的补充规则：**采用下文四种固定角色、平台创建租户、租户管理员维护成员的简单管理方式。
**本版采用的补充规则：**数据模型支持租户连接多个 BC，一次业务操作保持明确的单 BC 范围。
**本版采用的补充规则：**首版不提供租户自助注册、独立代投审批、自定义角色或账户级成员授权。

## 3. 角色与权限

| 角色 | 可执行操作 | 范围 |
|---|---|---|
| 平台管理员 | 管理租户与平台应用配置，切换租户管理连接、成员及投放业务 | 全部租户；业务写操作必须进入明确租户 |
| 租户管理员 | 管理成员、连接、策略、素材及广告搭建 | 本租户全部已接入账户 |
| 投手 | 使用现有连接进行取链、素材上传、策略管理及广告搭建 | 本租户全部已接入账户 |
| 只读成员 | 查看账户、素材、策略、预览与任务结果 | 本租户；不读取凭据或执行写操作 |

平台管理员不需要在每个租户下创建一份投手身份；操作记录保存真实平台操作人及目标租户。
用户可以有多个租户成员关系，每个成员关系分别保存角色；进入工作台时只激活一个租户上下文。
角色校验由后端完成，前端隐藏按钮仅用于简化界面。凭据明文不向成员列表、连接详情或浏览器返回。
只读成员可以查看已有预览，但生成预览可能创建推广链接，因此新建预览不归入只读权限。

## 4. 页面与操作流程

1. 登录后，平台管理员进入租户列表；普通成员进入唯一所属租户，拥有多个租户关系时先确定工作租户。
2. 页面顶部持续显示当前租户和 BC；多个 BC 时显式切换，不能通过粘贴账户隐式改变 BC。
3. 平台管理页提供租户创建、名称修改、状态管理和管理员成员维护；停用租户保留历史资源及审计记录。
4. 租户成员页按固定角色维护成员；管理员可停用成员，权限变化对后续请求立即生效。
5. 连接管理页展示 BC、授权状态、授权时间、目录更新时间及最近异常，管理员可发起授权、重新授权和停用连接。
6. 账户目录页支持 BC、账户状态、名称与 ID 搜索，通过服务端分页展示；页面不下载完整账户池。
7. 素材页不提供“配置素材账户”步骤；上传结果中可以查看实际上传账户和素材状态。
8. 搭建页使用多行文本框粘贴账户；解析结果保留原始行和错误原因，无需逐个勾选匹配成功的账户。

切换租户后清理当前页面的查询缓存和未提交输入；进行中的后台任务仍属于创建时的租户及 BC。
本稿建议停用租户或成员后拒绝其新的业务写请求；排队任务在下一执行步骤重新校验权限，失权则暂停并记录原因。
暂停仅影响尚未执行的后台步骤，不自动暂停或删除已在 TikTok 创建并启用的广告。
平台代投不改变 TikTok 外部权限，仍只使用目标租户连接具备的能力。

## 5. 核心实体与归属

| 实体 | 关键字段 | 关系与约束 |
|---|---|---|
| User | 用户 ID、登录标识、状态、平台角色 | 登录身份，不直接承载租户业务数据 |
| Tenant | 租户 ID、名称、状态 | 业务资源的隔离边界 |
| TenantMembership | 租户 ID、用户 ID、角色、状态 | 同一租户与用户组合唯一 |
| PlatformTikTokApp | 平台应用 ID、SDK 配置、密钥引用、回调地址 | 平台级配置，租户不能修改 |
| TikTokConnection | 连接 ID、租户 ID、授权状态、凭据引用、授权主体 | 各租户独立保存，不使用全局“当前账号” |
| TenantBC | 内部 ID、租户 ID、TikTok BC ID、状态 | 同一租户与 BC ID 组合唯一 |
| ConnectionBC | 租户 ID、连接 ID、TenantBC ID、权限状态 | 记录连接对 BC 的访问关系 |
| AdvertiserAccount | 租户 ID、广告账户 ID、名称、币种、时区、远端状态 | 同一租户与广告账户 ID 组合唯一 |
| BCAccountAccess | 租户 ID、TenantBC ID、广告账户 ID、连接 ID、权限摘要、核验时间 | 记录 BC 资产关系及授权访问路径 |
| AuthorizationAttempt | 尝试 ID、租户 ID、操作人、state 摘要、失效时间、使用状态 | 回调只能关联发起时的租户上下文 |
| AuditEvent | 租户 ID、实际操作人、动作、目标 ID、时间、结果、请求关联 ID | 连接、成员和平台代投操作可追踪 |

TikTok ID 按字符串处理，避免 JavaScript 数值精度丢失。
BC 资产关系和连接权限分别保存；账户可用范围是“当前租户当前 BC 资产”与“该租户有效连接授权账户”的交集。
所有业务查询均包含租户条件；连接、BC、账户等外键组合也必须属于同一租户，不能仅凭外部账户 ID 获取资源。
本稿建议同一外部 BC 归属一个租户；若外部账户已被其他租户接入，标记归属冲突，不自动开放第二租户使用。
目录仍保留可见账户及冲突状态；平台管理员核实并解除冲突后，第二租户才能继续业务使用。单纯复制带 tenant_id 的目录记录不能隔离同一账户中的远端广告。

## 6. TikTok 应用与授权回调

当前尚无开发者应用；先部署登录、连接管理及确定的 HTTPS 回调路由，再配置申请获批后的应用信息。
无 App 凭据时连接页展示“等待配置开发者应用”，其他页面可使用明确标识的模拟数据开发，不能显示为真实授权成功。
本稿采用平台级 App 与租户级连接模型，授权交换及账户查询直接调用官方 Python SDK；不建设 HTTP 或 MCP 转发网关。

1. 管理员在当前租户发起授权，后端验证身份，创建短期、一次性的 AuthorizationAttempt。
2. 后端生成授权地址，将随机 state 与发起租户、操作人及允许的内部返回路径绑定；不把凭据放入 state。
3. 回调验证 state 的存在性、有效期及使用状态，同时重新检查发起人的权限；缺失、过期或重复回调均拒绝生效。
4. 使用平台 App 在服务端完成授权交换；凭据加密保存或保存密钥系统引用，授权码与令牌不进入日志。
5. 新连接进入“待发现资产”，后台通过 SDK 获取授权范围；仅在确认 BC 及账户访问关系后允许业务使用。
6. 重新授权更新明确指定的原连接；新建连接不自动替换同租户其他连接，不依据浏览器此刻的租户选择写入归属。

连接状态定义为：`PENDING_AUTH`、`DISCOVERING`、`ACTIVE`、`REAUTH_REQUIRED`、`ERROR`、`DISABLED`。
发起授权不使仍有效的旧凭据立即失效；新授权完成核验后再替换。用户取消授权只结束本次尝试。
`ACTIVE` 只代表连接可用，具体账户或动作仍需校验对应权限；授权失效时只暂停依赖该连接的任务。

## 7. 大量账户目录与批量解析

资产发现使用分页任务和持久化进度，支持恢复中断；界面查询本地目录，不在页面请求中遍历外部账户。
本地目录更新成功后记录时间与结果；部分分页失败时不得把尚未扫描到的账户全部标为移除。
完整扫描确认资产已移除时标记访问关系失效，保留账户历史记录与已执行任务，避免历史引用断裂。
账户列表按稳定排序分页，查询响应包含游标；搜索优先支持精确 ID 和名称查询，前端不渲染无限行。

批量解析先按行清理空白，再对每行尝试精确账户 ID 或完整名称匹配；同名账户必须展示候选 ID。
解析结果包含原始行号、原文、状态、已解析 ID、候选项和原因；重复行保留反馈，但展开搭建前按账户 ID 去重。
无匹配、多个匹配、BC 不一致、无权限、账户不可用分别报错；不能自动转到其他租户或 BC 查找替代账户。
解析成功不等于永久授权，生成预览和执行前再次验证当前访问关系；调用时的远端拒绝也写回任务结果。
单次请求可以分块处理大量粘贴内容；分块属于执行约束，不减少用户需要接入的账户总数。

## 8. 对其他模块提供的接口契约

以下是本稿建议的业务接口，遵循整体设计的 API 前缀，不要求与 TikTok SDK 方法一一对应。

| 接口 | 输入与输出 | 校验 |
|---|---|---|
| `GET /api/me/tenants` | 返回当前用户可访问租户及角色，支持分页 | 已登录身份 |
| `POST /api/platform/tenants` | 名称、初始管理员；返回租户 ID | 平台管理员 |
| `POST /api/tenants/{tenant_id}/tiktok/authorizations` | 新建或重新授权的连接 ID；返回授权 URL | 管理员及租户访问权限 |
| `GET /api/integrations/tiktok/callback` | 授权结果及 state；返回明确租户的连接结果页 | 一次性 state 与发起人权限 |
| `GET /api/tenants/{tenant_id}/accounts` | BC、搜索条件、游标；返回账户及访问状态 | 当前租户成员或平台管理员 |
| `POST /api/tenants/{tenant_id}/accounts/resolve` | BC、原始行列表；返回逐行解析结果 | 当前租户访问权限 |
| 内部 `resolve_account_access` | 租户、BC、账户、所需动作；返回连接 ID 与权限结果 | 不向调用方返回凭据明文 |
| 内部 `assign_upload_account` | 租户、BC；返回具备上传权限的账户与连接 | 素材任务持久化实际选择结果 |

素材上传账户的具体分配与失败处理见[素材中心设计](2026-09-08-tiktok-03-materials-design.md)；选择结果属于上传记录，不作为永久统一源账户。
版权方连接遵循相同租户归属原则，业务细节见[版权方与链接设计](2026-09-08-tiktok-02-provider-links-design.md)。
策略和搭建必须引用明确租户，见[策略设计](2026-09-08-tiktok-04-strategies-design.md)与[搭建执行设计](2026-09-08-tiktok-05-build-execution-design.md)。

## 9. 验收标准

- 平台管理员切换租户可复用工作台，审计保留真实操作人；租户成员无法跨租户读取或操作资源。
- 同租户投手可以访问全部已接入账户；只读成员不能取链、上传、修改策略或提交搭建。
- 回调遇到过期、重复或错误 state 不改变任何连接；切换浏览器租户不改变授权发起租户。
- 大量账户目录可分页检索；发现任务可续跑，部分失败不误删其他账户的有效访问关系。
- 批量粘贴 ID 和完整名称可解析，同名及越权逐行报告，去重后每个有效账户只出现一次。
- 账户权限采用 BC 资产与连接授权交集；连接失效、成员失权与 BC 归属变化在业务执行前被识别。
- 素材上传不要求配置素材账户，每次都能回查其实际上传账户；凭据与授权码不出现在响应或日志中。

## 10. 前端交互补充草案，待本轮评审

本节补齐 UI-01、UI-02、UI-08、UI-10 的页面呈现与交互，不改动前文已确认的账户、授权和隔离规则。下述界面及原型进入本轮评审，不能仅因业务设计已确认就视为页面设计也已确认。

### 10.1 页面位置与固定上下文

| 页面 ID | 页面名称与路径 | 页面职责 |
| --- | --- | --- |
| UI-01 | 登录 `/login` | 沿用模板登录，恢复有效登录后的原访问位置 |
| UI-02 | 平台租户管理 `/platform/tenants` | 平台创建、查看和管理租户，并进入租户工作台 |
| UI-08 | 账户与授权 `/tenants/:tenantId/accounts?tab=accounts` | 同页两个页签：账户、授权连接 |
| UI-10 | 成员管理 `/tenants/:tenantId/members` | 管理当前租户成员和固定角色 |

租户工作台侧栏顺序固定为：广告搭建、搭建任务、素材库、投放策略、账户与授权、版权方连接、成员管理。成员管理只向管理员显示；平台管理是独立入口，不混在普通租户菜单中。
租户工作台顶栏持续显示租户名称和当前 BC；平台人员进入租户后显示“平台管理员 · 当前代管：租户名”，实际工作页面保持一致。UI-02 处于平台范围，顶栏显示“平台管理”，BC 控件不参与全平台列表筛选。
租户及 BC 选择器使用带服务端搜索的弹出列表，显示名称及完整 ID；一个可用 BC 时显示固定值，不制造多余选择步骤。
切换 BC 或租户只改变正在浏览的范围，不改写任何已保存草稿或任务的租户/BC 绑定。新范围清理旧结果；回到原范围可打开原草稿。此前“清理未提交输入”指清理新页面中的旧表单显示，不删除已保存草稿。
管理表单或凭据 Sheet 仍有未保存内容时，先显示“留在当前页 / 丢弃未保存修改”的离页提示；不自动将旧数据提交到新范围。广告草稿则提供“保存并切换 / 留在当前页”，保存仍属于原租户与BC。已有任务继续以原绑定执行。

### 10.2 UI-01 登录

页面使用单列登录卡片，包含产品名称、邮箱、密码、密码显隐按钮和主按钮“登录”。不显示租户/BC 选择、不开放注册，不添加尚未接入的第三方登录入口。
表单标签始终可见；邮箱为空或格式错误在字段下提示，密码错误统一提示“邮箱或密码不正确”，不透露账号是否存在。提交中按钮显示“正在登录”并禁止重复提交，保留邮箱，密码不存入浏览器持久存储。
登录成功：存在经过验证的内部返回路径时返回该页面并重新校验权限；平台管理员无返回路径时进入 UI-02，普通成员进入可访问租户工作台。没有成员关系时显示“尚未加入租户，请联系管理员”，不展示虚构业务数据。
会话失效的 401 跳转 UI-01 并显示“登录已过期，请重新登录”；403 保持已登录状态，显示无权限页面，不循环跳回登录。已保存草稿可以通过原地址恢复。

### 10.3 UI-02 平台租户管理

布局顺序为页面标题和“新建租户”按钮、筛选工具条、租户表格、分页。没有经营数据图表或投放报表卡片。
工具条包含“搜索租户名称或 ID”、状态（全部/正常/停用）和“清除筛选”。搜索与状态均在服务端执行。

| 表格列 | 呈现 | 操作 |
| --- | --- | --- |
| 租户 | 名称为主行，完整租户 ID 为次行 | 复制 ID |
| 状态 | 正常/停用的文字 Badge | 状态不只用颜色区分 |
| 操作 | 查看、进入租户；更多菜单含编辑和停用/恢复 | 停用租户不能进入业务工作台 |

“新建租户”打开右侧 Sheet，字段为租户名称、初始管理员；管理员从已有用户中搜索，不在该流程发送邀请邮件。底部固定“取消 / 创建租户”，必填错误在字段下展示。
“查看”打开只读 Sheet，显示租户 ID、状态及管理员成员信息；“编辑”只编辑名称。停用确认文案明确说明将阻止新的系统业务操作、保留历史记录，不暗示自动停止 TikTok 已启用广告。
“进入租户”设置当前租户，进入同一工作台；不创建代投身份、工单或第二套页面。返回平台管理不清除租户历史任务。

### 10.4 UI-08 账户与授权

页头显示标题“账户与授权”，下方 Tabs 固定为“账户 / 授权连接”；URL 的 `tab=accounts|connections` 保存当前页签。刷新或从异常提示进入时可定位正确页签。
账户页签受当前 BC 筛选；授权连接页签按当前租户展示连接，尚未发现 BC 的新连接也必须可见，不因顶栏选择了某个 BC 而隐藏。

**账户页签：** 顶部显示当前 BC、目录更新时间及正在更新的文字状态；工具条为账户名称/ID搜索、账户状态、可用性筛选和清除筛选。主区只显示本地目录，不因打开页面遍历 TikTok。

| 表格列 | 具体内容 |
| --- | --- |
| 广告账户 | 名称主行、完整账户 ID 次行及复制按钮；长 ID 始终为字符串 |
| 币种与时区 | 币种、时区；未获取显示“待完善”，不填默认值 |
| 平台状态 | 平台原始状态的可读文字，与授权状态分开 |
| 可用性 | 可搭建、可上传、权限待核实、无权限或归属冲突 |
| 核验时间 | 最近已知权限/目录核验时间；未核实显示“尚未核验” |
| 操作 | 查看详情 |

账户详情使用右侧 Sheet：账户信息 → 所属 BC → 当前租户的可用连接及权限 → 异常原因。投手/只读成员能看业务状态，不能查看令牌；跨租户冲突仅提示“该账户存在其他租户归属”，不展示其他租户的名称或凭据。
表格不提供“选择账户去搭建”、账户分配给投手或“设为素材账户”等操作；广告搭建继续使用批量粘贴。归属冲突和无权限账户仍显示，可按状态筛选，不从列表删除。

**授权连接页签：** 工具条为连接状态筛选；管理员显示主按钮“新增授权”。表格列为连接名称/ID、授权状态、关联 BC、最近授权/发现时间和操作。关联多个 BC 时显示前两个名称及“查看全部”，完整关系放在 Sheet 中分页查看。
操作入口为“查看详情”，有 `manage` 权限的管理员另有“重新授权 / 停用”。重新授权入口明确当前连接和所属租户，不让用户填写素材账户。停用确认只描述连接失效对新操作/未执行步骤的影响，不执行远端停投。
没有平台 App 配置时显示“等待配置开发者应用”，新增授权按钮不可用；租户管理员看到联系平台管理员的说明，平台管理员看到应用接入准备状态，不在此界面回显 App Secret。
用户点击新增或重新授权后进入 TikTok 授权流程；回调回到绑定租户的该页签，显示“授权成功，正在发现账户”等实际阶段。取消或失败保留旧连接状态；若当前页面属于另一个租户，提供进入发起租户的明确入口，不在后台替用户改写当前草稿范围。

### 10.5 UI-10 成员管理

仅平台管理员和租户管理员可进入；投手及只读成员看不到菜单，直接访问得到 403 无权限页面。
布局为标题、当前租户说明、“添加成员”按钮、搜索/角色/状态筛选、成员表格和分页。表格列为姓名/邮箱、角色、状态、操作；不提供账户分配列。
“添加成员”使用 Sheet 搜索已有用户，角色固定为租户管理员、投手、只读成员。编辑角色与停用均作用于本租户成员关系，不改变用户在其他租户的角色。
保存时显示进行中状态；服务端返回最后一位管理员不可移除时，在当前 Sheet 展示“请先设置其他租户管理员”，保留输入。成功后关闭 Sheet、刷新当前页并显示简短结果提示。

### 10.6 管理页公共状态与大量数据交互

| 状态 | 页面表现与恢复 |
| --- | --- |
| 首次加载 | 保留页头、工具条与表头，表体显示 6 行 Skeleton；不短暂显示“没有账户” |
| 正在翻页/筛选 | 保留已有行并标记加载中，暂时禁用分页；响应只更新对应租户/BC/筛选范围 |
| 尚无资源 | 区分无租户、无授权、无成员；管理员显示对应创建入口，其他角色显示联系管理员的说明 |
| 筛选无结果 | 显示“没有符合条件的记录”及“清除筛选”，不提示重新授权 |
| 列表获取失败 | 表体内 Alert 和“重试”；已有数据保留并显示获取失败，不清空成正常空列表 |
| 401 | 登录失效，进入 UI-01；保留经校验的内部返回地址 |
| 403 | 当前角色不能访问；隐藏写按钮、显示“无权访问此页面”和返回工作台入口，不注销登录 |
| 表单保存失败 | 字段错误靠近字段；连接/权限错误显示在 Sheet 顶部；保留非敏感输入 |

账户、租户、成员和连接列表默认每页 50 条，可选 100 条；均为服务端筛选和分页，BC 筛选使用 URL 参数 `bc_id`。底部显示当前页及上一页/下一页，不伪造未取得的总数或可任意跳转的页码；查询条件变化后重置游标。
筛选条件、Tabs 和可恢复的页码游标保存在本页面状态/URL；任何游标都不能跨租户或 BC 复用。表格有自己的横向滚动区域，页头、顶栏与导航不跟随表格横向移动。
Sheet 打开后焦点进入标题或首字段；关闭返回触发按钮。键盘可访问菜单、分页、复制和关闭，错误文字不只依赖 Toast。关闭有未保存内容的 Sheet 使用同一离页提示。
本轮原型使用明确标识的模拟列表和状态，不触发真实登录或业务动作；授权、账户发现和成员变更在原型中只展示模拟状态。
