# 分页列表数据总数设计

## 目标

TK-ADA 中所有对用户展示分页控件的列表都显示当前查询条件下的数据总数，让用户在翻页前即可判断结果规模。

## 统一口径

- 系统内部游标分页响应统一包含 `items`、`next_cursor` 和非负整数 `total`。
- `total` 表示应用租户、BC、权限、搜索与筛选条件后的完整结果数，不受当前游标和每页条数影响。
- 公共分页栏显示“共 N 条 · 第 X 页”；切换搜索、筛选或每页条数时，页码回到第一页并刷新总数。
- 请求刷新期间保留 React Query 的上一份总数；请求失败时不把未知总数伪装为 0。
- 已有独立精确总数的分页（MCP BC 候选、本地待选文件）直接展示已有总数。

## 后端

通用 `Page[T]` 增加必填 `total: int`。每个返回通用分页的查询在应用游标之前，以完全相同的租户、BC、权限和业务筛选条件执行计数；取页数据时继续使用当前 seek pagination，避免改变稳定翻页语义。数据库计数和当前页读取在同一请求会话内完成。

非通用分页模型若已包含精确总数则保持契约；缺少总数但出现在 UI 分页中的模型补齐等价字段。内部仅用于流式遍历、外部 SDK 转发且不直接驱动 UI 的分页契约不纳入本次 UI 改造。

## 前端

公共 `Pager` 接收 `total?: number`，有精确值时显示“共 N 条 · 第 X 页”，未知时仅显示页码。所有由通用 `Page` 驱动的调用点传入响应 `total`。三个手写分页区域分别复用其本地集合长度或服务端已有总数字段，并使用相同中文文案。

## 测试与验收

- 后端：验证通用分页 schema 要求 `total`，代表性租户、账户、素材、策略、版权方和搭建列表验证未筛选/筛选/第二页的总数不变。
- 前端：公共分页组件与代表性页面验证总数展示，并验证筛选后的总数和翻页后的总数。
- 运行后端相关测试、前端 Playwright 相关套件、客户端重新生成检查和前端生产构建。
- 发布遵循目标环境 runbook：推送已验证提交，冻结写入并排空任务，完整备份与恢复校验后再复制/切换版本，最后核对服务版本、健康状态和页面总数。
