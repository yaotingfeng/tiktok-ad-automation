# 推广系列批量改名设计

日期：2026-10-15
状态：待用户审阅

## 背景与目标

投放人员经常需要批量修改推广系列名称（换日期、换投手代号、加停投标记、按表格逐条改名）。目前只能逐条去 TikTok 后台改。

目标：在 TK-ADA 广告管理中增加"批量改名"动作，复用现有的「勾选/冻结 → 预览 → 提交 → 逐条执行 → 定向刷新 → 操作记录」链路，不新建模块或通道。

## 范围

首期包含：
- 只改**推广系列**（campaign）名称。
- 三种规则：查找替换、加前缀/后缀、表格粘贴（ID → 新名称）。
- 仅人工触发。

不包含：
- 广告组、广告改名。
- 模板生成名称（如 `{剧名}_{日期}_{序号}`）。
- 自动规则中的改名动作（自动规则合同显式拒绝 `name` 字段）。

## 用户流程

### 入口

- 广告列表「推广系列」层级勾选后，批量操作菜单中的「批量改名」：打开改名面板，默认"查找替换"页签。
- 广告列表工具栏「按表格改名」按钮（无需勾选）：打开同一面板，默认"表格粘贴"页签，作用于当前 BC。

### 改名面板

沿用现有右侧预览抽屉样式（shadcn `Sheet`）。三个页签各带一段说明和示例：

| 页签 | 行为 | 页内说明要点 |
| --- | --- | --- |
| 查找替换 | 对已勾选推广系列，区分大小写替换名称中所有出现的 `find`；`replace_with` 可空（即删除）。名称中不含 `find` 的标为"不变"跳过。 | 示例 `0901 → 1015` |
| 前缀后缀 | 在名称首/尾加文字，至少填一个。已以该前缀开头/该后缀结尾的标为"不变"跳过，避免叠加。 | 示例前缀 `【停】` |
| 表格粘贴 | 粘贴两列：推广系列 ID、新名称，一行一条；Tab 或逗号分隔；首行若不是数字 ID 视为表头忽略。单次上限 500 行。 | 说明可从飞书表格或导出报表复制；附占位示例 |

面板底部固定提示：「改名会同步修改 TikTok 后台的推广系列名称，并影响本工具按剧名的报表归类。」

### 预览

逐行显示：账户、推广系列 ID、原名称、新名称、改名后解析出的剧名/版权方、状态。

| 状态 | 条件 | 能否提交 |
| --- | --- | --- |
| 将修改 | 新旧名称不同且校验通过 | 是 |
| 不变 | 新旧名称相同 | 自动跳过 |
| 提示 | 改名后剧名/版权方变化，或无法解析出剧名 | 是，醒目提示"报表中将归到 X 剧 / 归入未识别" |
| 不可提交 | ID 不在本 BC 已同步目录；无管理权限；不是推广系列；新名称为空；超过 512 字符；含表情符号；与同账户其他推广系列（现有名称或本批其他新名称）重名；表格中同一 ID 出现多次 | 否 |

顶部汇总"共 N 条：修改 X、跳过 Y、异常 Z"。存在不可提交行时，可选"仅提交可修改的行"或返回修改。

### 提交后

跳转现有操作记录详情页，逐条显示结果，失败行可用现有"重试"。操作记录动作筛选新增"改名"。

## 后端设计

### 合同

- `ad_management/schemas.py`：`MutationField` 增加 `name`。`MutationSpec` 增加可选 `rename` 规则，三选一：
  - `replace`：`find`（必填，非空）、`replace_with`（可空字符串）
  - `affix`：`prefix`、`suffix`（至少一个非空）
  - `explicit`：`{campaign_id: new_name}`，1–500 条
- 校验：`field=name` 时必须 `mode=set` 且必须带 `rename`、不带 `value`/上下限；其他字段不能带 `rename`。
- `contracts/management.py`：`ManagementField` 增加 `name`，操作名 `rename`；`name` 命令只允许 `ref.kind == "campaign"`，`desired` 恰好只有 `campaign_name` 一个键。
- `execution.py` / `expansion.py` 的字段与操作映射表同步增加 `rename`。

### 表格粘贴目标解析

新增函数（`ad_management` 内）：输入 BC 与 `explicit` 映射，按 `remote_id` 在本租户、本 BC 已同步的 `AdObject(kind="campaign")` 中查找并核验读权限。未命中、无权限、非推广系列的 ID 作为不可提交行返回给预览；命中目标生成 `FrozenSelectionRecord`，再走现有 `prepare_preview`。

`automation_rules/executor.py` 已有"由目标列表直接构造冻结选择集"的代码，抽成共享函数供两处复用，不复制。

### 预览展开

`expansion.py` 对每个推广系列按规则计算最终名称并冻结到 `final_value`，重试只消费冻结值。逐条完成上表校验；重名比对同账户现有其他推广系列名称和本批其他新名称。用现有 `parse_campaign_name` 解析新名称，预览项附带新剧名、版权方、是否变化、是否无法解析。

### 执行

- SDK 通道：普通推广系列调 `campaign_update`，Smart+ 调 `smart_plus_campaign_update`（复用现有 `_smart_plus` 判断），请求体只含 `advertiser_id`、`campaign_id`、`campaign_name`。
- MCP 通道：映射到对应的 campaign update 工具，参数同上。
- 写前路由与权限复核、UNKNOWN 对账、重试全部沿用现有实现。

### 写后刷新

沿用现有定向刷新。目录发布时 `append_campaign_name_projection` 会追加名称投影，剧名/版权方变化时推进 `grouping_revision`，报表归类自动更新，不新增重算逻辑。

### 操作记录

`TaskActionFilter` 增加 `rename`，记录摘要显示"改名 N 条"。

### 数据库

预计无需迁移：`final_value` 已是字符串列，规则存于预览 `mutation` JSON。实施计划中核对，若需要则单列 Alembic 迁移。

## 前端

- `features/ads`：推广系列层级批量菜单加「批量改名」，工具栏加「按表格改名」。
- `features/ad-management/ManagementPreviewSheet.tsx`：增加改名动作的三个页签、说明文案、预览表格的新旧名称和剧名提示列。
- `presentation.ts`：改名动作标题、状态与筛选标签。

## 测试

- 三种规则计算，含"不变"跳过与前后缀防叠加。
- 全部不可提交校验：跨 BC ID、无权限、非推广系列、空名、超长、表情符号、账户内重名、批内重名、重复 ID、超过 500 行。
- 冻结最终值重试不漂移。
- SDK、MCP 两个通道请求体只含名称字段，普通与 Smart+ 分流正确。
- 改名成功后名称投影追加、剧名变化时 `grouping_revision` 推进。
- 自动规则拒绝 `name` 字段。
- 前端构建与现有测试套件；锁与并发相关测试使用真实 PostgreSQL 和 Redis。

## 验收标准

- 三种规则都能从预览到执行完成，TikTok 后台名称与本工具目录一致。
- 不可提交行无法被发送到 TikTok。
- 改名导致剧名变化时，预览有提示，执行后报表归类随之更新。
- 操作记录可按"改名"筛选，失败行可重试。
