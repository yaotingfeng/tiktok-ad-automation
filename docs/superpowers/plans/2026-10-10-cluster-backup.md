# 集群备份实施计划

**Goal:** 将已验证的一致性备份实际部署到 ACK test，保存到项目独立云盘，不依赖 Jenkins 或个人电脑。

**Architecture:** 复用 release 的集群锁、暂停和恢复。CronJob 控制器使用受限 ServiceAccount；独立 PVC 保存加密归档，临时恢复 Pod 使用本地 PG/Redis 和原加密密钥验证，不运行业务消费者。私钥留在本机私有目录，不进入集群。现有应用镜像/配置不改。

**Scope:** 用户明确要求配置并操作完成。托管备份策略/OSS 权限尚不可用，不能代为声称启用。每日北京时间 03:00 为建议窗口，等待用户偏好；无答复先完成手动验证，定时状态如实报告。

- [ ] 抽取源码归档/Redis恢复共用点，新增集群恢复适配、持久加密归档与保留规则。
- [ ] 测试恢复隔离、锁竞争、备份失败恢复服务、保留最近有效副本；运行既有回归。
- [ ] 创建专用 Retain 云盘、ServiceAccount/Role、备份镜像和初始暂停 CronJob。
- [ ] 实际手动备份，回读密文并在本地解密/隔离恢复，验证九角色恢复。
- [ ] 按已确认窗口启用定时任务，记录权限缺项和验证证据；提交推送公司 main。
