# 实时同步可靠性实施计划

对应设计：../specs/2026-10-18-realtime-sync-reliability-design.md。按用户要求完成整轮整改，阶段是实现/验证边界，不在每个阶段把同一故障作为新任务反复交回。

1. 当前止损：完成 431 条当前投放目录与 37 账户素材补数；原三条 AUTO PAUSE 规则真实时刻幂等补跑；去重命中、原执行器发送、官方逐素材回读。
2. 同步核心：先写失败回归，再实施实时/补数分槽、旧窗口迁出热槽、2 分钟当前日规划、旧结果防覆盖、素材事实/关联拆分与有界恢复、目录有界公平派发和独立执行容量。补齐真实 PG 锁与 Redis 队列迁移测试。
3. 监控与消费：分钟级健康扫描、缺口重建、持久告警与恢复；页面最旧覆盖/实时刷新；5 分钟自动止损支持，保持恢复排期及原阈值。验证租户和 BC 隔离，不以空值冒充零或完整覆盖。
4. 发布：核算节点/RSS/连接和既有配额；聚焦提交，按既有授权使用公司生产发布链路。变更前 PG/Redis/源文件/构建/配置完整备份、隔离恢复通过再切换；原队列消息只作有证据的精确迁移。
5. 生产验收：全部角色实际镜像/开关/配额、至少三个完整实时周期；各账户事实/目录/关联最老时间和覆盖；同币种同日逐账户对账；三条止损更快排期及回执；告警实际可追踪。更新部署手册、验证记录与实施进度。
