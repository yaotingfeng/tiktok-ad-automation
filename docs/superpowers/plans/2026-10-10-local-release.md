# 本地一键发布实施计划

**Goal:** 在本机完成检查、构建、上传、发布前备份、部署与验收；只保留最新一份通过恢复验证的本地备份，不使用云备份存储或 Jenkins。

**Architecture:** 保留 deploy/release 的锁、暂停、恢复与迁移状态机。备份改为本地原子归档和回读校验，新归档成功后才替换上一份。统一入口使用明确的已提交main SHA创建干净执行副本，保护用户未提交改动；本机配置只存忽略目录，不把凭据写进脚本。

**Tech Stack:** Python3.14、Docker、kubectl、uv、Bun、PostgreSQL18、Redis。

**Spec:** 用户2026-10-10明确要求“本地备份保留最新的一份，不上传云存储；完成剩余工作”。此指令覆盖原云桶发布门禁，授权实施和验证，不执行真实广告/OAuth写入。

## Constraints / Review Focus

- 保留用户AGENTS.md改动，不自动提交未知业务改动；只推公司main。
- 新备份损坏/恢复失败时不能删除上一份；失败现场留作恢复，成功后清理本轮重复明文及旧受管备份。
- 保留线上true/true/false开关、tkada库、Redis15、9角色与现有域名。
- 失败必须可恢复且不清队列/回退数据库；平台UNKNOWN任务不重放。
- 完整检查不得以忽略类型/跳过测试替代修复；真实依赖测试在独立容器进行。

## Tasks

- [ ] 本地备份：修改backup.py/release.py，测试原子保留、损坏拒绝、同目录/符号链接误删保护、恢复失败旧归档保留；移除upload和AWS/age云门禁及Jenkinsfile。
- [ ] 统一入口：deploy/local.py提供check/deploy/backup/status/recover/finish；本机私有配置、明确SHA干净checkout、测试→构建推送→备份发布；可重入恢复入口与错误日志；不自动提交所有工作区。
- [ ] 既有后端：按ty/Ruff诊断修复类型契约/确实错误，运行完整后端测试，不降低门禁。
- [ ] 本地检查环境：补齐Bun与PG18工具；验证完整前后端/浏览器及镜像构建、发布备份恢复集成；清理本轮临时资源。
- [ ] 交付验证：提交推公司main，真实只读预检；实际本地备份及恢复演练；如发布候选就绪，说明版本和影响后按既有授权完成发布验收。记录真实结果/限制，文档只保留当前本地方式。
