# 素材与搭建流程可恢复性收口计划

用户要求：修复复审问题，复查整体代码中复杂状态及卡住分支，交付可发布版本。本轮完成本地代码、完整链路与发布前检查，不执行真实广告写入或未经指定的环境发布。

## 设计原则

- 保留原上传与已冻结任务身份；失败历史和 UNKNOWN 不能通过改写旧任务绕过。
- 首次转存登记只补“准备代数”：旧代明确未发送或明确未生效失败时，新准备可建立下一代、固定原主账户；旧消费者仍引用旧代。未知结果不得开新代。
- 正常准备、超时只读核实、任务唤醒继续复用既有执行器与 outbox，不增加第二套重试调度器。
- 素材目录去重优先实际可用副本，自动/手动匹配共用可信内容可用性判断；不物理合并历史记录。
- 检查上传→分发→封面→预览→提交→恢复与后台队列，每个非终态要有持久唤醒或明确待核实原因，不能只增加前端轮询。

## 阶段与验收

- [x] 1. 固化失败 seed 无法重新准备、不可用目录代表隐藏可用别名两项回归，先失败后修复。
- [x] 2. 收口 seed 准备代数、明确未发送的终止和过期副本核实，覆盖权限恢复/重绑、并发新消费者、旧消费者和 UNKNOWN。
- [x] 3. 统一选材可用性与优先代表，覆盖全库搜索、旧文件名、跨租户拒绝、同名异内容及原分页行为。
- [x] 4. 独立审查搭建/队列/封面和上传生命周期；对可复现卡住分支做根因修复，减少重复状态与无用恢复分支。
- [x] 5. PostgreSQL/Redis 回归、双通道全流程、前端页面/构建、迁移演练、静态检查与独立最终复审；逐项关闭发现。
- [x] 6. 记录验证结果、代码审计范围与发布前提，聚焦提交；如尚有未通过发布门禁，明确列出，不把本地模拟当作实际平台验收。
