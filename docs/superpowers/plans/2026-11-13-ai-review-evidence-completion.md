# AI 复盘事实补齐实施计划

**Goal:** Agent 通过 TK-ADA 冻结输入拿到可核验的执行、成熟收入、策略/素材关联和规则候选指标，禁止用受理代替回读或用缺失代替零。

**Architecture:** 沿用已批准 TK-ADA 事实/计算、插件方法、DSH 会话边界。复用本地正式报表、搭建对象、素材订单、广告管理 observation/receipt，不在模型会话触发平台请求。原始未记录的历史指标明确不可回测，不补造历史。

**Tech Stack:** SQLModel/PostgreSQL、现有报表/规则/广告管理领域服务、DSH 原生插件。

- [x] 1. 广告管理真实状态回读按任务对象/租户冻结，保留结果、实际值、时间及失败/未知；下一轮区分已核验与待回读。
- [x] 2. D0/D3/D7 独立成熟窗口，覆盖足够历史完整日，版本/覆盖/币种/截断明确；不混用未成熟收入。
- [x] 3. 保留规则全部候选对象判断时指标、规则定义/跳过原因，提供确定性历史候选回测；旧事实缺失明确不可用。
- [x] 4. 用真实搭建对象关联策略版本及素材订单策略，聚合对应报表事实；已有手工广告仍按账户参与规则复盘，不能假归属某搭建策略。
- [x] 5. 冻结素材订单/计划兑现详情，整合方法与证据可引用合同，真实 PG 行为及整链验证、独立复审，更新运行说明和提交。

验收：有规则无剧单也能获取命中/未命中/真实动作；接受≠回读；D7有成熟样本；同账户不同策略不串归属；旧历史缺失不假回测；冻结后更新来源不改变旧复盘；跨租户/BC/优化师无泄漏。真实模型、真实平台写入和部署不在本轮操作范围。

本地交付与外部边界见 [专项验收](../../validation/2026-11-13-ai-review-evidence-completion.md)。外部制作方需回传真实生产谱系；旧历史不补造，真实模型与生产验收仍未执行。
