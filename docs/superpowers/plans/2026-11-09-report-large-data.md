# 大账户池报表查询优化

目标：减少生产首屏快照的无用读取与重复随机 I/O，保持金额、覆盖、排序、授权和冻结选择合同。

本轮在现有 main 原位执行，不创建分支；不包含经营比例功能修改。优先采用无需迁移、无需调整运行额度的 SQL 优化。生产诊断只使用只读事务，执行计划及真实数据留在私有 `.runtime/`。

- [x] 账户快照：仅在余额排序时读取全候选余额；仅在搜索/命名条件需要时读取版权方投影及事实名称。页内余额展示仍读取当前页。
- [x] 完整服务诊断发现余额历史扫描超过40秒。统一为按账户LATERAL最新一条，复用于页补全、同步状态和余额排序依赖版本。
- [x] 验证素材批量读取及账户引用JOIN/名称集合查询候选：未获得稳定收益，不实施。
- [x] 使用真实 PostgreSQL 回归查询成本、金额、余额排序、搜索、分页与冻结选择；94项通过，修改模块静态检查完成，API既有5项类型问题原样记录。
- [x] 生产相同 REPEATABLE READ 数据窗口比较旧/新结果及执行计划；完整服务诊断仅写查询快照并全部回滚，独立报告 SQL 与服务耗时，不按缓存差异外推倍数。
- [x] 检查差异并记录验收；只提交本轮文件，推送仅按用户明确要求执行。当前main包含未上线0102及其他工作，禁止将其当作纯报表小修直接整批上线。

重点核验：账户无事实仍保留，余额非 AVAILABLE 不参与排序；版权方文字筛选不能漏行；同视频跨账户使用位置完整保留；旧快照不引入新系列；非授权账户与其他租户不进入结果。

本轮定位并减少已确认的无用读取和余额历史扫描。大账户池冻结全部系列引用仍有磁盘读取长尾；如需继续压低冷首屏，需要单独评估目录成员索引与状态日期索引/预聚合方案，不将此阶段结果写成全页性能问题已解决。
