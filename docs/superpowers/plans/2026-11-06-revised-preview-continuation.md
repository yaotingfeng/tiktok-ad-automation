# 修改配置后的同草稿续建

用户已确认：失败后修改同一草稿、生成新预览、再次提交属于正常流程。本次将原“回到新建草稿”的文案补丁升级为实际支持。

- 冻结预览在每账户组合的现有 scene_snapshot 中保存续建计划；已有成功对象只引用确定成功的原回执，按新意图逐对象判断兼容，父对象不能复用时其子对象也不复用。素材依赖沿用既有资源规划与映射，不新设素材 owner。
- 沿用不可变 DraftUnitReservation 记录首次占用，后续执行通过同草稿、同剧、同账户的已受理续建版本接续。新版本提交持有源步骤锁重新验证；旧版本请求发送前、恢复调度时均检查是否已有新版本接续。未知/在途或没有无副作用证明的旧创建请求不允许接续。
- 不覆盖旧任务、请求正文、回执或远端对象。新版本内用新步骤记录复用关系，历史结果仍能追溯。旧成功系列不兼容新预算/策略时，预览明确显示新建。
- 同一预览的请求幂等和跨租户、BC、连接权限保持原合同。只有所有目标对象均已成功且兼容时才引导返回原任务；明确失败的对象即使配置未变也可续建。续建计划过期时通过现有提升预览重试版本机制刷新，不能悄悄改变用户确认的新增数量。
- UI 显示复用/新增数量、来源任务与待核实/刷新原因；不在提交后才告知整个范围重复。只本地测试，不联调、不推送、不部署。

验证：真实 PostgreSQL HTTP 提交和执行状态；视频/图片轮播；已成功系列复用、预算变化新建、不同定向续建；原预览重复点击；未知/在途拦截；源状态过期；旧恢复/发送和新提交竞争；跨租户/BC隔离。前端浏览器替身验证预览确认和旧任务说明。具体结果在 implementation-progress 中补齐。
