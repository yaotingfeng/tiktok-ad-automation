# AI 投手能力与配置简化

用户已确认：优化模式是唯一的人工/自动执行选择；AI 可以新增或修改现有工具支持的策略、规则。素材制作使用内置 CL6 v4、CL8 v5、GM-精剪 v4 方案，创建投手时不再填写策略 ID、飞书表格。

## 实施范围

1. 删除表单发布授权和素材技术配置，服务端不再以历史授权 JSON 阻断 AUTO；保留租户/账户、领域参数、不可变基线、共享对象和并发核验。旧 JSON 仅历史归档，不赋予第二套权限。
2. 策略/规则提案增加明确 create/update 操作。复用原领域创建服务，新增后绑定当前投手；新策略成为后续未冻结搭建的绑定策略。人工确认前零写入，自动模式在同样校验后执行；按请求幂等，保留前后与新实体标识。
3. 能力目录明确支持的操作及 Schema；DSH 工具可预检候选并提交结构化提案，不能把未接入的全部网页功能声明为可调用。已有排期/素材/搭建/规则执行器继续承担执行与回读。
4. 素材生产按当前租户凭据读取目录解析内置方案，不能使用本地个人公司 Key、表格或跨租户 ID。不在优化师表单保存表格；若上游必须配置回写，则以实际合同解决，不虚构可选字段。订单保存实际选择的策略及版本，重试不换方案、不重复发单。
5. 更新方法、能力说明、运行手册和版本；增加真实 PostgreSQL 的人工/自动新增、幂等、越界/旧版本与共享保护回归，以及素材目录和前端表单回归。只模拟外部传输，不创建真实广告或素材订单。

## 发布注意

提案操作增加数据库字段，须新增 Alembic 迁移；旧任务缺少创建操作仅表示 update，已完成历史不改写。切换 API/DSH 配套版本，旧待处理任务取消并重新发起，不能自动套用新授权语义执行旧提案。生产发布需按本批具体迁移方案进行；本计划不报告代码/测试或上线已完成。
