# 短剧投放前端交互原型

## 评审路线

1. 从“广告搭建”开始，保留示例的两部剧、三个账户，点击“解析并准备”。
2. 打开一部剧的“调整素材”，增减素材后保存，观察组数与广告数；同一部剧的调整应用于全部目标账户。
3. “生成搭建预览”查看剧目汇总、账户组合、排除项及冻结创意明细。
4. 顶部演示场景可切换币种不符、确定失败或结果待核实；点击“创建并立即启用”只生成模拟结果。
5. 从侧栏查看素材库、上传队列、策略列表和编辑页。管理页面用于布局评审。

原型仅有内存示例状态，刷新/重置即还原；不调用任何业务接口，不读取视频内容，不传输所选文件。上传队列只展示选择文件的名称和大小，不把模拟文件添加为可投放素材。示例目录包括 The Bond、Hidden Promise，以及账户 A/B/C（别名 DEMO-A/B/C）。文案和 CTA 示例用于呈现布局，不是正式100条文案池或已验证的场景能力。

## 本轮已验证

- 内嵌 JavaScript 通过 `node --check`。
- 浏览器验证：默认2剧×3户=6 Campaign / 12 Ad Group / 24 Ad，日预算合计USD600。
- 一部剧素材6→3后：6 Campaign / 9 Ad Group / 18 Ad，日预算仍USD600。
- 币种不符排除账户C的两个组合，实际提交4 Campaign，预算USD400；三级计划/提交/排除计数一致。
- 未知结果先回查；明确失败仅重试缺失步骤。创意数量1时异常定位SP1，避免显示不存在的SP2。
- 修改策略使旧预览失效；同一预览提交后禁用再次提交并提供查看任务入口。
- 输入空行后的错误仍指向原始行号；仅输入账户B时，明细显示B。
- 查看1440px桌面与390px窄屏；1280/390px均无整页横向溢出。Sheet具有键盘关闭与焦点恢复逻辑。

未在原型中实现真实授权、100条文案池、全库素材补选/组间移动、全部管理写操作、服务端分页、海量账户处理、任务后台执行与持久化。相关完整状态与验收安排见[前端设计](../specs/2026-09-08-tiktok-06-frontend-experience-design.md)和[交付总计划](../plans/2026-09-08-tiktok-00-delivery-roadmap.md)。原型检查不替代正式应用测试。
