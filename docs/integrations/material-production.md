# TK-ADA → 素材工具：联合开户与免密进入

依据 2026-10-20 外部任务 API 文档 6.9 / 6.10。素材工具固定来源为 `https://manjumt.gzjunbo.net`。本功能不改变成片回传。

## 使用

平台管理 → 新建租户：输入显示名称、专属登录账号、初始密码。公司名称等于租户显示名称，素材登录账号等于投放登录账号，初始密码相同；素材交付固定 `r2` / `true`。名称 1–100 字符，账号遵循现有 3–64 位小写英数/`_.-` 规则，密码 8–128 位且包含字母和数字。

提交立即创建本地租户、管理员与开户任务。租户详情显示素材制作“开通中 / 已开通 / 开通失败”。网络异常自动有限重试；业务拒绝或五次失败后由平台管理员核对原因并点击“重试开通”。不自动替换占用的账号、不把同名历史账号当作本次开户结果。

租户工作区 → 投放准备 → 素材制作：平台管理员、租户管理员、投手可进入，viewer 不显示且后端拒绝。点击时后端验证当前权限，根据租户绑定取素材账号，调用免密接口取得链接；浏览器在当前标签页直接打开。切租户时取消未完成请求，旧结果不触发跳转。需要回到投放工具时可使用浏览器返回。

链接五分钟有效、只使用一次，素材侧会话按其合同保持七天。链接不缓存、不入库、不记录审计正文、不提前生成。TK-ADA 停用用户/租户会阻止新链接，但无法撤销已经建立的素材侧会话；上游文档没有提供远端会话撤销接口。

## 服务端配置

| 配置 | 说明 |
| --- | --- |
| `MATERIAL_TOOL_PROVISIONING_KEYS` | JSON 对象，配置引用到 `owp_` 开户密钥；例如 `{"primary":"<实际开户密钥>"}`，真实值仅放私有运行配置 |
| `MATERIAL_TOOL_DEFAULT_KEY_REF` | 新开户使用的引用，例如 `primary`；默认 `default` |
| `CONNECTION_ENCRYPTION_KEY` | 沿用现有租户凭据加密密钥，不可重新生成覆盖 |

API、control Worker、Beat 必须读取一致配置；部署模板通过现有环境文件/Secret 注入。无新业务布尔开关。空配置会明确拒绝联合开户；已有广告、素材业务不受影响。`owk_` 公司 API Key 不能用于开户或免密。

每条绑定保留开户密钥引用和指纹。不能在相同引用下静默换另一把密钥：素材工具只允许同一把密钥为自己开过的账号申请链接。新增密钥用新引用并调整默认引用，旧引用保留以服务原账号；吊销/迁移历史归属须先与素材工具确认。

## 数据与恢复

- `material_production_binding` 保存 tenant/admin/request ID、素材账号、外部 company/user/key ID、加密公司 API Key、开户密钥引用与指纹、状态与尝试记录。
- 待开户请求按租户加密，确保超时重试包括密码在内完全一致；成功后立即删除该密文。失败记录保留密文用于恢复，不用于网页登录。
- 请求使用 `Idempotency-Key: tkada:<request_id>`。上游重放会轮换公司 Key，因此同一记录持有数据库行锁进行一次有时限的外部调用，成功落库后不会重放。
- control 队列执行 `material_production.provision`；Beat 每 60 秒运行 `material_production.recover`，通过现有 outbox 恢复到期任务。队列只保存绑定 ID 与代数，不含密码和密钥。旧代数/重复消息不重复调用上游。
- 本地创建 API 以客户端 UUID 及服务端 HMAC 内容摘要防重复；响应丢失保持原请求重试。改变内容需重新打开创建表单生成新操作编号。
- 历史租户无绑定时显示未开通；不批量创建公司，不根据用户名猜测绑定。历史接入需另行提供明确操作范围。
- 两边仅初始密码相同。投放密码修改不需要更新免密登录凭据，也不会自动修改素材侧密码；当前上游没有密码同步接口。

## 本地 API

| 方法/路径 | 用途 |
| --- | --- |
| `POST /api/platform/tenants` | 联合创建；body 为 `name, username, password, request_id` |
| `GET /api/tenants/{id}/material-production` | 读取脱敏开户状态 |
| `POST /api/platform/tenants/{id}/material-production/retry` | 平台管理员重试失败开户 |
| `POST /api/tenants/{id}/material-production/login-link` | body 固定 `{}`，不接受用户名或外部用户 ID；返回 `login_url, expires_at`，响应 `no-store` |

上游业务错误只映射预定义错误码/文案，不透传 response body、异常 URL 或 Cookie。登录 URL 只接受指定域名的 `/api/login-links/consume`，由浏览器消费，服务端绝不提前访问。

## 真实联调验收

配置有效开户密钥后，在明确授权的新测试租户上执行：创建本地租户 → 回读外部 company/user 绑定 → 点击菜单 → 浏览器进入正确公司。检查重复点击、超时重试、停用和只读成员拒绝。人工已有账号（包括 demo）只有确实由该开户密钥创建时才可使用 6.10。

本轮本地测试使用 HTTP 传输替身和专用 PostgreSQL，不以其结果代替真实开户/浏览器登录联调。发布涉及新 Alembic 迁移和 Beat 调度，按部署手册执行完整迁移流程。
